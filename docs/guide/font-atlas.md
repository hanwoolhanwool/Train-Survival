# 한글 폰트 아틀라스 — 비운 채로 둔다

작성일: 2026-09-04 · 대상: `Assets/_Project/Art/Fonts/F_NotoSansKR_SDF.asset` ·
훅: `tools/git-hooks/pre-commit` · 정비 도구: `Game/QA/Font/*`

> **한 줄 요약**: 이 에셋의 글리프는 **필수 데이터가 아니라 캐시**다. 비운 채로 두고,
> 훅이 그 상태를 지킨다. 되살리려 하지 않는다.

---

## 1. 증상 — 같은 작업을 14번 했다

이 파일 하나가 **커밋 14회**를 먹었고, 그중 둘은 제목이 아예 **"다시 굽는다"**였다.
글리프 수가 이렇게 오갔다.

| 커밋 | 글리프 | |
|---|---:|---|
| `2d44706` | 153 | 준비 화면 문구 |
| `f4e4e11` | 168 | 4차 문구 |
| `9a89d96` | **185** | 최대 |
| `86f1537` | **74** | ← **무너짐** · "다시 굽는다" |
| `a843cd5` | 101 | "27자 추가" |
| `43661da` | **126** | "다시 굽는다" |

**185까지 갔다가 74로 무너지고, 다시 126까지 올려 놓은 상태**였다. 그리고 빌드할 때마다
또 0으로 떨어져 매번 손으로 되돌려야 했다.

## 2. 원인 — 설정 두 개가 서로를 잡아당긴다

```yaml
m_AtlasPopulationMode: 1        # Dynamic — 런타임이 필요한 글자를 소스 TTF 에서 굽는다
m_ClearDynamicDataOnBuild: 1    # 그렇게 구운 것을 빌드 때 지운다
```

- **Dynamic 모드**라 게임은 `NotoSansKR-VF.ttf`(10.4 MB, 프로젝트에 포함)에서 필요한 글자를
  **실행 중에 굽는다.** 에셋에 미리 구워 둘 필요가 없다.
- **`ClearDynamicDataOnBuild: 1`**이라 TMP 가 빌드·재직렬화 시점에 그걸 **비운다.**
  ⚠ 이름이 `OnBuild` 지만 **빌드하지 않아도 비워진다** — 2026-09-02 에 마지막 빌드가
  8일 전인데 126 → 0 이 된 것을 확인했다.
- 반대로 **씬을 열거나 플레이하기만 해도** 화면에 뜬 글자가 자동으로 구워져 파일이 커진다.

즉 **양방향으로 계속 변한다.** 저장소는 "구워진 상태"를 추적하는데 엔진은 그걸 캐시로 취급하니,
사람이 그 사이에서 매번 되돌리는 구조였다.

## 3. 비워도 되는 근거 — 적중률이 14 %였다

| | 값 |
|---|---:|
| 게임이 쓰는 고유 한글 | **약 757자** |
| 아틀라스에 구워져 있던 한글 | **108자** |
| **캐시 적중률** | **14 %** |
| → 나머지 649자 | **이미 런타임에 굽고 있었다** |

**86 %를 이미 런타임에 굽고 있었다.** 캐시를 지워도 달라지는 것은 그 14 %의 첫 표시 시점뿐이다.

### 검증 — TTF 가 전부 공급하는지 직접 물었다

프로젝트의 `.cs`·`.prefab`·`.unity`·`.asset` 795개에서 한글·자모·전각기호 **1,013자**를 뽑아
`TMP_FontAsset.TryAddCharacters()` 에 통째로 넘겼다.

```
[FontAtlas] 검증 시작 — 글자 1013자 · 아틀라스 현재 126자
[FontAtlas] 통과 — 소스 TTF 가 1013자를 전부 공급한다 (구워진 글자 1013자).
[FontAtlas] 아틀라스를 다시 비웠다 — 글자 0자.
```

**공급 못 하는 글자가 0자**다. 그 뒤 빈 아틀라스로 빌드해 `-smoke 25` 를 돌렸고,
**종료 코드 0 · 폰트 관련 경고 0건**이었다.

## 5. 유지 방법 — 훅이 지킨다

`tools/git-hooks/pre-commit` 이 **스테이징된 내용**의 글리프 수를 세고, 0 이 아니면 커밋을 막는다.
워킹트리가 아니라 커밋될 내용을 보므로, 빌드가 파일을 건드려도 스테이징만 안 하면 통과한다.

```
커밋을 멈춘다 — 한글 폰트 아틀라스에 글리프 126개가 섞였다.
해결:
  git restore --staged <파일> && git checkout -- <파일>
```

**설치**는 클론 직후 1회다 (README "시작하기"에 포함).

```bash
cp tools/git-hooks/pre-commit .git/hooks/pre-commit
```

> ⚠ **`core.hooksPath` 를 쓰지 않는다.** Git LFS 가 `.git/hooks` 에
> `post-checkout`·`post-commit`·`post-merge`·`pre-push` 4개를 설치해 두는데,
> `hooksPath` 를 바꾸면 **그 넷이 통째로 무력화된다.** LFS 가 쓰지 않는 `pre-commit`
> 슬롯에만 넣는 이유다.

## 7. 이 결정이 뒤집히는 조건

**첫 표시 히치가 실제로 문제가 될 때**만 다시 연다. 지금은 아니라고 본 근거:

- 한글 UI 는 대부분 **메뉴·HUD**라 인게임 프레임 예산과 분리돼 있다.
- 이미 86 %가 런타임 베이킹이었고 **그것으로 문제가 보고된 적이 없다.**

문제가 생기면 선택지는 **정적 아틀라스**(`Atlas Population Mode: Static` + 1,013자 전량 굽기)다.
결정론과 히치 0 을 얻는 대신 **한글 문자열을 새로 쓸 때마다 다시 구워야 하므로**,
지금 없앤 수동 작업이 그대로 돌아온다. 그 값을 치를 이유가 생겼을 때 하면 된다.
