## 로컬에만 남기는 파일

- 반복 렌더링한 프레임 이미지, 동영상, 대용량 모션 교환 덤프와 일반 실행 로그
- 이미 반입된 PNG의 납품용 복사본, ZIP 묶음, PDF 출력본, 문서에 근거로 채택되지 않은 검토 화면
- 포트폴리오 제작 중 내려받은 웹 페이지·외부 도구 및 촬영 결과
- 임시 소스·프리팹 백업, Python 캐시, Blender 연결·시작 상태 점검 도구, 대화 첨부파일
- 문서가 완료 화면으로 사용하지 말라고 명시한 `ingame-first.png`, `ingame-latest-final.png`와 채택 전 `dq-prototype.png`

재생성 가능 여부가 불확실한 파일도 삭제하지 않았다. 특히 로컬 백업과 검토 중간본을 무조건 삭제해도 된다는 의미는 아니다.

## 제작 코드의 사용 범위

이번에 보존한 코드는 과거 제작 절차의 기록이다. 범용 도구로 정비하거나 실행 검증한 것은 아니다. 당시 버전의 Blender 오브젝트·메시 정점 순서·리그 이름, Unity 씬과 에셋, 로컬 절대 경로와 설치된 라이브러리에 의존한다. 일부 스크립트는 실행 즉시 씬·에셋을 변경한다.

`tmp/` 아래의 Python 파일은 서로를 import하거나 기존 경로를 참조하므로 위치를 유지했다. `.cs.txt`는 Unity 에디터에서 실행했던 코드 조각이며 독립 C# 프로젝트가 아니다. 파일명을 참조하는 제작 데이터를 함께 남겼지만 모든 버전의 제작 과정을 새 환경에서 재현할 수 있다는 보장은 없다. 재사용하려면 입력 경로·버전·의존성을 먼저 확인하고 별도 작업 사본에서 검증한다.

기획서에 기록된 Blender `.blend` 제작 원본은 저장소 밖 `Desktop/Train_Survival_Blender/Raccoon_Production` 등에 있다. 이번 선별은 그 파일들을 반입하거나 백업하지 않았다. `output/raccoon-grip-v5/CH_Raccoon_TP.before.fbx`는 기획서에 보존 대상으로 명시된 교체 전 반입본이므로 별도 보존했다.

## 이후 파일을 추가할 때

`.gitignore`는 세 작업 폴더에 새로 생기는 파일을 기본 제외한다. 이미 추적 중인 618개 파일은 계속 변경 사항에 표시되고 일반적인 커밋으로 갱신할 수 있다.

새 제작 원본·도구·필수 검증 근거는 내용을 검토한 뒤 해당 파일만 `git add -f -- <파일 경로>`로 등록한다. 폴더 전체를 강제 추가하지 않는다. 새 범용 도구는 `tools/`, 게임에 사용하는 결과물은 `Assets/`, 설명과 승인 근거는 `docs/`에 두는 것을 우선한다.

선별된 기존 파일의 커밋 날짜는 파일 최종 수정 시각(한국 시간)을 사용한다. 이 보존 정책과 목록의 작성일은 2026-11-05이다. 기존 파일의 내용은 수정하지 않았다.

## CI 입력 의존성 추가 점검 (2026-11-05)

최초 선별 뒤 Unity 에디터 제작 코드의 `File.ReadAllText` 호출을 추적하면서 누락된 입력 JSON 7개를 발견해 추가 보존했다. 꼬리 가중치 2개, 꼬리 형상 2개, 손목 패치와 원래 회전값, 엄지 파지 데이터다. 최종 보존 수는 618개이며 로컬 전용은 5,248개다.

이 데이터는 과거 캐릭터 제작 도구를 수동 실행할 때 사용한다. 현재 CI의 테스트·플레이어 빌드 진입점에서 해당 제작 메서드를 호출하지 않는다. 현재 CI는 Unity 테스트, Windows 플레이어 빌드, 결과물 업로드로 구성돼 있으며 배포 스텝은 없다.

점검한 범위는 워크플로, 빌드 코드, 에디터 자동 실행 훅, 런타임 코드, 테스트 코드, 패키지 설정, Git에 포함된 빌드 씬과 제작 데이터다. `output/`를 사용하는 UI 화면 테스트는 폴더를 직접 생성해 결과를 쓰며, 배치 모드에서는 건너뛴다. `tmp/`와 대화 첨부파일에 대한 CI 입력 참조는 발견되지 않았다.

이번 제외 규칙은 이미 추적하던 파일을 제거하지 않는다. Git에서 제외된 파일을 모두 삭제해도 된다는 뜻은 아니다. 원본이 보존되지 않은 로컬 제작 중간본과 백업은 별도 보관 판단이 필요하다. 이 단계는 정적 점검이며, 이후 실제 빌드·실행 결과는 다음 절에 별도로 기록한다.

## 제외 파일 없는 새 사본에서 실제 빌드·실행 검증 (2026-11-05)

대상 커밋은 `e531e3a5ea06153f2c4d3e85fe29b20ac6adc91b`이다. Git에 커밋된 파일만 별도 작업 사본으로 체크아웃하고, 기존 `Library` 캐시를 복사하지 않았다. 로컬 전용 5,248개가 검증 사본에 없음을 빌드 전후 모두 확인했다. 원래 작업 폴더와 실행 중인 Unity는 변경하거나 종료하지 않았다.

- Windows / Unity 6000.5.3f1에서 저장소의 `Game.Editor.BuildScript.PerformWindowsBuild`로 빌드: 성공, 418 MB, 오류 0건, 경고 44건.
- 처음 실행한 검사는 기존 Unity 프로세스의 UDP 7777 점유로 호스트 시작에 실패했다. 파일 누락 실패가 아니었다.
- 검증 사본의 `Boot.unity`에서 루프백 포트만 17777로 바꿔 재빌드: 성공, 오류 0건. 게임 로직과 에셋 입력은 변경하지 않았다.
- 해당 실행 파일을 `-batchmode -force-d3d11 -smoke 30`으로 검사: Boot → Main → 인게임 진입 후 30초 실행 및 세션 유지, 정상 종료 코드 0. 실행 로그에서 파일 누락·예외·자동 주행 실패는 발견되지 않았다.
- 비표시 모드의 화면 캡처는 검은 화면이므로 시각 검증 근거로 사용하지 않았다. 전체 기능·그래픽 품질 검수, 전체 테스트 모음, Linux GitHub Actions 실행 결과를 의미하지 않는다.

결론: 이번 5,248개 제외로 인해 새 체크아웃의 기본 Windows 빌드와 인게임 실행이 깨지지는 않았다. 기존부터 별도 반입 대상으로 명시된 `Anim_Hold_*.fbx` 3개도 추가하지 않고 검증했다. 해당 원본의 반입 절차는 `Assets/_Project/Art/Animations/NOTICE.md`를 따른다.
