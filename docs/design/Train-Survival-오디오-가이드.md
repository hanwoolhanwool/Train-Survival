## 2. 오디오 기둥 — 세계관에서 도출

[세계관 §1.1](Train-Survival-세계관-컨셉.md)의 세 겹 대비를 청각으로 옮긴 결과다.
**판단이 갈릴 때는 "이 대비가 더 또렷해지는가"를 묻는다** — 시각과 같은 기준이다.

| 대비 | 앞 | 뒤 | 청각 번역 |
|---|---|---|---|
| **귀여움 ↔ 적의** | 동물 원래의 울음 | 별씨의 낮은 웅웅거림 | **괴성으로 덮지 않는다.** 원음은 그대로 두고 그 위에 이물질을 얹는다 |
| **근경 ↔ 원경** | 열차의 쇠·기름·마찰음 | 바람과 넓은 정적 | 발밑은 고되고, 저 멀리는 비어 있다 |
| **기차 ↔ 세계** | 주기적·기계적·저역 | 비주기적·유기적·중고역 | **주파수 대역으로 가른다** — 겹치면 둘 다 죽는다 |

### 2.1 다섯 기둥

| # | 기둥 | 근거 | 판단 질문 |
|---|---|---|---|
| 1 | **소리가 곧 면역이다** | [세계관 §2.2](Train-Survival-세계관-컨셉.md) — *"기적·엔진 소음은 별씨의 부름을 흐트러뜨리는 소리. 시끄러운 것이 미덕인 세계"* | 조용해지는 것이 위험으로 읽히는가? |
| 2 | **밤에는 귀가 눈을 대신한다** | 주 교전 시간대가 밤이고([기획서 §2](Train-Survival-기획서.md)), 시각은 어둠에 묻힌다 | 눈을 감아도 수·방향·거리가 오는가? |
| 3 | **정적은 리소스다** | [세계관 §3.2](Train-Survival-세계관-컨셉.md) 처치 후 *"짧은 정적"* · [기획서 §8.2](Train-Survival-기획서.md) 최종장 *"완전한 무음"* | 정적을 쓸 자리를 위해 평소가 채워져 있는가? |
| 4 | **다이제틱 우선** | [비주얼 가이드 §9.5](Train-Survival-비주얼-UIUX-가이드.md)의 청각판 | 알림음을 넣기 전에, 세계의 소리로 같은 정보를 줄 수 없는가? |
| 5 | **자기 조작은 지연 0** | [개발 가이드 M1](../guide/Train-Survival-개발-가이드.md) — *"발사음은 입력 즉시 로컬 재생(지연 0)"* | 호스트 승인을 기다리고 있지 않은가? |

### 2.2 기둥 1의 구체적 귀결 — "조용해지면 죽는다"

이 게임의 코어 판타지는 *"멈추면 죽는다"* 이고, 세계관은 그것을 **소리의 문제**로 설명한다.
따라서 연료·속도 상태의 **1차 표현은 HUD 숫자가 아니라 엔진 소리여야 한다.**

| 연료 상태 | 엔진 사운드 | 플레이어가 받는 것 |
|---|---|---|
| 충분 | 규칙적인 저역 박동 + 레일 조인트가 빠르게 지나감 | 안전. 배경으로 물러난다 |
| 부족 | 박동이 느려지고 **불규칙한 기침**이 섞인다 | "뭔가 이상하다" — 화면을 보기 전에 안다 |
| 고갈 임박 | 저역이 빠지고 **레일 조인트 간격이 벌어진다** | 감속이 귀로 먼저 온다 |
| 정지 위기 | 열차 소음이 걷히고 **바깥의 소리가 들어온다** | 공포. 세계가 조용해진다 = 별씨가 다가온다 |

- 마지막 줄이 이 게임 오디오 설계의 핵심 장면이다. **소리가 빠지는 것이 가장 무서운 사건**이다.
- [비주얼 가이드 §9.5](Train-Survival-비주얼-UIUX-가이드.md)의 다이제틱 연료 표시(화실 불빛)와
  **한 쌍**이다. 시각은 화실, 청각은 엔진. 둘 다 서면 HUD 연료 줄은 물러날 수 있다(§22 미결).

## 3. 이 게임의 특수 조건

무대가 특이해서 일반적인 FPS 오디오 상식이 그대로 오지 않는다.

| 조건 | 귀결 |
|---|---|
| **무대에 상시 소음이 있다** | 열차 주행음이 항상 깔린다 = **마스킹 베드**. 저역이 이미 점유돼 있으므로 **정보성 소리는 중고역**에 배치한다. 저역으로 만든 경고는 엔진에 먹힌다 |
| **무대가 좁고 밀집한다** | 4인이 40 m 열차 위에 있다. 3D 감쇠를 일반 FPS처럼 잡으면 전부 최대 볼륨으로 들린다 — **열차 내부 전용 감쇠 프리셋**이 필요하다(§14) |
| **적은 옆에서 온다** | 몬스터 스폰 측면 거리 **14~24 m**([세계관 §3.2.1](Train-Survival-세계관-컨셉.md)). 정면이 아니라 **좌우 패닝이 주 정보 채널** |
| **무대가 흔들린다** | [비주얼 가이드 §9.4](Train-Survival-비주얼-UIUX-가이드.md)의 "흔들림 중에도 읽힌다"가 청각에도 적용 — 리스너가 흔들리므로 **정위(定位)가 미세하게 흔들린다**. 중요한 소리는 패닝에만 의존하면 안 된다 |
| **1인칭 + 협동** | 내 소리와 남의 소리가 구분돼야 한다. **내 조작은 2D 근접, 남의 조작은 3D**(§15) |
| **밤이 주 교전** | 시각 정보가 줄어드는 시간대에 청각 부하가 최대가 된다 — 동시 발성 예산의 피크가 여기다(§14) |

## 4. 믹스 구조

### 4.1 버스 구성

```
Master
├── Music
├── Ambience        지역·날씨·시간대 루프
├── SFX
│   ├── SFX_Self    내 조작 피드백 (2D 근접, 항상 우선)
│   ├── SFX_Train   열차 구조물·주행 (준-앰비언스, 상시)
│   └── SFX_World   타인·몬스터·환경 사건 (3D)
└── UI
```

- **`SFX_Self`를 분리하는 이유**: 밤 웨이브에서 `SFX_World`가 포화돼도 내 총소리는 들려야 한다.
  볼륨이 아니라 **버스로 보장**한다.
- **`SFX_Train`을 분리하는 이유**: 상시 재생되므로 앰비언스처럼 취급하되, 게임플레이 정보
  (연료·속도, §2.2)를 실어 나르므로 앰비언스 슬라이더로 꺼지면 안 된다.

### 4.2 우선순위 — 무엇이 무엇을 덕킹하는가

정보 계층은 [비주얼 가이드 §9.2](Train-Survival-비주얼-UIUX-가이드.md)의 A~E계층과 같은 순서다.

| 순위 | 종류 | 예 | 처리 |
|---|---|---|---|
| 1 | **생존 위협** | 낙오 경고, 연료 고갈, 보스 차지 텔레그래프 | 하위 전부를 −6 dB 덕킹 |
| 2 | **자기 조작 피드백** | 발사, 릴, 거부음 | 절대 잘리지 않는다 |
| 3 | **타인·몬스터** | 동료 총성, 접근, 공격 | 거리 감쇠 + 발성 상한 |
| 4 | **앰비언스·열차** | 지역 루프, 주행음 | 1·2 발생 시 물러난다 |
| 5 | **음악** | BGM | 전투 진입 시 자동 하강 |

- **덕킹은 볼륨이 아니라 자리를 만드는 일이다.** 경고를 키우는 대신 나머지를 낮춘다 —
  전체 음압이 올라가면 다음 경고를 위한 여유가 사라진다.

## 5. 열차

세계관상 **가장 중요한 축**이다. 배경이 아니라 생존의 소리다(§2.1 기둥 1).

| 요소 | 성격 | 내용 |
|---|---|---|
| 주행 루프 | 루프 | 엔진 박동 + 레일 조인트 "덜컹". **속도에 피치·간격 연동** |
| 차체 삐걱임 | 루프 | 흔들림에 맞춘 금속 스트레스 — 무대가 살아 있다는 감각 |
| 기적(汽笛) | 원샷 | 지역 전환·최종장·수동. **세계관상 "부름을 흐트러뜨리는 소리"** — 가장 상징적인 한 방 |
| 화구·연료 투입 | 원샷 | 뚜껑 열림 → 투입 → 점화. 3단으로 나누면 "넣었다"가 확실해진다 |
| 저연료 경고 | 루프/원샷 | §2.2 표 — 별도 알림음보다 **엔진 자체의 변화**를 먼저 쓴다 |
| 칸별 앰비언스 | 루프 | 모닥불, 용광로, 정수기 물, 히터. 건축물이 늘수록 열차가 시끄러워진다 |
| 연결부 스트레스 | 루프 | 내구도 하락에 따라 삐걱임 증가 — **파괴 전에 들린다** |
| 연결부 파단 | 원샷 | 금속 비명 → 파단. 밤 방어전의 핵심 실패 신호 |
| 칸 이탈 | 원샷 | 멀어지는 도플러 — 뒤로 흘러가는 것이 들려야 한다 |
| 칸 재결합 | 원샷 | 체결 "쿵" + 잠김. 성공의 보상음 |
| 칸 피격·파괴 | 원샷 | 재질별 타격 + 붕괴 |
| 차륜·제동 | 루프 | 감속·가속 구간 전용 |

- **연결부는 "파괴 전에 소리로 예고"한다.** [기획서 §9.1](Train-Survival-기획서.md)의 순차 파괴
  규칙 덕분에 위험 지점이 항상 한 곳(후미)이므로, 그 한 곳이 비명을 지르면 방어 지점이 청각으로 지정된다.

## 6. 집게(하푼) — 코어 상호작용

[수직 슬라이스 스펙 §회수 연출](Train-Survival-수직슬라이스-스펙.md)이 *"로프가 되감기는 시각 연출
+ **릴 사운드** — 기다리는 시간이 아니라 회수하는 시간으로 체감시킴"* 으로 **이미 명시적으로 요구**한
항목이다. `HarpoonState` 상태머신에 1:1로 대응시킨다.

| 상태 | 사운드 | 비고 |
|---|---|---|
| `Ready` → 발사 | 공압 발사음 | **입력 즉시 로컬**(기둥 5). 티어 1/2/3 음색 구분 |
| `Firing` | 로프 풀림 루프 | 비행 거리감 |
| 명중 → `PendingGrab` | 재질별 명중음 | 나무·돌·금속·살점·천(보따리) 5종 |
| `Reeling` | **릴 감기 루프** | 티어별 속도 → 피치. 상위 티어의 이점이 귀로 들린다 |
| `Holding` | 파지 유지 루프 | 대상 무게에 따른 로프 텐션. 무거울수록 낮고 팽팽하다 |
| `MissRecovery` | 빗맞음 + 회수 | **페널티 구간이 들려야 한다** — 재발사 불가를 소리로 안다 |
| 쿨다운 종료 | 재장전 완료 "찰칵" | 다시 쏠 수 있음을 알린다. 짧고 건조하게 |
| 그랩 거부 | **거부음** | [집게 파지 검증 I2](../plans/features/집게-단계별-파지-1차-플레이-검증-항목.md)의 이월 항목 |
| 티어 변경 | 강화 완료음 | |
| 손잡이 이탈 저항 | 텐션 루프 + 성공/실패 | [손잡이 스펙](Train-Survival-손잡이-이탈저항-스펙.md) `HoldGauge` 연동. **게이지가 소리로 읽혀야 한다** |

- 집게는 이 게임에서 **가장 자주 듣는 소리**다. 반복 피로를 피하기 위해 발사·명중은
  변형 3~4종 랜덤 + 미세 피치 랜덤(±3%)을 기본으로 한다.

| 볼트액션 라이플 | 발사(원거리 잔향) · 볼트 조작 · 장전 · 빈 격발 |
| 근접(마체테/도끼) | 스윙(허공) · 명중(재질별). **[M5 2차에서 "스윙 사운드가 없어 쿨다운 간격을 체감할 수 없다"로 이월된 항목](../plans/M5/M5-2차-플레이-검증-항목.md)** |
| 수리 망치 | 타격 반복 · 수리 완료 · 대상 없음(헛침) |
| 공통 | 탄피 낙하(재질별 바닥) · 피탄 임팩트(재질 5종) · 트레이서 통과음 · 무기 전환(꺼냄/집어넣음) |

- **빈 격발은 탄약 UI보다 먼저 온다.** 총을 쏘다 탄이 떨어진 순간을 화면으로 확인시키면 늦다.
- **재질별 피탄음이 조준 피드백의 절반이다.** 맞았는지 빗나갔는지를 소리로 판정한다 —
  현재 `ImpactEffectView.Play(position, normal)`에 **재질 정보가 없다**(§21).

## 8. 몬스터 · 보스

### 8.1 별들림의 청각 3요소

[세계관 §3.2](Train-Survival-세계관-컨셉.md)의 시각 3요소(눈 / 별씨 결정 / 자세)에 대응하는
**청각 규칙**이다. 신규 몬스터를 추가할 때도 이 규칙만 적용한다.

| # | 요소 | 내용 |
|---|---|---|
| 1 | **원음 유지** | 울음은 **원래 동물의 것**이다. 토끼는 토끼처럼, 여우는 여우처럼 운다. 피치를 낮추거나 왜곡해 크리처화하지 않는다 |
| 2 | **별씨 웅웅거림** | 개체마다 **낮고 일정한 hum**이 붙는다 ([세계관 §3.1](Train-Survival-세계관-컨셉.md) *"따뜻하고, 아주 낮게 웅웅거린다"*). 이것이 "씌었다"의 유일한 청각 증거다 |
| 3 | **호흡·자세** | 낮은 자세에서 나오는 거친 숨. 근거리 전용 |

**금지 사항**: 괴성, 포효로 원음 덮기, 리버스 리버브·피치 시프트 같은 호러 관용구.
전부 §2의 대비를 죽인다. **[비주얼 가이드 §16 Do/Don't](Train-Survival-비주얼-UIUX-가이드.md)의
"크리처화 금지"와 같은 규칙이다.**

### 8.2 거리별 읽기 — 청각판

[세계관 §3.2.1](Train-Survival-세계관-컨셉.md)의 거리별 시각 층에 청각 층을 정확히 겹친다.
**밤에는 청각 층이 먼저 도착한다.**

| 거리 | 시각(세계관 §3.2.1) | 청각 | 전달되는 정보 |
|---|---|---|---|
| **20 m+** | 어둠 속 붉은 점 2개 | **웅웅거림 + 발소리 무리** | "온다" — **수와 방향**. 좌우 패닝이 주 채널 |
| **10~15 m** | 귀여운 동물임이 읽힘 | **동물 원음(울음)** | §2의 대비가 여기서 발생한다 — 시각과 같은 지점 |
| **3~5 m** | 자세, 곤두선 털 | **도약 예고음** (숨 들이쉼) | "덤빈다" — **회피 판단의 단서** |
| **1~2 m** | 눈 모양, 결정 디테일 | 거친 숨, 결정의 미세 진동 | "화났다" |
| **처치** | **빛이 꺼진다** | **웅웅거림이 먼저 끊기고, 동물 소리가 반 박자 남았다 사라진다** | **"별들림이 풀렸다"** |

- 마지막 줄이 이 게임 몬스터 오디오의 결론이다. 세계관 §3.2의 *"잠들듯 쓰러진다 · 짧은 정적"* 을
  소리로 구현하면 **비명이 아니라 hum의 소멸**이 된다. 죄책감은 여기서 나온다.
- **3~5 m의 도약 예고음은 게임플레이 정보다.** 갑판 도약 수평 사거리가 3 m이므로
  (`LeapHorizontalRange`), 이 소리가 없으면 도약은 회피 불가능한 이벤트가 된다.

### 8.3 종류별

| 대상 | 사운드 |
|---|---|
| 일반 3종(Runner/Brute/Leaper) | 접근 울음 · 발소리(체급별) · 도약 · 공격 · 피격 · 사망 |
| 스탬피드 | 지축 울림 접근 루프 — **거리가 멀어도 들린다**(예외적으로 감쇠 완만) |
| 골렘(사막·북극) | **지형과 같은 재질** — 돌·유리·얼음의 마찰. 동물 소리는 일절 없다. [세계관 §5.2](Train-Survival-세계관-컨셉.md)의 *"말이 통하지 않는다"* 를 소리로 만든다 |
| 보스 공통 | 등장 · 페이즈 전환 · **차지 텔레그래프** · 돌진 · 투사체 발사/비행/착탄 · 사망 |
| 웨이브 | 밤 시작 신호 · 마지막 밤 예고 · 웨이브 종료 |

- **차지 텔레그래프는 최우선 신호다.** `ChargeTelegraphSeconds` 기본값 **1.2초** 안에 회피 판단이
  끝나야 하고, 보스가 화면 밖에 있을 수 있다. §4.2 순위 1에 배치한다.
- **보스 사망은 정적을 쓴다.** 격파 배너보다 **소리가 멎는 것**이 먼저다.

## 9. 플레이어

| 요소 | 내용 |
|---|---|
| **발소리** | **재질별 필수** — 열차 지붕(금속) / 갑판(나무) / 지상 타일(흙·모래·풀·눈). 지역이 바뀐 것을 발밑으로 안다 |
| 점프·착지·낙하 | 착지는 높이별 2단 |
| 피격·사망·부활 | 사망은 짧게. 부활은 숨이 돌아오는 소리 |
| 허기 | 배에서 나는 소리 → 심장박동(임계) |
| 체온 | 더위(귀 울림) / 추위(이 떨림) — **색이 위험도를, 소리가 원인을** 말한다([비주얼 가이드 §18.1](Train-Survival-비주얼-UIUX-가이드.md)의 대응 규칙) |
| 동상 | 부위 감각 소실 — 먹먹해지는 필터 |
| **낙오 경고** | **긴급도 최상.** 열차가 멀어지는 도플러 — 다이제틱으로 처리하면 알림음이 필요 없다 |
| 음식 섭취 | 씹기 → 삼킴 → 버프 획득 |
| 시점 전환 | 1인칭/3인칭 전환 시 리스너 위치 변화(§14) |

- 발소리는 **본인 것은 2D 근접, 타인 것은 3D**다(§15). 4인이 좁은 열차 위에 있으므로
  타인 발소리는 감쇠를 짧게 잡지 않으면 소음이 된다.

## 11. 환경 앰비언스

### 11.1 지역 4종 × 낮/밤

| 지역 | 낮 | 밤 |
|---|---|---|
| 숲 (봄) | 새소리, 잎사귀 바람, 물소리 | 풀벌레, 부엉이 — **살아 있는 밤** |
| 사막 (여름) | 열기 바람, 모래 흐름, 정적 | 급랭 바람, 먼 울음 |
| 대초원 (가을) | 풀 물결, 풍차 삐걱임, 새 떼 | 낮고 넓은 바람 |
| 북극 (겨울) | 눈보라, 얼음 균열 | **거의 무음** + 초저역(오로라) |

- **북극의 밤이 가장 조용하다.** [세계관 §4.4](Train-Survival-세계관-컨셉.md)의 정서 *"불안"* 을
  소리를 빼서 만든다 — 기둥 3(정적은 리소스)의 최대 사용처이자, 최종장 무음의 예고편이다.
- 지역이 바뀌면 앰비언스는 **크로스페이드**한다. 기적(§5) 한 방이 그 전환을 덮는다.

### 11.2 날씨 3종

`Weather_Sandstorm` / `Weather_Blizzard` / `Weather_ColdSnap` — 각각 **진입 / 루프 / 이탈** 3구성.

- 모래폭풍·눈보라는 **마스킹이 게임플레이다.** 시야가 차단되는 만큼 청각도 덮이면 이중 불이익이 된다.
  → **몬스터 접근음은 날씨 루프에 먹히지 않도록 주파수를 비켜 배치**한다(§3의 마스킹 베드 규칙).

## 12. UI 사운드

[비주얼 가이드 §19](Train-Survival-비주얼-UIUX-가이드.md)가 별도 문서로 미뤄 둔 항목이 여기다.

| 대상 | 소리 |
|---|---|
| 메뉴 | hover / click / back / 탭 전환 / 슬라이더 틱 |
| 패널 | 열기 / 닫기 (§10과 공유) |
| 배너 | 등장(`HudBannerQueue`) — 긴급도별 3단 |
| 상태 경계 | 안전→주의→경고→위험 진입 시 각 1회 (`HudTransientFade`의 유예 2초와 동기) |
| 세션 | 로비 접속 / 플레이어 입장·퇴장 / 게임오버 / 업적 해금 |

- **상태 경계음은 유예 2초 안에서 반복되지 않는다.** 비주얼 §9.2가 깜빡임을 막으려고 넣은
  유예를 청각도 그대로 쓴다 — 안 그러면 임계값 근처에서 소리가 떨린다.
- UI 사운드는 **월드 재질 어휘를 공유한다**([비주얼 가이드 §17](Train-Survival-비주얼-UIUX-가이드.md)
  검수 항목). 전자음이 아니라 **황동·나무·가죽**의 소리다.

## 13. 음악

| 트랙 | 용도 |
|---|---|
| 타이틀 / 로비 | |
| 지역 테마 4종 | 각 지역의 정서([세계관 §4.4](Train-Survival-세계관-컨셉.md)) — 설렘 / 경외 / 그리움 / 불안 |

| 보스 4종 | 지역 테마의 변주 — 처음 듣는 곡이 아니어야 "이 지역의 결산"으로 읽힌다 |
| 게임오버 | |
| **최종장 3단** | ① 초가속 방어전(상승) → ② 공간 왜곡(붕괴) → ③ **완전한 무음** |

  **여기까지 오는 모든 소리는 이 한 번의 무음을 위해 쌓인다**(기둥 3).
- 레이어드 믹스를 쓰면 4(지역) + 1(전투 레이어) + 4(보스) 구성으로 8트랙 이상을 절약할 수 있다.

## 14. 3D 공간 · 발성 예산

| 항목 | 규칙 |
|---|---|
| 리스너 위치 | 1인칭 카메라. **3인칭 전환 시에도 리스너는 캐릭터 머리에 둔다** — 카메라를 따라가면 소리가 뒤로 물러난다 |
| 감쇠 프리셋 A (열차 내부) | 40 m 무대에 4인 → **짧고 급한 감쇠**. min 2 m / max 25 m |
| 감쇠 프리셋 B (선로 밖) | 교전 거리 14~24 m가 들려야 한다 → min 5 m / max 60 m |
| 감쇠 프리셋 C (원거리 사건) | 스탬피드·보스·기적 → max 150 m, 완만 |
| 도플러 | **열차 관련만 사용**(칸 이탈·낙오 경고). 나머지는 0 — 무대가 흔들려서 오작동한다 |
| 동시 발성 상한 | 전체 **32**, 그중 `SFX_World` **16** |
| 같은 클립 상한 | 동종 4개 — 웨이브 12체가 동시에 울면 하나의 굉음이 된다 |
| 쿨다운 | 발소리·피격 등 고빈도 소리는 소스별 최소 간격 |
| 풀링 | `AudioSource`는 `PoolManager` 경유([아키텍처 규칙](../conventions/architecture-rules.md)) |

- **밤 웨이브 최대 물량**(동시 12 + 플레이어 4 + 자원 12, [M8 완료 기준](../guide/Train-Survival-개발-가이드.md))이
  발성 예산의 설계 피크다. 여기서 안 터지면 나머지는 여유가 있다.

## 15. 네트워크 규칙

[네트워크 아키텍처 §4](Train-Survival-네트워크-아키텍처.md)의 권위 모델을 오디오에 적용한 판단 기준이다.

| 소리의 성격 | 재생 방식 | 예 |
|---|---|---|
| **내 조작의 결과** | **로컬 즉시** — 호스트 승인을 기다리지 않는다 | 발사, 릴, 거부음, UI |
| **모두가 봐야 하는 사건** | **권위 이벤트 구독** — 호스트가 확정한 것을 전원이 재생 | 몬스터 사망, 칸 파괴, 보스 페이즈 |
| **타인의 조작** | **브로드캐스트 RPC** — 소유자 제외 | 동료 총성, 동료 집게 |
| **로컬 표현만** | `*LocalEvent` 구독 — **본인만** | 패널 열기, 프롬프트, 조준 상태 |

- **판단 규칙**: `*LocalEvent`로 끝나는 이벤트에 붙인 소리를 남이 들으면 버그다.
  반대로 권위 이벤트에 붙인 소리를 나만 들으면 협동이 깨진다.
- 소리는 게임 상태를 바꾸지 않는다 — **오디오 때문에 새 네트워크 상태를 만들지 않는다.**
  M8의 시각 연출과 같은 원칙이다.

## 19. Do / Don't

| Do | Don't |
|---|---|
| 조용해지는 것을 위험으로 쓴다 | 위험할 때 소리를 키우기만 한다 |
| 동물 원음을 남긴다 | 괴성·왜곡으로 크리처화한다 |
| 정보성 소리를 중고역에 둔다 | 저역 경고음을 만든다 (엔진에 먹힌다) |
| 세계의 소리로 상태를 알린다 | 모든 상태에 알림음을 붙인다 |
| 내 조작은 지연 0으로 재생한다 | 호스트 승인 후 발사음을 낸다 |
| 정적을 아껴 쓴다 | 계속 시끄럽게 채운다 |
| 같은 뜻에 같은 소리를 쓴다 | 화면마다 다른 확인음을 쓴다 |
| 시각 단서와 쌍을 이룬다 | 오디오로만 전달되는 정보를 만든다 |

## 20. 검수 기준 — "한 장의 기준 사운드"

본격적인 에셋 확보 전에 아래 범위로 **한 장면**을 만들어 통과시킨다.
[비주얼 가이드 §17](Train-Survival-비주얼-UIUX-가이드.md)의 기준 화면과 같은 씬에서 함께 본다.

> **Prototype Scope**: 열차 주행 루프 + 숲 낮/밤 앰비언스 + 집게 1사이클(발사→릴→명중→거부) +
> 리볼버 발사·재장전·빈 격발 + 별들린 동물 1종(접근→도약→피격→사망) + UI 확인/거부 + 발소리 2재질

**Acceptance Checklist**

- ☐ 화면을 보지 않고 **몬스터의 수와 방향**을 말할 수 있다.
- ☐ 화면을 보지 않고 **연료가 부족해지는 것**을 안다.
- ☐ 처치 순간 **웅웅거림이 먼저 꺼지는 것**이 들린다.
- ☐ 20 m 밖 개체와 5 m 개체를 소리만으로 구분할 수 있다.
- ☐ 도약 예고음을 듣고 회피할 시간이 있다.
- ☐ 열차 주행음 위에서 총성·경고가 **묻히지 않는다**.
- ☐ 내 총성과 동료 총성이 구분된다.
- ☐ 발사 입력과 발사음 사이에 **체감 지연이 없다**(호스트·클라 양쪽).
- ☐ 같은 소리를 20회 연속 들어도 거슬리지 않는다.
- ☐ 4인 동시 행동 시 소리가 뭉개지지 않는다(발성 상한 동작 확인).
- ☐ 밤 웨이브 최대 물량에서 프레임·오디오 드롭이 없다.
- ☐ 볼륨 슬라이더 5종이 각자 맞는 대상만 조절한다.
- ☐ **전부 음소거해도 플레이가 성립한다**(§16).
- ☐ 낮→밤 앰비언스 전환에 끊김이 없다.

## 21. 현재 구현과의 격차 · 이행 순서

**실측 (2026-08-20)**: 스크립트 **294개** 중 오디오 참조 **0개**. 오디오 클립·믹서 **0개**.

### 21.1 이미 있는 훅 — 구독만 하면 되는 것

| 낮/밤 전환 · 지역 전환 · 날씨 | `DayPhaseChangedEvent` · `RegionChangedEvent` · `WeatherChangedEvent` |

### 21.2 없는 훅 — 코드 작업이 선행되는 것

| # | 필요한 소리 | 현재 상태 | 필요한 작업 |
|---|---|---|---|
| 1 | **총 발사음** | `WeaponAmmoChangedLocalEvent`만 있다 — 탄약 수 변화로는 **빈 격발**(수가 안 변한다)과 구분되지 않고, 발사 시점과도 어긋난다 | `WeaponFiredLocalEvent`(성공/빈 격발 구분) 신설 |
| 2 | **근접 스윙·명중** | `MeleeSwingView.PlaySwing()` 진입점은 있다 | 진입점에 재생 추가 — **이건 이벤트 신설 없이 된다** |
| 3 | **재질별 피탄음** | `ImpactEffectView.Play(position, normal)`에 **재질 정보가 없다** | 표면 재질 판정(태그/레이어 또는 `PhysicMaterial`) 추가 |
| 4 | **몬스터 공격·도약** | `MonsterAgent`의 `TryBeginDeckLeap`·`ServerTryAttack`은 **서버 로직뿐** — 표현 브로드캐스트가 없다 | 표현용 RPC 또는 로컬 이벤트 신설. **§8.2의 도약 예고음이 여기 걸린다** |
| 5 | **몬스터 사망 위치** | `MonsterDiedEvent`는 `killerClientId`만 나른다. `NotifyDiedRpc`는 `deathPosition`을 받지만 이벤트로 넘기지 않는다 | 이벤트에 위치 추가, 또는 `NotifyDiedRpc`에서 직접 재생 |
| 6 | **제작 완료** | `CraftingEvents`에 완료 알림이 없다 (`RequestCraftServerRpc`만) | 완료/실패 이벤트 신설 |
| 7 | **발소리 재질** | `PlayerMotor`에 지면 재질 조회가 없다 | 접지 판정 시 재질 조회 + 보폭 타이밍 |
| 8 | **주행음 속도 연동** | `WorldScrollController`에 속도는 있다 | 읽어서 피치·간격에 매핑 |

### 21.3 권장 이행 순서

*(이 문서는 순서만 제안하고, 실행은 별도 마일스톤에서 계획한다 — 비주얼 가이드 §18과 같은 방식)*

| 차수 | 내용 | 근거 |
|---|---|---|
| **1. 인프라** | `IAudioService` + `AudioMixer` 5버스 + `AudioSource` 풀 + 볼륨 설정·저장 | 이게 없으면 **한 개도 못 붙는다.** 순수 로직(믹스 계산·쿨다운·발성 상한)은 EditMode로 고정 |
| **2. 조작 피드백** | 집게(§6) · 총기(§7) · UI 확인/거부(§12) · 발소리 2재질 | **이월 3건이 여기서 전부 해소된다** — 집게 거부음(I2) · 근접 스윙음(M5 2차) · 릴 사운드(슬라이스 스펙). §21.2의 1·2번 선행 |
| **3. 세계 존재감** | 열차 주행·삐걱임(§5) · 지역 앰비언스 4종(§11) · 낮/밤 전환 | 기둥 1·2가 성립하는 지점. §21.2의 8번 선행 |
| **4. 위협 전달** | 몬스터 거리별 층(§8.2) · 도약 예고 · 보스 텔레그래프 · 연결부 스트레스 · 낙오/연료 경고 | **게임플레이 정보다.** §21.2의 4·5번 선행 |
| **5. 마감** | 건설·제작(§10) · 날씨(§11.2) · 재질별 피탄(§7) | §21.2의 3·6번 선행 |
| **6. 음악** | 지역 테마 + 전투 레이어 + 보스 + **최종장 3단**(§13) | 최종장은 해당 콘텐츠 구현 후 |

> **선행 조건**: [M8 2차 플레이 검증](../plans/M8/M8-2차-구현-계획.md)이 먼저다.
> 검증 중에 오디오를 넣으면 "낮/밤 전환이 읽히는가"의 원인 분리가 어려워진다 —
> 비주얼 가이드 §18이 HUD 재배치에 걸었던 것과 같은 조건이다.

## 22. 미결 사항

| 항목 | 내용 |
|---|---|
| **오디오 스택** | Unity 내장 `AudioMixer`로 갈지, FMOD/Wwise 미들웨어를 도입할지. 레이어드 음악(§13)과 상태 기반 믹스는 미들웨어가 유리하나 **빌드·라이선스·팀 규모** 대비 판단 필요 |
| **음원 확보 경로** | 라이브러리 구매 / 외주 / 직접 제작. **상업 배포 라이선스** 확인이 선행된다(폰트 미결과 같은 성격) |
| **HUD 연료 줄의 거취** | §2.2의 엔진 소리 + [비주얼 §9.5](Train-Survival-비주얼-UIUX-가이드.md)의 화실 불빛이 둘 다 서면 HUD 연료 줄을 지울 수 있는가 — **플레이 검증 필요** |
| **동물 원음의 출처** | §8.1 "원음 유지"를 실제 동물 녹음으로 갈지, 스타일라이즈드 톤에 맞춰 가공할지 |
| **보스 음악의 구조** | 지역 테마 변주(§13)가 실제로 "결산"으로 들리는지 검증 필요 |
| **자막·시각 대체** | §16의 접근성 — 중요 사건에 텍스트를 병기할지, 방향 인디케이터로 대체할지 |
| **햅틱** | [비주얼 §19](Train-Survival-비주얼-UIUX-가이드.md)가 "소리·햅틱"을 묶어 남겼다. 이 문서는 소리만 다룬다 — PC/키보드 기준이라 우선순위가 낮으나, 게임패드 지원 시 재검토 |
| **보이스·내레이션** | [세계관 §7](Train-Survival-세계관-컨셉.md)의 *"서사 전달 수단 — 최소한의 텍스트/음성을 둘지 미정"* 이 미결이라, §4.1 버스는 **5개로 고정**했다. 음성을 채택하면 `Voice` 버스와 대사 우선순위 규칙이 추가된다 |
| **기적의 게임플레이화** | §5의 기적이 세계관상 "부름을 흐트러뜨리는 소리"라면, **실제로 몬스터를 흩는 조작**이 될 수 있는가 — 기획서에 없는 제안이므로 채택 여부 판단 필요 |
