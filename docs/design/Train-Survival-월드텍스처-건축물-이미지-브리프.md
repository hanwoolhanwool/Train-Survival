# Train Survival 월드 텍스처·건축물 이미지 제작 브리프

작성일 2026-10-27 · v1.1 · 11종 제작·프로젝트 적용 완료

## 1 범위와 근거

이번 제작·적용 범위는 **북극 지면 1장, 바다 해저 1장, 설치 가능한 건축물 아이콘 9종으로 총 11종**이다. 피격·결빙·수중 피드백은 §6에서 이미지와 구현의 역할을 구분해 다음 제작 규격을 정한다.

기존 [세계관 컨셉](Train-Survival-세계관-컨셉.md), [비주얼·UIUX 가이드](Train-Survival-비주얼-UIUX-가이드.md), [이미지 생성 브리프 §M](Train-Survival-이미지생성-브리프.md), [인게임 UI 이미지 브리프](Train-Survival-인게임-UI-이미지-브리프.md)를 기준으로 한다. 자연은 부드러운 세미 카툰, 열차 위 생활 시설은 관리되는 낡은 철판·목재·배관으로 표현한다. 황폐한 사실주의나 과장된 녹·피·공포 이미지를 추가하지 않는다.

건축물 정체성은 `StructureCatalog.asset`에서 설치 가능한 항목과 실제 프리팹을 기준으로 한다. 온실 돔은 `_placeable: 0`이므로 제외한다. 건축물의 실제 모델·도색을 먼저 확인하고, 원본이 단순한 프리미티브인 경우 그 실루엣을 유지하면서 기존 아이템 아이콘의 재질 표현만 보완한다. 완성된 3D 모델이 있는 것처럼 기록하지 않는다.

## 2 월드 텍스처 공통 규격

- 출력: 정사각형 PNG, 최종 1024×1024, 불투명 BaseColor, sRGB, Repeat, mipmap 사용.
- 완전한 수직 탑다운. 프레임 전체가 표면이며 원근·수평선·하늘·가장자리 비네트가 없다.
- 10m 패치에 대응하는 큰 2~4m 색면과 중간 0.5m 변화. 사진 스캔 같은 미세 노이즈를 넣지 않는다.
- 방향성 조명, 투사 그림자, 반사광, 물결 코스틱, 발광, 글씨, 발자국, 레일, 큰 소품을 굽지 않는다.
- 생성 원본의 심리스를 가정하지 않는다. 2×2 반복과 반폭 오프셋을 검수한다. 실패하면 이미지 생성 도구로 이음매 수정을 요청하고 재검수한다. 통과하지 않은 이미지를 지면에 연결하지 않는다.
- 머티리얼의 `_BaseMap`과 `_MainTex`에 연결하고 `_BaseColor`·`_Color`를 흰색으로 설정한다. 다른 지역 머티리얼은 변경하지 않는다.
- 반복 수는 실제 표면 크기와 UV를 확인해 10m 반복에 맞춘다. 기존 §M의 북극 60×40m=(6,4), 해저 200×40m=(20,4)를 기준으로 하되, 현행 프리팹 치수가 다르면 실제 치수를 우선하고 결과를 기록한다.

## 3 건축물 아이콘 공통 규격

- 최종 512×512 RGBA PNG, 실제 투명 배경, 한 파일에 한 건축물. Sprite Single, Clamp, Bilinear, mipmap 없음.
- 기존 목재·망치·리볼버 아이콘과 같은 손으로 칠한 세미 카툰 재질, 큰 명암면, 절제된 모서리 마모.
- 앞면과 옆면, 상면이 읽히는 3/4 시점. 물체가 캔버스의 약 80~84%에 들어오며 잘린 부품이 없다. 지면·배경·부유 그림자·받침용 장식 타일을 새로 넣지 않는다.
- 실제 프리팹의 핵심 부품과 도색을 유지한다. 배관·다리·총신의 위치를 임의로 교체하지 않는다. 거치 총과 터렛은 총구가 우상단을 향하도록 시점을 선택한다. 이미지 좌우 반전으로 비대칭 구조를 바꾸지 않는다.
- 그림 안에 이름·수량·단계·키·테두리·상태 색을 굽지 않는다. UI에서 별도로 표시한다.
- 32·48·56px 축소본에서 서로 구분되는지 확인한다. 실제 선택·대상 안내에는 48px 슬롯을 사용한다. 실제로 존재하지 않는 건축 레시피나 조작 방식을 새로 만들지 않는다.

## 4 생성 프롬프트 기준

월드 텍스처는 “Use case: stylized-concept / Asset type: seamless tileable game BaseColor texture”로 시작하고 §2 공통 조건과 지역별 색·형태만 사용한다. 장면용 하늘·열차·광원 규칙을 섞지 않는다.

건축물은 “Use case: stylized-concept / Asset type: transparent game construction icon”으로 시작한다. 첫 참고 이미지는 해당 실제 프리팹 렌더로 구조·도색 기준, 두 번째는 기존 완성 아이템 아이콘으로 화풍 기준임을 명시한다. 실물과 화풍 참고의 역할을 혼동하지 않는다.

내장 `image_gen` 도구로 파일별 생성한다. 정확한 프롬프트, 참고 경로, 생성 원본, 최종 파일, 검수 수치는 `output/imagegen/world-structures-v1/`에 보관한다. 기존 88종 원본 이미지는 덮어쓰지 않는다.

## 5 검수와 적용 완료 조건

1. 월드 2장과 건축물 9종의 수량·파일명·해상도·알파 확인.
2. 월드 텍스처의 가로·세로 이음매, 2×2 반복, 저대비와 큰 무늬 확인.
3. 프리팹 참고와 아이콘의 핵심 부품·도색 비교. 32·48px 판독과 투명 가장자리 확인.
4. 두 머티리얼의 텍스처 참조·흰색 틴트·실제 표면에 맞는 반복 수 확인.
5. 설치 가능한 9종에만 아이콘이 매핑되는지 검사. 기존 아이템 40종과 기호·부품 참조 유지.
6. 건축 선택·설치 판정·회전·재료 차감 요청은 기존 로직 유지. Unity 컴파일과 참조·표시 검증 결과를 기록.

## 6 피드백 이미지 후속 범위

기존 결빙 비네트는 코드 생성, 수중은 카메라 앞 색상 오버레이다. 이번 11종과 분리하여 다음 **4개 이미지 파일**을 후속 제작 단위로 제안한다. 상태 판단·수치·타이밍은 이미지가 아닌 기존 게임 이벤트와 표현 코드가 담당한다.

| 후보 파일 | 규격 | 이미지 역할 | 함께 필요한 구현 |
|---|---|---|---|
| `T_FX_HitVignette` | 1024² RGBA, 중앙 투명 | 화면 가장자리의 부드러운 충격 마스크. 피·상처 묘사 없음 | 피격 이벤트, 강도·감쇠, UI 가림 최소화 |
| `T_FX_FrostMask` | 1024² RGBA, 중앙 최소 60% 투명 | 큰 서리 결정이 가장자리에만 남는 중립 백색 마스크 | 기존 동상 강도에 알파 연결, 지역·해상도 검수 |
| `T_FX_WaterSplash` | 1024² RGBA, 4×4 프레임 시트 | 입수·출수 때의 짧고 단순한 물보라 | 프레임 순서·수명·월드 크기·파티클 재질 검증 |
| `T_FX_Bubble` | 256² RGBA | 얇은 가장자리와 투명 중심의 기포 한 개 | 수중 조건·발생 위치·상승 속도·발생량 제한 |

화면 전체를 채우는 청색 필터, 물속 안개, 카메라 흔들림은 추가 이미지로 세지 않는다. 물보라 시트는 연속 동작 검증이 필요하므로 한 장의 정적 콘셉트만으로 제작 완료 처리하지 않는다.

## 7 진행 기록

### 7.1 납품과 적용

| 구분 | 수량 | 결과 |
|---|---:|---|
| 북극 지면 | 1 | 1024² RGB. 기본 지면과 현행 북극 A~J 빙판에 연결 |
| 바다 해저 | 1 | 1024² RGB. 바다 A~J 해저·얕은 해저·경사면에 연결 |
| 건축물 아이콘 | 9 | 512² RGBA. 공용 목록에 등록하고 망치의 선택 건축물·수리/철거 대상 안내에 표시 |
| 후속 피드백 | 4 후보 | §6 규격 작성. 이미지 생성·이벤트/파티클 연결은 미착수 |

- 내장 `image_gen`으로 개별 생성. [프롬프트·출처·규격 기록](../../output/imagegen/world-structures-v1/manifest.json), [최종 11종](../../output/imagegen/world-structures-v1/final), [건축물 축소 검수판](../../output/imagegen/world-structures-v1/Structures-Review.png).
- 기존 88종 PNG의 SHA-256이 모두 동일함을 확인했다. UI 공용 참조는 **97종**, 이번 전체 이미지 목록은 월드 2장을 합해 **99종**이다. 기호·공통 부품 일부는 후속 기능용 등록 자산이며 모든 파일이 동시에 화면에 쓰이는 것은 아니다.
- 최종 아이콘의 가시 영역은 512px 중 최대 약 420px이고, 사방 최소 40px 여백과 원본 알파를 유지한다. 크기·중심만 정리했으며 좌우 반전·색상 변경은 하지 않았다.
- 실제 프리팹 렌더는 [참고 폴더](references/world-structures)에 보관했다. 천막은 4×4 셀 대표 크기이며, 정적 프리뷰에서 전용 천 셰이더가 표시되지 않아 **프리뷰 사본에만 원래 천 색의 일반 재질**을 사용했다. 원본 천막 메시·재질·바람 셰이더는 변경하지 않았다.
- 거치 기관총·자동 터렛은 현재 블록아웃 형상의 아이콘이다. 두 모델의 구조가 같으므로 회청색/황갈색 도색과 별도 UI 이름으로 구분한다. 향후 모델 교체 시 아이콘도 갱신해야 한다.

### 7.2 표면 반복 검수

- 북극은 1차 생성 후 오프셋 이음매 보정본, 해저는 비교 결과 더 자연스러운 1차 생성본을 채택했다. 2×2 반복 및 Unity 표면 렌더에서 직선 이음매가 두드러지지 않는지 확인했다. 경계 픽셀이 수학적으로 완전히 같은 텍스처라는 뜻은 아니다.
- 0~255 RGB 기준 반대 경계 평균 절대 차: 북극 X **3.95** / Y **5.90**, 해저 X **5.98** / Y **4.78**. 원본 비교와 수치는 [검수 기록](../../output/imagegen/world-structures-v1/texture-seam-check.json)에 있다.
- 기본 북극 60×40m는 (6,4), 바다 200×40m는 (20,4). 현행 북극은 중앙 16×40m, 주변 52×40m와 여러 작은 빙판으로 나뉘므로 하나의 반복 값을 공유하면 늘어짐이 생긴다.
- `SurfaceTextureTiling`을 북극·바다 프리팹 총 20종에 연결했다. 대상 표면만 실제 메시 크기 기준 **10m당 1회** 반복하며, 열차 주행에 따라 표면이 미끄러지지 않도록 타일 내부 기준을 사용한다. 다른 머티리얼 속성을 유지하며 매 프레임 재계산하지 않는다.
- Unity 적용 표면: [북극](../../output/imagegen/world-structures-v1/reviews/Unity-Surface-Arctic.png), [해저](../../output/imagegen/world-structures-v1/reviews/Unity-Surface-Sea.png). 실제 프리팹에서 대상 표면만 표시한 정적 렌더이며 날씨·수중 효과를 포함한 플레이 화면은 아니다.

### 7.3 검증 범위
