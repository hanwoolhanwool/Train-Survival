# 수직 슬라이스 스펙 — 집게 프로토타입

작성일: 2026-07-18 · 버전: **v0.1 (초안)**

> 목적: 네트워크 아키텍처 문서 §6.4가 정의한 **"호스트 1 + 클라이언트 1로 집게로 물체를 낚아채는 수직 슬라이스"** 를 실제로 제작 가능하도록, 기획서 v0.2.1에 없는 구체 스펙을 확정한다.
> 모든 수치는 **튜닝 전제의 초기값**이다. 확정 수치가 아니라 "코드를 쓰기 위한 출발값"이며, 슬라이스 플레이테스트에서 조정한다.

## 1. 슬라이스 범위

### 1.1 포함

| 요소 | 내용 |
|---|---|
| 세션 | 호스트 1 + 클라이언트 1 (UnityTransport 직결). 1인 실행도 "혼자 호스트인 세션" (네트워크 문서 §7) |
| 좌표계 | 열차 원점 고정 + 월드 스크롤 (네트워크 문서 §4.1). 지형은 더미 타일 스트리밍 |
| 열차 | 기관차 + 2칸 고정 구성 (§5). 증설·파괴 없음 |
| 플레이어 | 1인칭 이동 (§4) + 낙하/이탈 규칙 |
| 집게 | **1단계 기본 집게만** (§2). 소형 자원 낚아채기 + 미스 페널티 |
| 자원 | 스크롤되는 지형 위에 소형 자원 오브젝트(돌·나뭇가지 더미) 주기 스폰. 획득 시 카운터 증가만 (인벤토리 없음) |
| 검증 | §3의 손맛 성공 기준 측정 (인공 지연 환경 포함) |

### 1.2 제외

전투(무기·몬스터), 낮/밤 루프, 제작·요리, 열차 증설/파괴, 생존 게이지, Steam 트랜스포트, 재접속. 집게의 전투 활용(기획서 §3.2)은 **몬스터가 없으므로 범위 밖**이되, 그랩 대상 인터페이스는 자원/몬스터 공용으로 설계한다.

## 2. 집게(하푼) 스펙 — 1단계 기본 집게

### 2.1 조작 모델

무기 슬롯 장비형(기획서 §6.1 "집게도 무기 슬롯 사용 가능")을 전제로 한다.

| 입력 | 동작 |
|---|---|
| 좌클릭 (탭) | **발사.** 조준점 방향으로 집게 투사체 발사 |
| 명중 시 | **자동 릴 감기 시작.** 추가 입력 불필요 — 대상이 끌려오는 동안 이동·시점 조작 자유 |
| 릴 감기 중 우클릭 | **그랩 취소.** 로프 절단, 대상은 그 자리에 낙하 (즉시 재발사 가능) |
| 빗나감(미스) | **릴 회수 시간** 동안 재발사 불가 (§2.3) |

- 채택 이유: "탭 발사 + 자동 릴"은 조작 부하가 가장 낮아 이동·경계와 병행 가능(후반 "채집 vs 경계" 분담 전제). 홀드 조준·연타 릴 등 손맛 강화 변형은 슬라이스 테스트 후 재검토.
- 조준 보조: 없음 (순수 조준점). 콘솔 이식 시 재검토.

### 2.2 수치 (초기값)

| 항목 | 값 | 근거 |
|---|---|---|
| 사거리 | **20 m** | 칸 길이(12 m, §5)의 약 1.7배. 지붕에서 선로변 자원을 노리는 감각 기준 |
| 투사체 속도 | **40 m/s** | 즉발(히트스캔)이 아닌 투사체 — 이동 목표 리드샷의 손맛 확보. 20 m 기준 비행 0.5초 |
| 릴 감기 속도 | **8 m/s** | 소형 자원 기준. 20 m 명중 시 회수까지 2.5초 |
| 발사 쿨다운 (명중·취소 후) | **0.5 s** | 연사 방지 최소값 |
| 대상 등급 | **소형만** | 돌·나뭇가지·열매 (기획서 §3.1 1단계 정의). 무게 차등은 2단계+에서 도입 |

### 2.3 미스 페널티 (기획서 §3.2 확정 사항의 수치화)

| 항목 | 값 |
|---|---|
| 릴 회수 시간 (1단계) | **2.5 s** (재발사 불가) |
| 회수 연출 | 로프가 되감기는 시각 연출 + 릴 사운드 — "기다리는 시간"이 아니라 "회수하는 시간"으로 체감시킴 |
| 상위 단계 완화 | 2단계 1.5 s / 3단계 0.8 s (안) — 슬라이스 범위 밖, 참고용 |

### 2.4 네트워크 동작 (네트워크 문서 §4·§6.3 적용)

| 구간 | 처리 |
|---|---|
| 발사 입력 | **로컬 즉시**: 발사음·로프 사출·팔 애니메이션 재생 (지연 0) → 호스트에 발사 보고 |
| 명중 판정 | 쏜 클라이언트 로컬 판정 → 호스트 보고 (사격과 동일 원칙) |
| 그랩 확정·끌기 | **호스트 소유.** 대상 오브젝트의 견인 이동은 호스트가 시뮬레이션, 클라이언트는 스냅샷 보간 |
| 시작 지연 흡수 | 명중 확정 전 로프 **탄성(늘어남) 연출**을 로컬 재생 — 호스트 확정이 도착해 견인이 시작될 때까지의 30~80 ms를 시각적으로 흡수 |
| 판정 불일치 (클라 명중 → 호스트 거부) | 로프가 "미끄러져 빠지는" 연출로 미스 전환 → 미스 페널티 적용. 발생률은 §3에서 계측 |

## 3. 손맛 검증 — 성공 기준

슬라이스의 존재 이유는 네트워크 문서 §6.3 리스크(원격 클라이언트의 반응성) 검증이다. **아래 기준을 통과하면 스택(NGO) 유지 확정, 미달이면 연출 처방 개선을 반복하고, 그래도 미달이면 Fusion 전환 조건 1(네트워크 문서 §3.3) 발동을 논의한다.**

### 3.1 측정 환경

- UnityTransport 직결 + **UTP Network Simulator로 인공 지연 부여**.
- 측정 프로파일 3종: ① RTT 0 ms (기준선) / ② RTT 60 ms + 지터 ±10 ms (국내 일반) / ③ RTT 120 ms + 지터 ±20 ms + 패킷로스 2 % (악조건).
- 측정 대상은 항상 **클라이언트 측** (호스트는 지연 0이므로 검증 대상이 아님).

### 3.2 정량 기준

| # | 항목 | 목표 | 측정 방법 |
|---|---|---|---|
| Q1 | 발사 입력 → 로컬 발사 연출 시작 | **1 프레임 이내** | 프레임 로그 |
| Q2 | 발사 입력 → 대상 견인 시작(화면상) | 프로파일 ② 기준 **250 ms 이내** | 입력 타임스탬프 ↔ 대상 첫 이동 프레임 |
| Q3 | 견인 중 대상 이동의 시각적 끊김 | 프로파일 ③에서도 **워프/역행 없음** | 육안 + 위치 로그 |
| Q4 | 명중 판정 불일치율 (클라 명중 표시 후 호스트 거부) | 프로파일 ② 기준 **1 % 미만** | 100회 이상 발사 로그 집계 |
| Q5 | 호스트 측 동작 | 전 항목 로컬 체감과 동일 (회귀 없음) | 호스트 플레이 확인 |

### 3.3 정성 기준

- 테스트 절차: 참가자(개발 인원 전원)가 **어느 쪽이 호스트인지 모르는 상태**로 양쪽을 번갈아 플레이 → 각 세션 후 "지연·이질감을 느꼈는가" 응답.
- 통과 기준: 프로파일 ②에서 **참가자 전원이 호스트/클라이언트를 구분하지 못하거나, 구분해도 "플레이에 지장 없음"으로 응답**.
- 프로파일 ③은 통과 조건이 아닌 **참고 계측** (악조건 하한 파악용).

## 4. 플레이어 이동 스펙 (1인칭)

### 4.1 기본 수치 (초기값)

| 항목 | 값 | 비고 |
|---|---|---|
| 걷기 속도 | **4.5 m/s** | |
| 달리기 속도 | **7 m/s** | 슬라이스에서는 스태미나 없음 (게이지 시스템 범위 밖) |
| 점프 높이 | **1.2 m** | 칸 지붕(높이 3 m, §5) 간 이동은 점프가 아닌 사다리/계단 — 점프는 장애물·건축물 대응용 |
| 공중 제어 | 이동 입력의 50 % | 열차 위 낙사 리스크를 조작으로 만회할 여지 |
| 웅크리기 | **슬라이스 제외** | 본편 TBD |

### 4.2 낙하·이탈 규칙

월드 스크롤 구조상 열차에서 떨어지면 지면과 함께 후방으로 밀려난다(컨베이어). 슬라이스 규칙:

| 상황 | 처리 |
|---|---|
| 열차에서 지면으로 낙하 | 사망 아님. 지면에서 이동 가능하되 스크롤에 의해 초당 열차 속도만큼 뒤로 밀림 |
| 복귀 수단 | 열차 측면·후미의 **사다리/난간 상호작용 지점**에 접근 시 탑승. 달리기(7 m/s) > 기본 열차 속도(6 m/s, §5)로 설정해 **전력 질주하면 따라잡을 수 있게** — "떨어지면 긴장되지만 즉사는 아닌" 감각 |
| 이탈 한계 | 열차 후미 기준 **40 m** 이상 뒤처지면 사망 → 기획서 §9.1 부활 규칙 적용 (슬라이스에서는 후미 칸에서 5초 후 부활) |
| 화면 연출 | 30 m부터 화면 가장자리 경고 + 거리 표시 |

- 본편에서는 지역·몬스터에 따라 지상 체류의 위험도가 달라질 수 있으나(예: 지상 몬스터 습격), 그 확장은 본편 몬스터 설계와 함께 결정한다. **"낙하 = 즉사 아님 + 추격 복귀 가능"** 원칙만 본편 확정 사항으로 승격 제안.

### 4.3 네트워크 전제

- 이동은 소유자 권위, 상태 머신은 처음부터 `Normal / Grabbed / Carried` 골격을 포함해 작성한다 (네트워크 문서 §4.2 — "일단 로컬 이동만 만들고 나중에 추가" 금지).
- 슬라이스에서 `Grabbed/Carried`로 전환하는 콘텐츠(몬스터)는 없으나, **상태 전환 RPC 경로는 디버그 명령으로 검증**한다.

## 5. 열차 규모 (레벨 디자인 기준 단위)

| 항목 | 값 | 근거 |
|---|---|---|
| 칸 길이 | **12 m** | 실제 화차(13~15 m)보다 약간 압축 — 1인칭 체감상 "한눈에 들어오는 방어 단위" |
| 칸 폭 | **3 m** | 지붕 위 2인 교차 이동 + 거치 무기 1기 배치 가능한 최소 폭 |
| 지붕 높이 (지면 기준) | **3 m** | 지면 자원과의 시차로 집게 조준각 형성 |
| 칸 간 연결부 | **1.5 m** | 점프 없이 도보 통과 가능. 본편에서 방어 목표(연쇄 이탈 규칙)가 되는 공간 |
| 슬라이스 구성 | **기관차 + 2칸 = 총 약 40 m** | 이동·집게 사거리(20 m) 감각 검증에 충분한 최소 구성 |
| 기본 열차 속도 (스크롤 속도) | **6 m/s** | 플레이어 달리기(7 m/s)보다 낮게 — §4.2 복귀 규칙 성립 조건. 본편에서는 연료 상태에 따라 가변 |

- 칸 크기(12 × 3 m)는 이후 **건축 그리드·칸 증설 프리팹의 기준 단위**가 되므로, 슬라이스 테스트에서 이동감·조준감으로 먼저 검증하는 것이 목적.

## 6. 미결 (슬라이스 이후 결정)

| 항목 | 결정 시점 |
|---|---|
| 집게 손맛 변형 (홀드 조준, 릴 연타 등) | 슬라이스 테스트 결과에 따라 |
| 2·3단계 집게 수치, 무게 등급별 릴 속도 | 자원/제작 트리 설계와 함께 |
| 낙하 규칙의 본편 확장 (지상 몬스터 위험도, 지역별 차등) | 몬스터 설계 시 |
| 스태미나와 달리기의 관계 (복귀 규칙 난이도에 직결) | 생존 게이지 설계 시 |
| 웅크리기·조준 보조 | 본편 전투 설계 시 |
