## 1. 코어 ① 보온 장비 기본 체온 상향

**배경**: 5차 검증 사용자 원문 — "보온 장비를 입으면 기본 체온이 36.5보다 높았으면.
온실 돔에 들어가도 그 높아진 값까지만 내려가게". 현재 장비 축은 단열 계수뿐이라
(`EquipmentCatalog`의 `_coldInsulation`·`_heatInsulation` — 환경 온도를 쾌적대로 당김)
쾌적한 환경에서는 장비가 체온에 아무 영향이 없다.

**수식 관찰**: `TemperatureMath.Step`은 쾌적대 안에서 회복 목표가 `curve.NormalBody`다 —
**이 값을 장비가 밀어 올리면 요청이 수식 그대로 성립한다**. 돔(그늘)은 환경을 쾌적대로
당길 뿐이므로, 쾌적해진 환경에서의 수렴점이 `NormalBody + 보너스`가 된다
("그 높아진 값까지만 내려간다" — 별도 분기 없음).

| 축 | 설계 |
|---|---|
| 데이터 | `EquipmentCatalog.Entry`에 `_bodyWarmthBonus` (℃, `Min(0)`) 추가 — 단열 계수와 같은 자리, 같은 규약 |
| 합산 | `PlayerInventory.GetEquippedBodyWarmth()` — 착용 장비 합산 후 `EquipmentLogic.ClampBodyWarmth`로 클램프 (단열 합산 `ClampInsulation`과 같은 구조) |
| 클램프 상한 | **+1.0 ℃ 제안** — `NormalBody(36.5) + 1.0 = 37.5 < HeatWarn(38)`. 장비를 겹쳐 입어도 **경고 구간에 스스로 들어가지 않는** 안전선 (스튜 상한과 같은 사상) |
| 수식 반영 | `TemperatureSettings.ToCurve(float bodyWarmthBonus)` 오버로드 — `NormalBody`만 상향한 곡선을 만든다. `Step`·`GetStress` 등 순수 함수는 **무변** (곡선이 이미 담고 있다) |
| 호출부 | `PlayerTemperature.Update`에서 `_inventory.GetEquippedBodyWarmth()`를 곡선 생성에 주입 — 단열 적용(`ApplyInsulation`)과 같은 프레임, 같은 서버 권위 |
| 유지 | 사망~부활 리셋·`OnNetworkSpawn` 초기값은 기본 `NormalBodyTemperature` 그대로 — 부활 직후 첫 Update가 자연 회복시킨다 (전용 처리 없음) |
| 무변 | 스튜 즉시 체온 상한(38/39 ℃ 국면화)·요리 보온 버프(단열 가산 축)·단열 역효과(음수 계수) — 전부 다른 축, 손대지 않는다 |

- 확정 값 (구현 중 실제 아이템명으로 정정 — "방한 세트"는 단일 아이템이 아니라 조합):
  **가죽 옷 +0.5 ℃ / 누비 바지 +0.2 ℃ / 사막 로브·투구·장화 0 ℃** (보온 조합 합산 +0.7,
  로브는 더위 장비 — 체온 상향은 추위 대비 축이다). 전부 에셋이라 플레이 검증에서 조정
- EditMode: 곡선 상향 후 쾌적대 회복 목표 = 36.5 + 보너스 / 돔 통과(`ResolveAmbient`) 후에도
  동일 / 클램프 경계 / 보너스 0 = 기존 곡선과 동일(회귀 안전선)

## 2. 코어 ② 전 지역 온도

**배경**: 5차 검증 사용자 원문 — "사막이 아닌 지역에서도 온도가 있으면 좋겠다".
현재 숲은 낮 22 / 밤 15 ℃로 쾌적대(10~32 ℃) 안 — **온도 압박이 0**이라 옷·난방·스튜 보온이
숲 구간(기본 5일) 내내 무의미하다.

**설계 원칙**: 수식·컴포넌트는 이미 지역 온도를 일반적으로 처리한다
(`PlayerTemperature.GetRegionAmbient` → 낮/밤 국면별 `RegionDefinition` 값). 따라서 이 항목의
본체는 **에셋 값 설계**다 — 쾌적대(`TemperatureSettings`)는 건드리지 않는 것을 제안한다
(쾌적대를 좁히면 건축물 완화·단열·스튜 상한 등 기존 균형 축이 전부 흔들린다.
지역 값만으로 압박을 만드는 쪽이 되돌리기 쉽다).

| 지역 | 현재 (낮/밤) | 제안 (낮/밤) | 의도 |
|---|---|---|---|
| 숲 | 22 / 15 ℃ | 22 / **5 ℃** | 낮은 쾌적 유지(지역 개성 — 숲은 "온화한 낮") · **밤은 완만한 추위** — 표류 0.06 ℃/s로 방치 시 약 25초에 저온 경고(35 ℃) 진입. 난방기·보온 장비·모닥불 스튜가 밤마다 가치를 갖는다 |
| 사막 | 45 / 2 ℃ | 유지 | 이미 양방향 압박 성립 (기획서 §4.2) |

- 숲 밤 5 ℃는 사막 밤 2 ℃보다 완만하다 — 지역 난이도 서열(숲 1 / 사막 4) 유지
- 보온 장비(§1)와의 결합: 방한 세트(단열 + 체온 상향) 착용 시 숲 밤이 사실상 무압박이 되는
  것이 **의도된 보상 구조**다 — "옷의 가치가 상시 성립"의 성립 형태
- EditMode 신규 없음 (수식 무변·값은 에셋) — 검증은 플레이 (숲 밤 경고 발생·난방기 완화·
  장비 착용 시 무압박)

## 3. 소규모 ① (A6) 취소 순간이동 해소

**원인 확정**: `ResourceNode.ReleaseGrab`이 낙하 지점 Y를 `_spawnPosition.Value.y`(원래 스폰
높이)로 **되돌려 재바인딩**한다 — 공중에서 취소하면 지면으로 순간이동해 보인다.

| 축 | 설계 |
|---|---|
| 재바인딩 | 현재 높이 그대로 재바인딩 (Y 복원 삭제) — 낙하 목표 Y(기존 스폰 높이 = 지면)는 서버가 해제 시점에 보관 |
| 하강 표현 | 노드에는 중력이 없다 — **서버가 `_spawnPosition.y`를 낙하 속도로 목표 Y까지 `MoveTowards`** (서버 Update, 견인 아님·하강 중에만). 클라이언트는 기존 스크롤 유도(`ApplyScrolledPosition`)가 낮아지는 스폰 Y를 그대로 따라가므로 **신규 동기화 채널이 없다** |
| 낙하 속도 | `_fallSpeed` 직렬화 필드 (제안 6 m/s — 프리팹 파일 수정 없이 스크립트 기본값. 컴포넌트 추가가 아니라 해시 리스크 없음) |
| 무변 | 견인·예측 고정·수납 경로 — 하강은 "재바인딩 이후"의 표현 축이라 그랩 파이프라인을 건드리지 않는다. 하강 중 재그랩은 허용(`IsAvailableForGrab` 무변) — 잡으면 견인이 위치를 덮어쓴다 |

## 4. 소규모 ② (A3) 열차 위 낙하 — 프레임 소속 축

**배경**: 인벤토리가 가득해 회수를 놓치면 대상이 도착 지점(플레이어 앞)에서 월드 프레임으로
재바인딩돼 **뒤로 흘러가며**, 다시 잡으려면 흘러가는 것을 쫓아야 한다. 노드는 스폰 재바인딩 =
월드 프레임 전용이라 "열차 위에 놓인다"는 상태가 없다.

**핵심 관찰**: 열차는 월드 좌표상 정지해 있고 월드가 스크롤한다 — "열차 프레임 소속"은
**스크롤 유도를 끄고 고정 위치에 머무는 것**이 전부다. 신규 이동 로직이 없다.

| 축 | 설계 |
|---|---|
| 상태 | `NetworkVariable<bool> _isDeckResting` 신규 — true면 `ApplyScrolledPosition` 생략, 재바인딩된 `_spawnPosition` 고정 표시 (컨베이어·견인 어느 쪽도 아닌 **휴지 상태**) |
| 진입 판정 | `ReleaseGrab`에서 낙하 지점이 **열차 발자국 위**(&#124;x&#124; ≤ 칸 폭/2 · Z가 어느 칸 위 · Y ≥ 갑판)면 갑판 휴지 + 낙하 목표 = 갑판 높이, 아니면 기존 월드 재바인딩 + 목표 = 지면. 발자국·칸 판정은 `TrainLayoutSettings` 기존 함수(`IsZOnCar` — 6차 즉사 존과 같은 뿌리) 재사용 |
| 판정 순수화 | 진입 판정을 순수 함수로 추출 (`ResourceDropMath.ResolveDropFrame` — Deck/World + 목표 Y 반환, EditMode) |
| 효과 범위 | **A3(인벤 가득)와 갑판 위 취소가 한 지점에서 함께 풀린다** — 인벤 가득 경로는 `HarpoonController` 도착 처리의 `Rejected` → `ServerReleaseTow` → `ReleaseGrab`이라 별도 분기가 필요 없다 (도착 지점 = 홀더 앞 = 열차 위) |
| 후방 회수 | 갑판 휴지 노드는 `GroundResourceSpawner`의 후방 회수(`GetMetersBehindSpawn`) 대상에서 제외 — 견인 중 제외(`IsClaimed`)와 같은 자리에 조건 추가 |
| 재그랩 | `IsAvailableForGrab`은 무변 (휴지는 towed가 아님 — 이미 그랩 가능). `TryClaimGrab` 확정 시 휴지 해제 → 이후 해제 시 재판정 (갑판 ↔ 지상 왕복이 자연 성립) |
| 풀 반환 | `OnDespawned`에서 휴지 상태 리셋 (기존 리셋 목록에 합류) |

- **엣지 (구현 중 판단)**: 이탈 칸 위에 놓인 노드 — 이탈 칸은 슬롯에서 뒤로 밀려나므로 노드가
  공중에 남을 수 있다. **최소안 = 재판정하지 않는다** (놓인 순간의 발자국 판정이 전부.
  이탈은 드문 사건이고 노드는 재그랩으로 회수 가능) — 문제가 되면 후속
