# 플레이어 확장 계획 — 애니메이션 표현 + 그랩/캐리 구속 콘텐츠

작성일: 2026-08-16 · 상태: **착수 전 결정 ①~④ 확정 (2026-08-16, 사용자) · 착수 대기**
(선행 조사: 플레이어 18종 + 몬스터 28종 스크립트 전수 · `Player.prefab` 실측 ·
집게 그랩 파이프라인 분석. 관련 스펙: [network-movement.md](../specs/player/network-movement.md) ·
[M8-1차-구현-계획.md](M8-1차-구현-계획.md) §2.6)

> **목표**: 플레이어에게 남은 두 개의 큰 공백을 닫는다.
> **A축 — 애니메이션·외형**: 원격 플레이어까지 포함해 이동·점프·사망이 애니메이션으로
> 읽힌다 (M8 1차 §2.6의 "순수 로컬" 방침을 **하이브리드로 갱신**한다).
> **B축 — Grabbed/Carried**: M1부터 골격만 있던 구속 상태 머신에 **실제 콘텐츠**를 얹는다 —
> 몬스터가 플레이어를 붙잡고, 동료가 구출하고, 실패하면 열차 밖으로 던져진다.
> 구현 중 하드코딩은 허용하되, **차수 마감 시점에는 §4의 SOLID·판정-표현 분리 기준을
> 전부 통과해야 닫힌다** (§5 마감 조건).

## 0. 범위

**A축 — 애니메이션·외형 표현** (M8 1차와 같은 브랜치 `feat/m8-art-pass`):

1. **`PlayerAnimationDriver` 신설** — Animator 파라미터(`Speed`/`Jump`/`Dead`/`Grabbed`)를
   구동하는 표현 전용 컴포넌트. 소유자는 실제 속도, 원격은 보간 위치 델타로 추정
2. **하이브리드 동기화** (결정 ④) — Speed 로컬 유도(대역폭 0) + 점프만 소형 RPC +
   사망은 기존 권위 이벤트 재사용
3. **순수 로직 분리** — `PlayerAnimationMath` (속도 추정·스무딩·파라미터 산출, EditMode 대상)
4. M8 1차 단계 5(SkinnedMeshRenderer + Animator 배선)와 **합류** — 이 계획이 그 단계의
   상세 설계다

**B축 — Grabbed/Carried 구속 콘텐츠** (M8 머지 후 별도 브랜치 `feat/player-grab`):

5. **그래버 몬스터 변종** (결정 ②-ⓐ) — `MonsterSettings_Grabber.asset` 데이터 append.
   프리팹·풀·NetworkPrefabs 등록 **0건 증가**
6. **보스 그랩 패턴** (결정 ②-ⓑ) — `BossSignaturePattern.Grab = 4` + switch case 1개 +
   `BossDefinition` 필드 묶음 (확립된 확장 방식)
7. **구속 파이프라인** — 텔레그래프 → 서버 그랩 확정 → `Grabbed`(struggle 가능) →
   `Carried`(운반, 구출만 가능) → 투척 or 해방. 위치 구동은 **앵커 수식 공유 방식** (§2.4)
8. **해제 3종** (결정 ③) — 아군 공격 구출 · 연타 struggle 자력 탈출 · 시간 초과 시 열차 밖 투척
9. **입력 게이트 정비** — 구속 중 무기 입력 차단(현재 뚫려 있음 — 조사 §5.2), 시점 회전은
   허용으로 세분화, F9 디버그 해제 불가 버그 수정
10. **순수 로직** — `GrabEscapeMath` (struggle 게이지·시간 초과·해방 판정, EditMode 대상)
11. **스펙 문서 동기화** — `network-movement.md`를 as-built로 갱신 (본 계획과 동시 진행)

**비범위** (의도적 제외):

- **struggle·피격·구속 전용 애니메이션** — 에셋 자체가 없다 (M8 판정 결정 E와 같은 사유).
  1차는 `Grabbed` bool로 자세 고정만 하고, 에셋 확보 시 파라미터만 추가한다
- **FP 팔 뷰모델** — M8 결정 ① ⓐ 이월 유지
- **원격 플레이어 떨림 버그 근본 해결** — 별건(M6 잔여 §2). 단 A축의 속도 추정 스무딩이
  애니메이션 층위에서는 떨림을 흡수하도록 설계한다 (§2.2)
- **관전 카메라** — 별건(M6 잔여 §3)
- **그래버 전용 외형 모델** — 기존 `Monster.prefab` 공유 + `_variantColor`/`_visualScale`로
  식별. 전용 모델은 아트 패스 후속

## 2. 설계

### 2.1 A축 — `PlayerAnimationDriver` (표현 전용)

M8 1차 §2.6이 확정한 것(Humanoid 41본 · 루트 모션 없음 · `Idle↔Walk↔Run` 1D 블렌드 +
`Jump` + 사망)은 그대로 두고, **파라미터를 누가 어떻게 구동하는가**를 이 계획이 확정한다.

| 구성요소 | 역할 | 계층 |
|---|---|---|
| `PlayerAnimationDriver` | Animator 파라미터 구동. 판정·상태 소유 없음 — **읽기 전용 표현** | MonoBehaviour (`Gameplay/Player`) |
| `PlayerAnimationMath` | 위치 델타 → 수평 속도 추정, 스무딩, 파라미터 산출 | 순수 static |
| Animator Controller | `Speed`(float) · `Jump`(trigger) · `Dead`(bool) · `Grabbed`(bool) | 에셋 |

- **소유자**: `CharacterController.velocity`의 수평 성분을 그대로 `Speed`에 쓴다. 추정 불요.
- **원격**: `OwnerNetworkTransform`이 보간한 위치의 프레임 델타로 속도를 추정한다.
  단 **월드 스크롤 성분을 빼고** 계산한다 — 지상에 서 있는 원격 플레이어는 스크롤로
  밀리고 있어, 빼지 않으면 제자리인데 걷는 애니가 재생된다 (`IWorldScrollService` 조회,
  기존 규약 재사용).
- **사망**: `PlayerDiedEvent`(권위)·부활 완료를 구독해 `Dead`를 토글한다. 신규 복제 없음.
- **구속**: `NetworkPlayerController.MovementState`(기존 `NetworkVariable`)를 읽어
  `Grabbed`를 토글한다. B축이 미착수여도 A축은 성립한다(파라미터만 선배치).
- `NetworkPlayerController`는 **무수정** — 드라이버가 공개 프로퍼티만 읽는다 (M8 §2.6 계약 유지).

### 2.2 하이브리드 동기화 (결정 ④)

| 파라미터 | 채널 | 대역폭 |
|---|---|---|
| `Speed` | 없음 — 각 피어 로컬 유도 | **0** |
| `Jump` | `NotifyJumpRpc` — 소유자 → 서버 → `SendTo.NotOwner` 중계 | 점프 1회당 소형 RPC 1발 (이벤트성 — 상시 부하 없음) |
| `Dead` | 기존 `NotifyDiedRpc` 재사용 | **0 (증분 없음)** |
| `Grabbed` | 기존 `_movementState` 재사용 | **0 (증분 없음)** |

- `NotifyJumpRpc`는 `PlayRemoteFireRpc`와 같은 **연출 전용 서버 중계** 규약이다.
  서버 재검증 불요(게임 상태 무변경) — 다만 홍수 방지로 서버에서 초당 상한(4회)만 건다.
- **떨림 흡수**: 원격 속도 추정은 지수 스무딩(반감기 ~0.15 s)을 거쳐 `Speed`에 쓴다.
  원격 떨림 버그(M6 잔여 §2)가 위치 층위에 남아 있어도, 애니메이션 층위에서는
  Walk↔Run 경계에 히스테리시스(±0.3 m/s)를 둬 파라미터가 진동하지 않게 한다 —
  이 두 수치가 `PlayerAnimationMath`의 EditMode 검증 대상이다.

### 2.3 B축 — 구속 파이프라인 (상태 흐름)

```
[그래버 서버 AI]                      [플레이어]
 추격 (기존 ServerSimulate)            Normal
   │ 사거리 진입 + 쿨다운 경과
   ▼
 텔레그래프 0.8s (색·자세 예고) ──────→ (피하면 그랩 불발 — 쿨다운만 소모)
   │ 종료 시점에 사거리 재판정 (서버)
   ▼
 ServerTryGrabPlayer() 확정 ─────────→ Grabbed  ← struggle 연타 / 아군 구출 가능
   │ · _grabbedPlayer 복제                │ 유지 피해 3/s
   │ · _movementState = Grabbed           │
   │ 5s 내 미탈출                         ▼
   ▼                                   Carried  ← 아군 구출만 가능
 후방 운반 3.5 m/s                        │ 4s 경과
   ▼                                      ▼
 투척 (측후방 포물선) ────────────────→ Normal 복귀 + 공중 → 기존 이탈 규칙(30/40m)
```

**해방 경로 (어느 단계든)**: ⓐ struggle 게이지 만충(Grabbed 한정) ⓑ 그래버에게 누적
피해 40 도달 ⓒ 그래버 사망·기절·디스폰·바퀴 즉사 존 진입(기존 `ServerKillByCrush` 경로) —
전부 서버가 `ServerReleasePlayer()` 한 곳으로 합류한다 (집게의 `ServerReleaseTow` 전례).
해방 시 `_movementState = Normal` + 플레이어는 그 자리에서 제어권 회복.

**네트워크 시퀀스** (권위 분담 — 네트워크 문서 §4.2 "구속형"의 첫 실구현):

| 단계 | 권위 | 채널 |
|---|---|---|
| 텔레그래프 시작 | 서버 확정 | 그래버 `NetworkVariable<byte> _attackPhase` (기존 보스 돌진 국면 복제와 동일 규약) |
| 그랩 확정 | 서버 — 사거리·생존·`IsAvailableForGrab` 재검증 | 그래버 `_grabbedPlayer`(ref) 복제 + 플레이어 `_movementState` 복제 |
| 구속 중 위치 | **전 피어 로컬 계산** (§2.4) | 신규 채널 **없음** |
| struggle 연타 | 소유자 입력 → `StruggleServerRpc` (초당 상한 8) → 서버 게이지 누적 | 게이지는 복제하지 않음 — 소유자 HUD는 로컬 연타 수로 근사 표시, 확정(탈출)만 서버가 통지 |
| 격상·투척·해방 | 서버 확정 | `_movementState` 전환 + 투척은 `ThrownOwnerRpc(velocity)` — 소유자가 로컬 포물선 적용 (기존 `BeginRespawnOwnerRpc` 임펄스형 전례) |

### 2.4 구속 중 위치 구동 — 앵커 수식 공유 (기술 확정 ⑤)

플레이어 트랜스폼은 소유자 권위(`OwnerNetworkTransform`)라 **서버가 위치를 써도 복제되지
않는다** — 현재 Grabbed로 바꾸면 "제자리 빙결"이 전부인 이유다. 집게 파지가 이미 푼 문제를
그대로 뒤집어 이식한다:

- 그래버가 `NetworkVariable<NetworkObjectReference> _grabbedPlayer`를 복제하면,
  **모든 피어**(소유자 포함)가 `LateUpdate`에서 같은 앵커 수식
  (그래버 position + forward·offset)을 로컬 계산해 플레이어 트랜스폼에 대입한다.
- **소유자**는 대입 전에 `CharacterController.enabled = false`(구속 진입 시 1회) —
  기존 `TeleportTo`가 쓰는 것과 같은 충돌 회피 규약. 해방 시 재활성.
- 소유자가 대입한 위치는 `OwnerNetworkTransform`으로 자연 복제되지만, 원격 피어는
  **로컬 부착이 우선**이므로 화면이 갈리지 않는다 — `MonsterGrabTarget.LateUpdate`가
  파지 표시에 쓰는 검증된 구조 그대로다. 실행 순서 고정(`DefaultExecutionOrder`)도 동일하게 건다.
- 서버 판정(운반 거리·투척 지점)도 **같은 수식**을 호출한다 — "판정과 화면이 같은 수식을
  공유"가 이 방식의 핵심이다.

### 2.5 그래버 변종 + 보스 패턴 (데이터)

- **`MonsterSettings` append** — `[Header("그랩 공격")]`: `_canGrabPlayer`(bool, 기본 false) ·
  `_grabCooldownSeconds` · `_grabRange` · `_grabTelegraphSeconds` · `_dragSpeed` ·
  `_grabbedDamagePerSecond` · `_carriedAfterSeconds` · `_throwAfterSeconds` ·
  `_escapeStruggleCount` · `_rescueDamageThreshold`. 기존 변종 에셋 5종은 기본값이라
  **회귀 없음** (`_stunDurationSeconds = 0` 전례와 같은 "데이터로 끌 수 있는 축").
- **`MonsterVariantCatalog`에 `MonsterSettings_Grabber.asset` append** (기존 인덱스 뒤 —
  배열 순서 규약 준수). 프리팹·풀·NetworkPrefabs **0건 증가**.
- **그랩 실행 로직은 `MonsterGrabAttack` 컴포넌트로 분리**해 `Monster.prefab`에 병렬
  부착한다 — `MonsterAgent`(이동·추격·기본 공격)에 그랩까지 넣으면 SRP 위반("이동 그리고
  그랩"). `MonsterAgent`는 `_canGrabPlayer` 변종일 때 공격 판단을 `MonsterGrabAttack`에
  위임하는 조회면 하나만 얻는다.
- **보스** — `BossSignaturePattern.Grab = 4` + `BossAgent.ServerStepSignature` case 1개 +
  `BossDefinition` `[Header("고유 패턴 — 그랩")]` 필드 묶음. 그랩 확정·유지·해방은
  `MonsterGrabAttack`과 **같은 서버 API**(`IPlayerGrabber` 경유)를 호출한다 — 파이프라인
  중복 구현 금지.

### 2.6 플레이어 측 — `PlayerGrabbable` (신설)

`NetworkPlayerController`에 그랩 수신까지 넣지 않는다 (이미 625줄 — SRP). 신설
`PlayerGrabbable`(NetworkBehaviour)이 담당:

- 서버 API: `ServerTryBeginGrab(grabber)` / `ServerRelease(reason)` / `ServerEscalateCarried()` /
  `ServerThrow()` — 상태 전환은 전부 여기서 `NetworkPlayerController`의 서버 전용
  세터(`ServerSetMovementState`, 신설 — 디버그 RPC가 쓰던 대입을 공식화)를 호출.
- `IsAvailableForGrab` — 사망·부활 대기·이미 구속 중이면 거부 (집게 `TryClaimGrab`의
  점유 모델 이식 — 그래버 둘이 동시에 잡는 경합을 서버 한 곳에서 해결).
- 유지 피해는 `PlayerHealth.ApplyEnvironmentalDamage` 경로(장비 감산 없음 — 물린 상태).
- struggle: 소유자 `Update`에서 연타 키(Space) 카운트 → `StruggleServerRpc` →
  `GrabEscapeMath.Step`으로 게이지 누적·감쇠·판정.

### 2.7 입력·카메라 게이트 정비

| 항목 | 현재 | 변경 |
|---|---|---|
| 이동·점프 | 게이트됨 | 유지 |
| **시점 회전** | **완전 정지** | **허용으로 세분화** — 붙잡혀도 고개는 돌릴 수 있어야 구출 상황을 볼 수 있다. `UpdateLook`을 게이트 앞으로 이동 |
| **무기 입력** | **뚫려 있음** — 붙잡힌 채 사격 가능 | `HotbarController`의 기존 UI 게이트 집계에 `MovementState != Normal` 합류 (기술 확정 ⑦ — 무기 5종 무수정) |
| UI 열기 (I/제작/창고) | 뚫려 있음 | 같은 지점에서 차단 (Esc 세션 메뉴만 허용) |

### 2.8 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 구속 중 그래버 디스폰 (새벽 회수·후미 이탈·풀 반환) | `OnDespawned`/회수 경로에서 `ServerRelease` 보장 — 집게 `ServerUpdateTow`의 "대상 디스폰 감지 → ForceRelease" 전례. **누락하면 영구 구속**이므로 EditMode+플레이 양쪽 검증 |

| 그래버가 바퀴 즉사 존에 들어감 | 그래버 즉사(기존 `ServerCheckWheelKillZone`) → 해방 경로 ⓒ 합류 |

| 구속 중 플레이어가 집게 발사 중이었다면 | 무기 게이트 합류 시 `HarpoonController.TryCancel` 호출 — 견인 중이면 릴 해제 |

### 3.1 대역폭 (30 Hz 틱 기준 — 상시 부하 증분)

## 4. 아키텍처 마감 기준 (SOLID · 판정-표현 분리)

구현 중 하드코딩은 허용하되(§5), **차수를 닫으려면 아래를 전부 통과해야 한다.**

| 원칙 | 적용 | 검사 방법 |
|---|---|---|
| **SRP** | 이동(`NetworkPlayerController`) / 그랩 수신(`PlayerGrabbable`) / 애니 표현(`PlayerAnimationDriver`) / 그랩 공격(`MonsterGrabAttack`)이 각각 한 파일. 기존 컨트롤러에 "그리고"가 늘지 않았는가 | 리뷰 체크리스트 |
| **OCP** | 그랩은 `_canGrabPlayer` 데이터로 켜고 끈다 — 변종 추가에 코드 수정 0. 보스 패턴은 확립된 enum+case 확장. 무기 게이트는 `HotbarController` 1곳 합류로 무기 5종 무수정 | 신규 변종 에셋만으로 그래버 하나 더 만들어본다 |
| **LSP** | `IPlayerGrabber` 구현 2종(웨이브·보스)이 같은 해방 계약을 지킨다 — 어느 쪽이든 `ServerRelease` 한 곳으로 합류 | EditMode 계약 테스트 |
| **ISP** | `IPlayerGrabber`(그랩 주체 계약)와 `IGrabbable`(집게 피격 계약)을 합치지 않는다 — 방향이 반대인 별개 역할 | — |
| **DIP** | 보스·몬스터가 `PlayerGrabbable` 구체 타입이 아니라 인터페이스 경유. 애니 드라이버는 스크롤 속도를 `IWorldScrollService`로만 조회 | 어셈블리 의존 방향 확인 |
| **판정-표현 분리 (MVP)** | 서버 판정(`GrabEscapeMath`·앵커 수식)과 화면 표현(애니·HUD 게이지)이 분리. HUD는 상태를 소유하지 않고 이벤트·읽기 전용 조회만 (UI 계층 규약) | `Game.UI`에서 상태 변경 호출 0건 grep |
| **권위 이벤트 규약** | `PlayerGrabbedEvent`(권위 — 서버 확정 후) / struggle 게이지 표시(로컬 표현)를 XML 주석에 명시 | 아키텍처 규칙 §3 |
| **순수 로직 조기 분리** | `PlayerAnimationMath`·`GrabEscapeMath`는 Unity API 무의존 — EditMode에서 전 경계값 검증 | 테스트 존재 여부 |
