> **6차 목표**: **"몬스터를 낚아채면 놓을 때까지 집게에 매달려 있고, 든 채로 이동해
> 아군 앞이나 열차 바퀴에 넘겨 처치하는" 루프가 종단으로 성립**한다 — 처형 배율이 아니라
> **운반**이 집게의 가치가 된다. 놓인 몬스터는 잠깐 기절했다가 복귀한다 (처형 창 아님).

> (5차 계획 개선 7번이 예고한 그대로 — 집게가 계속 붙잡는가 / 대상이 기절 타이머를 소유하는가).

## 1. 선행 — 처형 축 제거 (설계 반전)

**배경**: 5차 검증 E 구역에서 사용자가 도착 이후 그림을 뒤집었다 — "그로기 상태에서 처형하는 것이
아니라, **끌고 온 상태에서 들고 이동**하고, 무기를 교체해 죽이거나 팀원이 죽여주는 것".
착수 전 결정(2026-08-09)으로 **파지 전용 + 그로기는 스턴(잠깐 기절) + 처형 배율 제거**가 확정됐다.

| 제거 | 근거 |
|---|---|
| `MonsterSettings._stunnedDamageMultiplier` (필드 + 4종 에셋 값) | 처형 개념 자체가 사라진다 — "배율 1로 끄기"가 아니라 축을 지운다 (죽은 조정축을 남기지 않는다) |
| `MonsterHealth`의 배율 적용 + `IMonsterStun` 조회 | 체력이 기절을 알아야 할 이유가 없어진다. `IMonsterStun` 인터페이스는 유일 소비자가 사라지므로 함께 제거 (기절 상태는 `MonsterGrabTarget` 내부 소유로 남는다) |
| `MonsterDamageMath` + `MonsterDamageMathTests` | 존재 이유가 배율이었다 |
| `MonsterDiedEvent.WasExecuted` + CoreLoopHud "처형!" 배너 | 처형 이벤트 표면 제거 — 이벤트는 5차 이전 시그니처(killerClientId 단독)로 복귀 |

**유지·조정**: `_stunDurationSeconds`는 남는다 — 의미가 "처형 창"에서 **"놓였을 때 잠깐 기절"**
(추격 재개 전의 이탈 틈)로 바뀌므로 기본값을 5 → **2.5초**로 내린다 (에셋).

> ⚠ 5차 검증 **F 구역(처형 7건)·K10·K11의 통과 기록은 이 반전으로 역사 기록**이 된다 —
> 6차 검증 문서에 "처형 부재 확인"(배너·즉사 없음)을 역방향 항목으로 넣는다.

## 2. 파지 상태 (들고 다니기)

**핵심**: 도착해도 집게가 놓지 않는다. 견인의 연장이므로 M1 파이프라인의 권위 구조
(그랩 확정·견인 = 호스트, 30 Hz 동기화, 몬스터 무예측)가 그대로 성립한다.

| 축 | 설계 |
|---|---|
| 계약 변경 | `IGrabbable.TryCompleteGrab` 반환을 `bool` → **`GrabCompletionResult` enum** (`Rejected` = 해제·낙하 / `Consumed` = 수납·소멸 / `Held` = 파지 유지). `ResourceNode` = Consumed(수납 실패 시 Rejected), `HandrailAnchor` = Rejected(도착 판정 자체를 안 탄다), `MonsterGrabTarget` = **Held** |
| 상태 머신 | `HarpoonState.Holding` 신규 — Reeling --도착(Held)--> Holding --놓기--> Cooldown. Holding 중 좌클릭(재발사)은 Ready가 아니므로 자연 차단 |
| 파지 앵커 | 서버가 매 프레임 `플레이어 위치 + 전방 × _holdDistance + 위 × _holdHeight`를 `UpdateTowPosition`으로 대입 — 견인과 같은 경로·같은 30 Hz 채널(`_towSyncHz`), 신규 동기화 없음 |
| 로프·훅 | 도착 시 훅을 회수하지 않고 부착 유지 — 파지 중 로프가 계속 보인다 (기존 Attached 표현 재사용, 신규 연출 없음) |
| 놓기 ① 우클릭 | `TryCancel`을 Holding에서도 허용 — 기존 취소 RPC 경로 재사용 |
| 놓기 ② 무기 교체 | `InputEnabled`가 false로 바뀌는 프레임에 소유자가 자동으로 취소 요청 — "무기를 바꾸면 놓는다"가 핫바 게이트에서 공짜로 성립 |
| 놓기 ③ 대상 사망·디스폰 | 파지 중 팀원 사격으로 죽으면 기존 `ServerUpdateTow`의 스폰 검사 → `ForceRelease` 경로 그대로 (5차 E12와 동일, 신규 처리 없음) |
| 놓이면 기절 | `MonsterGrabTarget.ReleaseGrab`이 **파지에서 놓인 경우에만** 기절 진입(`_stunDurationSeconds`). 견인 중(도착 전) 취소는 5차 E13 그대로 즉시 복귀 — 기절 없음 |
| 기절 규칙 | 기절 중 재그랩 불가(5차 E8 유지) · 이동·공격 정지 · 색·자세 표현 유지. 기절이 끝나면 추격 재개 |
| 처치 | 파지·기절 중 피해는 **전부 일반 데미지** — 팀원이 든 것을 쏘거나, 본인이 놓고(기절 2.5초) 무기를 들어 싸운다. 배율 없음 |

- 게스트 홀더도 성립한다 — 홀더 위치는 `OwnerNetworkTransform`으로 서버에 이미 있고,
  파지 앵커 계산·대입은 전부 서버다 (권위 구조 불변)
- 자원(`Consumed`)의 기존 흐름(수납·소멸·`TargetArrived`)은 한 줄도 바뀌지 않는다 —
  enum 도입은 몬스터 분기를 **대상 쪽에** 두기 위한 것 (5차 리팩터의 OCP 계약 연장)

## 3. 열차 하부 즉사 존

**결정 (2026-08-09)**: 5차 비범위였으나 파지가 들어오며 "갑판 위에서 아래로 끌 때만 성립"이라는
경로 제약이 사라졌다 — **지상에서 든 채 열차 옆으로 걸어가 바퀴에 들이미는** 경로가 주 동선이다.

| 축 | 설계 |
|---|---|
| 대상 제한 | **견인·파지·기절 상태의 몬스터만** 즉사한다. 자유 몬스터는 제외 — 지상 몬스터가 추격 중 열차 밑을 스치기만 해도 죽으면 밤 웨이브가 자멸한다 (존이 밸런스를 삼키지 않게 하는 안전선) |
| 존 판정 | 순수 함수 (EditMode) — 열차 발자국 안(&#124;x&#124; ≤ 칸 폭/2, RearZ‥FrontZ) **AND** y ≤ `_wheelKillHeight`. `TrainLayoutSettings`에 높이 필드 추가 (**0 = 존 비활성** — 에셋으로 끌 수 있다) |
| 판정 주체 | `MonsterGrabTarget` 서버 Update — 자기 상태(견인·파지·기절)를 이미 알고 있는 곳이라 조회가 없다 |
| 처치 처리 | `MonsterHealth.ApplyDamage(전체 체력, 그래버 clientId)` — 기존 사망 확정·킬 카운트·이벤트 경로 재사용. **처치 귀속 = 마지막 그래버** (바퀴에 넣은 사람의 킬) |
| 연출 | 최소 (기존 사망 처리 그대로) — 분쇄 연출은 2차 이월 연출 9건과 함께 후속 |

- 파지 중 존 접촉 = 즉시 (매달아 갈아 넣기), 놓인 기절 몬스터가 존 안 = 즉시
- 제안 수치: `_wheelKillHeight = 1.2 m` (지상 홀더의 파지 앵커 높이가 걸리는 선 — 플레이 검증에서 조정)

## 4. 소규모 ① 제작 창 발견성

5차 1차 검증이 통째로 막힌 원인 — 목록이 15줄인데 스크롤·분류가 없고 패널 높이(1040 px)가
화면을 넘쳤다. 레시피가 더 늘기 전에 처리한다.

- **스크롤 뷰** — 패널 높이 상한 = 화면 높이의 70 %, 넘치면 스크롤
- **분류 머리글** — 그룹 순서: **집게 강화 → 탄약 → 무기·장비 → 요리**. 분류는 레시피에서
  **파생**한다 (신규 데이터 없음): `IsHarpoonTierOutput` → 집게 강화 / `Station == Campfire` → 요리 /
  `IsItemOutput` → 무기·장비 / 그 외 → 탄약. 승급 줄이 최상단 그룹이라 발견성이 먼저 풀린다
- 재료 부족 줄은 회색 버튼이 "없는 것"처럼 보이지 않게 표기 보강 (버튼 라벨 "재료 부족")
- 인덱스 = RPC 식별자 규약과 무관 — **표시 순서만** 그룹화하고 요청은 기존 인덱스를 그대로 쓴다

## 5. 소규모 ② QA 수단 2종

3~5차 연속 이월의 공통 원인 = "상황을 사람이 만들 수 없다". 창고 경합(5차 H10)이 QA 키 하나로
풀린 전례를 따른다. 기존 키 규약(호스트 확정·콘솔 로그) 유지.

| 키 | 동작 | 푸는 항목 |
|---|---|---|
| **숫자패드 0** | 요청자 플레이어에게 **고정 피해 20** (물리 경로 — 장비 감산 적용) | H7 (가죽 옷 15 % 실측: 맨몸 20 vs 착용 17) — 3·4·5차 연속 이월 |
| **숫자패드 −** | **동시 그랩** — 호스트가 최근접 그랩 가능 자원 노드를 골라 전 피어에 브로드캐스트, 각 피어가 수신 프레임에 자기 집게로 그랩 요청 발행 | I1·I2 (동시 경합 — 한쪽 승인 + 한쪽 "다른 사람이 잡고 있다") |

- 동시 그랩도 창고 경합의 교훈을 적용한다 — **전제(대상 존재)를 시작 단계에서 검사**하고,
  결과(승인/거부 각 1건)를 콘솔에 찍어 무효 통과가 나오지 않게 한다

## 6. 소규모 ③ 스튜 즉시 체온 상한의 국면화

5차 G3 요청 — "사막의 낮에서는 스튜 상한이 좀 더 높으면 좋겠다". 현재 상한은 38 ℃ 단일 값.

- `TemperatureMath.ResolveWarmthCeiling(ambient, curve)` 순수 함수 (EditMode) —
  환경이 쾌적 상한을 넘는 **더위 국면이면 `_instantWarmthCeilingHot`**, 아니면 기존 38 ℃
- 더위 국면 상한 초기값 **39 ℃** 제안 = 고온 **피해** 임계 직전 (경고 구간까지는 허용하되
  음식으로 피해 구간에 스스로 들어가지는 않는다). 더 열고 싶으면 에셋으로 40+
- "끌어내리지 않는다"(5차 G4) 규칙은 그대로 유지
