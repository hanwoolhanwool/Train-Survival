# M5 잔여 작업 정리 — 7차 이후 편성 대상 7건

작성일: 2026-08-10 (갱신 2026-08-11) · 대상: `feat/m5-combat-survival` · 상태:
**2·3번 = 7차 완료** (2026-08-11, 2차 검증 통과 — [M5-7차-구현-계획.md](M5-7차-구현-계획.md)) ·
**4~8번 = 8차 편성** (2026-08-11, [M5-8차-구현-계획.md](M5-8차-구현-계획.md)) ·
**1번(터렛)만 편성 대기** (사용자 결정으로 8차 제외 — 9차 이후). 검증 잔여(7차 R5~R9·D6·
F2~F5 + 6차 이월 26건)는 이 문서의 범위 밖 — 8차 검증 문서에 편입한다

> M5 1~6차가 끝난 시점에서 **하기로 결정된 채 남아 있는 구현 작업**을 한 곳에 모은다
> (사용자 선정 2026-08-10). 검증 이월(6차 잔여 26건 등)은 이 문서의 범위가 아니다 —
> 확인 작업은 다음 검증 문서에 편입한다. 차수를 새로 열 때 이 목록에서 골라 계획을 세운다.

## 1. 터렛/거치 기관총 (M5 범위 명시 — 유일한 미구현 범위) — 8차 제외, 9차 이후

- **출처**: M5 범위 문장 "무기 3축 확장(샷건·볼트액션·근접·**터렛/거치 기관총**)".
  2차(전투)부터 "소유권 모델이 달라 검증 차수에서 별도 판단"으로 계속 보류됐다.
- **왜 미뤄졌나**: 지금까지의 무기는 전부 **플레이어 소유**(핫바 슬롯·소유자 입력·소유자 선반영)다.
  거치 무기는 **열차(씬) 소유 + 조작권 점유**라 소유권 모델이 다르다 — 좌석 점유(1인 확정),
  점유 중 이동·무기 입력 잠금, 탄약 공급원(개인 인벤 vs 장전식) 등이 전부 새 결정이다.
- **구현 방향 메모**: 고정 NetworkObject(건축물 종류화 `StructureKind` 확장 후보) + 점유는
  호스트 확정(창고 상호작용 `LocalInteraction` 규약 재사용). 사격 파이프라인은 `GunController`
  일반화가 이미 세팅 에셋 주도라 재사용 여지가 크다.
- **규모**: 중 — 별도 차수 급. 착수 전 결정 필요(점유 UX·탄약 경제·건축물 여부).

## 2. ~~온도 축 — 보온 장비 기본 체온 상향 + 지역 무관 온도~~ → **7차 완료** (2026-08-11)

7차에서 구현·검증 완료 — 검증 중 확장: 쾌적대 하향 회복 분리(0.1 ℃/s) ·
난방기 국면별 목표 수렴 재설계(밤 36 / 낮 37 ℃). 이하 원문은 기록으로 유지.

- **출처**: 5차 검증 사용자 원문 요청 2건 (개선 5·6번). 6차 착수 전 결정(2026-08-09)으로
  "**7차 이후, 별도 차수**" 확정 — 지역 에셋·평형 수식이 함께 바뀌는 중간 규모라 분리가 안전.
- **내용**:
  1. **보온 장비 기본 체온 상향** — 착용 시 평상 체온이 36.5 ℃보다 높게 유지되고, 온실 돔에
     들어가도 그 높아진 값까지만 내려간다 (= `TemperatureCurve.NormalBody`를 장비가 밀어 올리는 축.
     현재 장비는 단열 계수(환경 완화)만 있다)
  2. **지역 무관 온도** — 지금은 사막 외 지역에서 온도 압박이 사실상 없다. 전 지역에 온도를 두어
     옷·난방의 가치가 상시 성립하게 (3차 "온도 영향 일반화" 이월과 같은 축)
- **규모**: 중 — `TemperatureMath` 평형 수식 + `RegionDefinition` 전 지역 온도 등재 + 장비 카탈로그
  축 추가. EditMode 검증이 잘 듣는 영역.

## 3. ~~낙하 위치 2건 — 열차 위 낙하 · 취소 순간이동 해소~~ → **7차 완료** (2026-08-11)

7차에서 구현·검증 완료 — 검증 중 확장: 하강 로컬 재생(떨림 해소) · 이탈 칸 추종 ·
소실 칸 위 휴지 노드 회수. 이하 원문은 기록으로 유지.

- **출처**: 5차 검증 A3·A6 사용자 요청 (개선 2번). 6차 미편입 결정으로 이월 유지.
- **내용**:
  1. **(A3)** 인벤토리가 가득해 회수를 놓칠 때, 대상이 월드 프레임으로 복귀해 뒤로 흘러가지 않고
     **열차 위(플레이어 발밑)에 떨어지면** 좋겠다 — 자원 노드에 "열차 프레임 소속" 상태가 없어
     새 축이 필요하다 (지금 노드는 스폰 재바인딩 = 월드 프레임 전용)
  2. **(A6)** 우클릭 취소 시 대상이 **순간이동하듯** 떨어진다 — `ResourceNode.ReleaseGrab`이 낙하
     지점 Y를 **원래 스폰 높이로 되돌리기** 때문. 현재 높이에서 자연스럽게 떨어지게 바꾼다
     (낙하 표현 축 — 노드에는 중력이 없어 간단한 하강 보간이 필요)
- **규모**: 소~중 — ②는 국소 수정, ①은 프레임 소속 축 추가.

## 4. 전투 연출 — 2차 이월 9건 + 즉사 존 분쇄 연출 → **8차 편성** (2026-08-11)

- **출처**: 2차 검증 이월 ① — "전투 연출 부재로 육안 검증 불가 9건"(C3·C4·C5·C7·D4·E2·E4·E6·G4).
  6차에서 **열차 하부 즉사 존 분쇄 연출**이 합류(현재는 기존 사망 처리 그대로).
- **내용**: 탄착 이펙트 · 펠릿별 트레이서(현재 최근접 1줄·0.05 s) · 근접 스윙 모션 ·
  원격 발사 연출 개선 · **몬스터 변종 시각 구분**(M4 검증 TBD ②와 같은 뿌리) · 바퀴 분쇄 연출.
- **완료 효과**: 2차 미검 9건이 **일괄 재검증 가능**해진다 — 판정·권위 경로는 이미 실증됐고
  관측 수단만 없던 항목들이다.
- **규모**: 중 — 판정 로직 무변, 표현 계층만. 항목 수가 많아 한 차수의 절반쯤.

## 5. 버리기 UX 재설계 → **8차 편성** (2026-08-11)

- **출처**: 3차부터 이월. 현재 구현 = I 창 **패널 밖 드롭 = 슬롯 전량** 버리기(열차 측면 노드 산포).
- **내용**: 수량 지정(부분 버리기)·드롭 위치 예측 표시 등 조작감 재설계 — 구체 방향은 착수 전
  결정. 무기·장비 버리기 불가 규약(창고 보관이 처분을 흡수)은 유지 전제.
- **규모**: 소 — UI 조작 계층 중심, 확정 경로(`IResourceDropper`·원자 차감)는 재사용.

## 6. 창고 파괴 시 내용물 보따리 낙하 (재설계 2026-08-10) → **8차 편성 — 코어** (2026-08-11)

- **출처**: 3차부터 이월. 현재 = 창고 건축물·칸 파괴 시 내용물 **명시 소실**.
  당초 방향("자원 노드로 바닥에 산포")을 사용자 결정(2026-08-10)으로 **단일 보따리**로 재설계 —
  파괴된 창고의 슬롯 전체가 보따리 하나에 담겨 나온다. 무기·장비도 슬롯에 담기므로
  (버리기 불가 규약 — 창고 보관이 처분을 흡수) 자원 노드 산포로는 표현할 수 없던 축이다.
- **결정 사항** (2026-08-10):
  1. **회수 UX** — **E 상호작용 = 창고 창 UI 재사용**으로 옮겨 담기 + **집게 그랩 = 운반 전용**.
     그랩 도착은 수납이 아니라 발밑 낙하 (무기·장비가 들어 있어 자동 수납이 성립하지 않는다)
  2. **칸 파괴 시**(갑판 자체 소멸) — 그 자리 지상으로 **천천히 날아가는(느린 포물선) 연출**과
     함께 낙하 → 월드 프레임 소속. 집게로 건져 올리는 짧은 기회가 생기고, 놓치면 뒤로 흘러가
     후방 회수로 소실된다 (기존 집게 루프·후방 회수 규약 재사용)
- **구현 방향 메모**:
  - 보따리 = 풀링 NetworkObject 프리팹 + `NetworkList<NetworkSlot>` 10칸 — 창고와 **같은 슬롯
    표현**이라 E 창은 기존 창고 창(`StorageLogic.TryTransfer`)에 컨테이너만 보따리로 연결한다
  - `IGrabbable`(Reel) 구현하되 `TryCompleteGrab`은 항상 Rejected(운반 전용) — 도착·해제 낙하가
    **7차 A3 갑판 휴지·A6 하강 축을 그대로 탄다** (갑판 위 = 휴지, 지상 = 월드 재바인딩).
    7차 이후 착수가 순서상 자연스러운 이유
  - 생성 훅 = `TrainState.ServerClearStorageIfPresent`의 확정 지점 3곳 중 2곳: **건축물 파괴**
    (칸 생존) = 그 칸 갑판 위 휴지 스폰 / **칸 파괴** = 지상 투척 스폰(느린 포물선 — 서버 구동
    보간, A6 하강의 연장). **슬롯 재건 지점은 소실 유지** — 파괴 시점에 이미 나왔어야 하는
    안전망이라 보따리를 내지 않는다
  - 비면 자동 despawn. 신규 네트워크 프리팹 1종 — 풀링 등록 규약(NetworkPrefabs 중복 등록 금지·
    AutoObjectParentSync 해제) 준수
- **착수 전 결정 필요**: 투척 연출 중 그랩 허용 여부 · 보따리 위 보따리(중첩 파괴) 병합 여부 ·
  보따리 자체 내구도(공격에 파괴되는가) 여부.
- **규모**: 중 — 프리팹·UI 컨테이너 연결·투척 연출이 더해져 당초 "소"에서 상향.
  **선행 조건 충족 (2026-08-11)** — 7차 A3 갑판 휴지·A6 하강·이탈 추종·소실 회수 축이 전부
  구현·검증돼 보따리가 설 기반이 완성됐다. 즉시 착수 가능.

## 7. 몬스터 갑판 장애물 회피 → **8차 편성** (2026-08-11)

- **출처**: 3차부터 이월. 갑판 위 몬스터 이동이 **직선 추격**이라 건축물(돔·난방기 등) 사이에
  끼거나 몸통에 막힌 채 제자리걸음한다.
- **내용**: 지상 회피(`ProbeObstacle` — 전방 레이 + 법선 회피)를 갑판 경로
  (`MonsterSteering.ComputeDeckVelocity`)에도 적용하는 것이 최소안. 건축물 배치가 데이터라
  웨이포인트 그래프까지는 과하다는 기존 판단(M2) 유지.
- **규모**: 소 — 조향 순수 함수 확장 + EditMode.

## 8. 이탈칸 그랩 힘 게스트 표시 조사 (7차 2차 검증 발견 — 버그 5) → **8차 편성** (2026-08-11)

- **출처**: 7차 2차 검증 (2026-08-11). 이탈 칸을 집게로 잡을 때 **끌려오는 세기가 클라이언트
  화면에서 다르게 보인다**.
- **분석 완료 사항**: 저항은 서버 단일 계산(인원 × 견인력)이라 누가 잡아도 같다 — 갈리는 것은
  관측 경로 (호스트 = 권위 원값 / 게스트 = `ClientSmoothEjectionDisplay` 재시뮬 표시).
  스크롤 속도는 복제 값이라 후보에서 제외. 남은 후보: ① 저항 인원 복제 지연 동안 표시 속도가
  역방향으로 적분돼 드리프트 ② 드리프트 보정(저속 지수 감쇠)이 느려 고무줄 현상.
- **다음 단계**: 검증 R9(호스트/게스트 각각 잡고 화면별 세기 비교)로 조합을 특정한 뒤 수정.
- **규모**: 소~중 (원인 특정에 따라).
