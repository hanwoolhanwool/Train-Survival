## 1. 망치 조준 라벨 — 자원 부족 안내가 안 뜨는 버그

- **증상**: 자원이 부족할 때 돔 설치는 안 되지만(정상), "자원 부족" 안내가 화면에 뜨지 않는다.
  겨눈 칸이 손상돼 있으면 수리 안내가 설치·부족 안내를 가린다.
- **구현할 내역**:
  - 수리 안내와 설치(또는 자원 부족) 안내를 동시에 표시한다.
  - 자원 부족 안내는 붉은색으로 강조한다.
- **검증**: 자원 부족 상태에서 만피 칸·손상 칸을 각각 겨눠 부족 안내가 두 경우 모두 뜨는지 확인.

## 2. 연료 소모율 HUD 표시 (칸 증설 트레이드오프 가시화)

- **배경**: 현재 HUD는 연료 잔량만 보여줘, 칸 수에 따른 소모 변화(증설 트레이드오프)를 체감할 수 없다.
- **구현할 내역**:
  - HUD 연료 라인에 초당 소모율을 함께 표시한다 — 예: `연료: 54 / 100  (-0.80/s)`.
  - 칸 증설·이탈 시 표시 소모율이 즉시 갱신되며, 호스트·클라이언트 모두 동일한 값이 보여야 한다.
- **검증**: 증설/이탈 직후 표시 소모율이 호스트·클라 동일하게 바뀌는지 확인.

## 3. Esc 세션 메뉴·세션 종료 복귀 (클라이언트 Main 복귀)

- **배경**: 현재 세션을 나가는 수단이 없고, 접속이 끊겨도(호스트 이탈 포함) Game 씬에 방치되며 복귀 UI가 없다.
- **구현할 내역**:
  - 세션 활성 중 **Esc로 세션 메뉴 토글** — "세션 나가기(메인 화면으로)" / "계속하기" 버튼.
  - 세션 종료·끊김 감지 시 **자동으로 중앙 오버레이** "세션이 종료되었습니다 → 메인 화면으로" 표시.
  - 나가기를 누르면 세션을 종료하고 Main 씬으로 복귀한다.
  - 메뉴가 열린 동안 시점 회전을 멈추고 커서를 해제하며, 무기·상호작용 입력을 차단한다 (I 인벤토리 창과 동일한 동작).
  - 호스트가 나가면 세션 전체가 종료되고, 남은 클라이언트에는 종료 오버레이가 뜬다.
- **검증**: ① 클라 Esc → 나가기 → Main에서 재접속 ② 호스트 종료 시 클라에 오버레이 자동 표시
  ③ 메뉴 열림 중 좌클릭이 무기 발사로 새지 않는지.

## 4. 이탈 칸 위에서 지상 자원이 떨려 보이는 버그

- **증상**: 클라이언트가 뒤로 밀려가는 이탈 칸에 탑승하면 지상 자원·지형이 미세하게 떨려 보인다.
  (원인: 네트워크 복제 주기(30 Hz)로 계단식으로 움직이는 칸/카메라 vs 매 프레임 연속 이동하는 월드의 상대 변위 진동)
- **구현할 내역**:
  - 클라이언트에서 이탈 칸의 표시 위치를 매 프레임 부드럽게 보간해, 탑승 시점에서 월드가 떨리지 않게 한다.
  - 손잡이·건축물 등 칸에 붙은 요소도 함께 부드럽게 움직여야 한다. 서버의 판정(권위 값)은 바꾸지 않는다.
- **검증**: 클라이언트로 이탈 칸에 탑승해 지상 자원·지형이 부드럽게 흐르는지, 손잡이·돔이 칸과 어긋나지 않는지 확인.

## 5. 손잡이 회수 모션 부자연 (열차로 되돌아오는 움직임) — TBD

- **상태**: **TBD** (2026-07-31 결정) — 당장 적용하지 않는다. 재개 시 아래 내역대로 진행하고,
  손잡이-이탈저항 스펙 §4 수식 갱신을 함께 한다.
- **추가 관찰 (2026-08-01 2인 검증)**: 마지막 플레이어가 손잡이를 놓는 순간 이탈 칸이 즉시 최고 후퇴
  속력으로 밀린다 — 같은 원인(저항이 순간 해제되고, 잡힌 동안에도 밀림 속도가 목표에 머무름) 계열로,
  재개 시 함께 해소한다.
- **증상**: 집게로 손잡이를 잡는 순간 이탈 칸의 이동 방향이 뚝 끊기듯 반전된다. (저항이 순간 적용되어 속도가 점프)
- **구현할 내역**:
  - 잡기/놓기 순간 속도가 점프하지 않도록, 이탈 칸 속도가 목표 속도(밀림−저항)로 **가속도 램프**를 따라 수렴하게 한다.
  - 분리 직후 관성(0→목표)과 회수 반전(감속→정지→회수)이 같은 기울기로 부드럽게 이어진다.
- **검증**: EditMode 테스트(속도 점프 없음·목표 수렴) + 2인 손잡이 잡기/놓기 반복 시 모션이 이어지는지 확인.
- **비고**: 손잡이-이탈저항 스펙 §4의 수식(순간 저항 적용)과 달라지므로, 적용 시 스펙 문서 갱신도 필요하다.

### 건설 포트 → 망치 통합 구현 내역 (2026-08-01 적용)

- `TrainExpansionPort` 제거(스크립트·씬 오브젝트). E키 근접 상호작용 대신 망치 우클릭으로 통합 —
  설치·수리·건설이 망치 한 도구로 모인다.
- `RepairHammerController`: 다음 건설 슬롯(재건할 첫 빈 슬롯, 없으면 후미 증설)의 연결 지점을
  사거리 안에서 겨누면 건설 조준 성립 → 우클릭 = 칸 건설. 호스트가 건설 지점을 권위 상태로
  재계산해 거리 재검증 후 (자원 차감 + 건설)을 원자적으로 확정한다(기존 포트·돔 설치와 동일 패턴).
- 초록 테두리 프리뷰: `CarBuildGhostView`(씬 `CarBuildGhost`)가 지어질 칸 부피를 와이어 박스로 표시 —
  초록 = 건설 가능, 붉은색 = 자원 부족. HUD에는 "우클릭 — 칸 건설 (자원 N개)" 안내가 함께 뜬다.
- **자리 점유 시 건설 차단**: 지어질 자리(= 프리뷰 테두리와 같은 상자)에 플레이어·몬스터가 있으면
  테두리가 붉게 바뀌고 "자리에 사람·몬스터가 있어 칸을 지을 수 없다" 안내가 뜨며 우클릭이 먹지 않는다.
  새 칸이 사람·몬스터를 안에 가두는 상황을 막는다. 소유자 조준과 호스트 확정이 같은 판정 함수를 쓴다.
- 조준 계산은 `CarBuildAimLogic`(순수 로직)으로 분리 — EditMode 테스트 10개 추가(총 159개 통과).
- **플레이 검증 필요**: 2인 테스트로 ① 후미 겨눔 → 초록 테두리·안내 표시 ② 우클릭 건설(자원 차감)
  ③ 파괴된 중간 슬롯 재건 시 프리뷰가 그 자리에 뜨는지 ④ 자원 부족 시 붉은 테두리·안내.

#### 발견·수정: 짓지 않은 칸의 연결부 체력이 표시되는 버그 (2026-08-01)

- **증상**: 칸을 짓기 전인데 후미 건설 지점을 겨누면 "연결부 #2: 0 / 0"이 뜬다.
- **원인**: `CouplingPart`가 렌더러만 끄고 **콜라이더는 켠 채로 뒀다**. 씬의 `Connector_3`(연결부 #2,
  z = −20.25)는 아직 없는 칸의 연결부라 보이지 않지만 단단히 남아, 망치 조준 레이가 이 허깨비 부위를
  맞았다. 그 자리가 곧 슬롯 3의 건설 지점이라 칸 건설 조준까지 가로막혔다 —
  건설 포트를 망치로 옮기면서 드러난 기존 결함이다.
- **수정**:
  - `CouplingPart`: 표현과 함께 콜라이더도 상태에 맞춰 끈다(편성에 없거나 끊긴 연결부는 물리적으로도 없다).
    몬스터 표적은 `ITrainTargetRegistry`(Transform 기반)라 영향 없음.
  - `RepairHammerController.ReadPartState`: 복제 상태에 없는 부위는 표적으로 잡지 않는다(방어선).
  - 건설 지점이 씬 연결부 위치(z = −20.25)와 겹친다는 사실을 EditMode 테스트로 고정.

### 이탈 칸 재결합 구현 내역 (2026-08-01 적용)

설계는 [손잡이-이탈저항 스펙 §4.1](../design/Train-Survival-손잡이-이탈저항-스펙.md)에 있고, 여기에는 구현 형태와
구현하며 확정한 것만 적는다.

- **순수 로직**: `TrainStateLogic.CanRecouple`/`Recouple`(칸 부착 + 앞 연결부 복구),
  `CarRecoupleAimLogic`(겨눌 칸 선택·연결부 자리 프리뷰 부피·안내 문구 우선순위). EditMode 14개 추가 —
  **전체 173개 통과**.
- **호스트 확정**: `ITrainRecouple`(신설 계약, `TrainState`가 구현) — 새로 짓는 `ITrainExpansion`과 목적이
  달라(회수 vs 건설) 계약을 나눴다. 망치가 `RequestRecoupleServerRpc`로 요청하면 호스트가 대상 칸·조준 지점을
  권위 상태로 재계산해 거리 검증 후 (자원 차감 + 재결합)을 원자적으로 확정한다(기존 칸 건설과 같은 패턴).
  슬롯 도달은 조준이 쓰는 클라 표시 보간 값이 아니라 **권위 오프셋으로 다시 본다.**
- **조준·표시**: `CarRecoupleAimLocalEvent` 신설. 안내는 `InventoryHud`가, 테두리는 칸 건설과 같은
  `CarBuildGhostView`가 그린다 — 두 조준 이벤트를 함께 들고 있다가 **재결합 > 칸 건설** 순으로 그려,
  한쪽의 조준 해제가 다른 쪽 프리뷰를 지우지 않게 했다(망치 우클릭 우선순위와 같은 순서).
  겨누는 지점은 칸 건설과 같은 좌표(`CarBuildAimLogic.AnchorZ`)를 쓴다.
- **데이터**: `TrainExpansionSettings.RecoupleCost` = 2 (칸 신규 건설 5개보다 저렴).

구현하며 확정한 것 2건:

1. **절반 페널티는 '뚫렸던' 연결부에만** — 연쇄 이탈로 함께 떨어졌을 뿐 끊기지 않은 연결부(연결부 1이 뚫려
   칸2·칸3이 함께 이탈했을 때의 칸2↔칸3)는 체력을 그대로 되찾는다. 손상된 적 없는 자리에 페널티를 물리면
   방어에 성공한 연결부를 벌하는 셈이라, 스펙 §4.1의 "항상 절반"을 좁혔다.
2. **잡기 불가 전환 시 손잡이 그랩 자동 해제** — 재결합·소실로 `IsCarGrabbable`이 false가 되면 앵커가 스스로
   `ReleaseGrab`하고, 집게는 앵커 그랩 중 점유가 풀린 것을 보고 로프를 끊는다. 손잡이 앵커는 씬 정적 배치라
   despawn하지 않아 집게의 기존 "대상 소멸" 검사에 걸리지 않는 것을 구현 중 발견해 메운 구멍이다.
   재결합 확정 경로가 집게를 직접 알지 않아도 되게 앵커 쪽에 뒀다.

- **플레이 검증 통과 (2026-08-01 · 3인 세션)**: 손잡이는 칸당 2개뿐인데 끌어오기에 정확히 2인이 필요해,
  망치를 쥘 3번째 사람이 있어야 한다(스펙 §4.1 "알려진 제약"). 2인 끌어당김 + 1인 망치 구성으로
  조준·안내·부착·자원 차감·그랩 해제·연결부 체력·건축물 복귀까지 전 항목 이상 없음 — 상세는 스펙 §12.
  같은 세션에서 **손잡이 저항의 클라N 정성 확인**(인원별 감속/정지/끌어당김)도 함께 통과했다(슬롯 도달이
  재결합의 전제라 2인 끌어당김이 실제로 성립해야 확인되는 항목이다).
