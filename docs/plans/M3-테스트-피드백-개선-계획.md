## 1. 망치 조준 라벨 — 자원 부족 안내가 안 뜨는 버그

- **증상**: 자원이 부족할 때 돔 설치는 안 되지만(정상), "자원 부족" 안내가 화면에 뜨지 않는다.
- **원인**: `InventoryHud.DrawHammerTarget()`이 안내를 `수리 가능 → 설치 안내` 순서의 **배타적(else-if) 분기**로
  그린다. 겨눈 칸이 손상돼 있으면(수리 가능) 설치/부족 안내가 항상 가려진다. 두 조건은 독립인데 UI가 하나만 고른 것.
- **수정 방안**:
  - 수리 안내와 설치(또는 부족) 안내를 **동시에 이어 붙여** 표시한다.
  - 부족 안내는 `<color=red>`로 강조해 눈에 띄게 한다.
  - 부수 정리: `RepairHammerController.UpdateAimAndInput()`의 `ITrainExpansion` ServiceLocator 조회가 2회
    중복이므로 1회로 합친다.
- **대상 파일**: `Assets/_Project/Scripts/UI/InventoryHud.cs`, `Assets/_Project/Scripts/Gameplay/Train/RepairHammerController.cs`
- **검증**: 자원 0~2개 상태에서 (a) 만피 칸, (b) 손상 칸을 각각 겨눠 부족 안내가 두 경우 모두 뜨는지 확인.

## 2. 연료 소모율 HUD 표시 (칸 증설 트레이드오프 가시화)

- **배경**: 테스트에서 "연료 트레이드오프를 확인하기 어렵다"는 피드백. 현재 HUD는 잔량만 보여줘 칸 수에 따른
  소모 변화를 체감할 수 없다.
- **수정 방안**:
  - `FuelChangedEvent`에 `ConsumptionPerSecond` 필드를 추가한다.
  - 소모율은 **복제하지 않고 각 피어가 같은 입력으로 재계산**한다 — `FuelTank.OnFuelChanged()`(모든 피어에서
    NetworkVariable 콜백으로 발행됨)에서 `FuelMath.ComputeConsumptionPerSecond(설정 기본치, 칸당 소모,
    IFuelLoadProvider.AttachedCarCount)`를 호출. 입력이 전부 결정론적(SO + 복제 편성)이라 클라이언트에도 정확하다.
  - `CoreLoopHud` 연료 라인을 `연료: 54 / 100  (-0.80/s)` 형식으로 확장. 기본 편성(화물 2칸) 0.80/s,
    5칸 시 1.10/s, 칸 상실 시 감소가 눈으로 보인다.
- **대상 파일**: `Gameplay/World/FuelEvents.cs`, `Gameplay/World/FuelTank.cs`, `UI/CoreLoopHud.cs`
- **검증**: 증설/이탈 직후 표시 소모율이 호스트·클라 동일하게 바뀌는지 확인.

## 3. Esc 세션 메뉴·세션 종료 복귀 (클라이언트 Main 복귀 버튼)

- **배경**: 재접속 테스트를 하려면 클라이언트가 세션을 나갔다 다시 들어와야 하는데, 현재는
  - `INetworkSessionService.Shutdown()`을 **호출하는 코드가 프로젝트에 없고**,
  - 접속이 끊겨도(호스트 이탈 포함) Game 씬에 방치되며 복귀 UI가 없다 — 끊김 콜백 구독도 0건.
- **수정 방안**:
  1. **`SessionExitHud`(신규, `Game.UI`)를 Game 씬 `SliceHud` 오브젝트에 부착**:
     - 세션 활성 중 **Esc = 세션 메뉴 토글** — "세션 나가기(메인 화면으로)" / "계속하기" 버튼.
     - 세션 비활성(끊김·종료) 감지 시 **자동으로 중앙 오버레이** "세션이 종료되었습니다 → 메인 화면으로" 표시.
     - 나가기 처리 = `session.Shutdown()` 후 `SceneManager.LoadScene("Main")` — NGO 씬 관리는 세션과 함께
       죽으므로 일반 씬 로드를 쓴다(`LoadGameplayScene`은 호스트 전용이라 불가).
  2. **`SessionMenuToggledLocalEvent`(신규, `Game.Gameplay.Player`)** 발행 — I 창과 동일한 처리 계약:
     - `NetworkPlayerController`: 메뉴 열림 동안 시점 회전 정지 + 커서 해제 (I 창과 OR 결합, `ApplyCursorState()`).
     - `HotbarController`: `IsPanelOpen`에 메뉴 상태를 OR 결합해 무기·상호작용 입력 차단.
- **참고 동작**: 호스트가 "세션 나가기"를 누르면 세션 전체가 종료되고, 남은 클라이언트에는 종료 오버레이가 뜬다.
  플레이어 despawn 시 커서는 기존 로직(`OnNetworkDespawn`)이 복구한다.
- **대상 파일**: `UI/SessionExitHud.cs`(신규), `Gameplay/Player/PlayerEvents.cs`,
  `Gameplay/Player/NetworkPlayerController.cs`, `Gameplay/Inventory/HotbarController.cs`, `Scenes/Game.unity`
- **검증**: ① 클라 Esc → 나가기 → Main에서 재접속 ② 호스트 종료 시 클라에 오버레이 자동 표시 ③ 메뉴 열림 중
  좌클릭이 무기 발사로 새지 않는지.

## 4. 이탈 칸 위에서 지상 자원이 떨려 보이는 버그

- **증상**: 뒤로 밀려가는 이탈 칸에 탑승한 시점에서 지상 자원(지형 포함)이 미세하게 떨려 보인다.
- **원인 분석** (클라이언트):
  1. 이탈 오프셋은 `TrainState`의 `NetworkList<float>`로 복제되는데, NetworkList는 **틱 레이트(30 Hz)로만
     갱신되고 보간이 없다** → 클라의 `CarView`가 읽는 오프셋은 60 fps 기준 "2프레임 정지 → 1스텝 점프"의 계단값.
  2. 탑승 플레이어는 칸의 **위치 델타를 그대로 복사**해 이동하고(`NetworkPlayerController`, 의도된 설계),
     카메라는 플레이어의 자식이므로 **카메라도 30 Hz 계단**으로 움직인다.
  3. 반면 지형 타일·자원은 `WorldScrollController`의 매 프레임 연속 `_displayDistance`로 움직인다.
  4. → **연속 이동하는 월드 vs 계단 이동하는 카메라**의 상대 변위가 매 프레임 진동 = 떨림.
- **수정 방안**:
  - `TrainState`에 **클라이언트 전용 표시 오프셋**(`_displayOffsets`)을 두고, 매 프레임 복제값으로
    지수 수렴시킨다(수렴률 ≈ 12/s). 재건·재시작 같은 큰 불연속(> 3 m)은 애니메이션 없이 즉시 스냅.
  - `GetEjectOffset()`이 클라에서는 표시값을 돌려준다 — `CarView`·`HandrailAnchor`·`StructureView`가
    같은 값을 읽으므로 셋이 함께 부드럽게 움직인다. 서버는 원본 시뮬 값 그대로(권위 판정 불변).
- **대상 파일**: `Gameplay/Train/TrainState.cs`
- **검증**: 클라이언트로 이탈 칸에 탑승해 지상 자원·지형이 부드럽게 흐르는지, 손잡이·돔이 칸과 어긋나지 않는지.
- **비고**: 진단 시 지형 타일도 함께 떨리면 이 원인이 확정. Boot 씬의 `NetworkLatencyProfileDriver`가
  클라에 RTT 60 ms 시뮬을 기본 적용 중이라 "클라에서만 보인다"는 증상과 일치한다.

## 5. 손잡이 회수 모션 부자연 (열차로 되돌아오는 움직임)

- **증상**: 집게로 손잡이를 잡는 순간 이탈 칸의 이동 방향이 뚝 끊기듯 반전된다.
- **원인**: 현재 모델은 밀림 속도만 램프하고 **저항(잡은 인원 × 견인력)은 순간 적용**된다 —
  `net = push(램프) − n×pull(즉시)` 이라 잡는/놓는 순간 순 속도가 점프한다.
- **수정 방안** (`EjectMotionMath` 모델 단순화):
  - `ComputeTargetVelocity(targetPush, grabbers, pull)` = 목표 순 속도(저항 포함, 음수 가능).
  - `StepVelocity(current, target, accel, dt)` = 현재 속도를 목표로 **가속도 램프**(MoveTowards).
  - 시뮬은 칸별 단일 속도(`_ejectVelocities`)만 유지 — 분리 직후 관성(0→목표)과 회수 반전(감속→정지→회수)이
    같은 기울기(`EjectDeceleration`)로 부드럽게 일어난다. 기존 `StepPushSpeed`/`ComputeNetVelocity`는 대체.
  - `TrainDurabilitySettings.EjectDeceleration` 툴팁을 "속도가 목표(밀림-저항)로 수렴하는 가속도"로 갱신.
- **대상 파일**: `Gameplay/Train/EjectMotionMath.cs`, `Gameplay/Train/TrainState.cs`,
  `Gameplay/Train/TrainDurabilitySettings.cs`, `Tests/EditMode/EjectMotionMathTests.cs`(모델 교체에 맞춰 갱신)
- **검증**: EditMode 테스트(속도 점프 없음·목표 수렴) + 2인 손잡이 잡기/놓기 반복 시 모션이 이어지는지.
- **비고**: 손잡이-이탈저항 스펙 §4의 수식(순간 저항 적용)과 달라지므로, 적용 시 스펙 문서 갱신도 필요하다.
