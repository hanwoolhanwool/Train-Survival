# M7 4차 구현 계획 — 거치 무기 (터렛 + 거치 기관총)

작성일: 2026-08-25 · 대상: `feat/m7-mounted-weapons` (main에서 분기) · 상태: **착수 전 —
결정 ①~④ 확정 (2026-08-25, 사용자 결정 — §1)**
(차수 편성: [M7-착수-준비.md](M7-착수-준비.md) §4 — 4차 = 거치 무기, 결정 ③으로 M5에서 편입.
선행: 1~3차 구현 완료. 시작 기준선 EditMode **890/890** · 인게임 씬 = `Game_ArtTest` 단일)

> **4차 목표**: **열차가 화력을 갖는다.** 지금까지의 무기는 전부 플레이어 소유(핫바 슬롯·소유자
> 입력)였다. 거치 무기는 **열차에 설치되고 사람이 붙어서 쓰는** 첫 무기다 — 소유가 아니라
> **점유**이고, 내려놓고 가면 다음 사람이 쓴다. 이것이 기획서 §7.2의 "포수 역할"이 성립하는
> 지점이고, 5차 가속 방어전·6차 최종 보스 추격전이 전제하는 **"거치 무기 총동원"**(§8.3)의
> 실물이다.
>
> **부수 목표**: M5 완료 기준으로 이월된 **4인 세션 역할 분담 검증**을 이 차수 검증에서 겸한다
> (착수 준비 결정 ⑨ — "거치 무기 차수 겸사").

## 0. 범위

**코어** (2단계 편성 — 결정 ④):

**A단계 — 거치 기관총** ("사람이 붙어서 쓴다")

1. **건축물 2종 등재** — `StructureKind`에 `MountedGun`·`Turret` append + 카탈로그 엔트리.
   건축 개편이 세운 그리드 설치·철거·피해·파괴·이탈 칸 추종 경로를 **그대로** 탄다
2. **점유 모델 신설** — 한 거치 무기에 **1인 확정**(호스트 권위). 붙기·내리기·강제 하차
3. **플레이어 구속** — 점유 중 이동·핫바 입력 잠금, 좌석 앵커 고정, 사각(射角) 제한 시야
4. **조준·발사** — 점유자 로컬 판정 → 호스트 확정(`GunController`와 같은 파이프라인).
   조준각은 **표현 전용 중계**, 판정은 서버가 좌석 기준으로 재검증
5. **탄창·재장전** — 거치 무기가 자체 탄창을 갖고, **점유자가 자기 인벤의 소총탄으로 채운다**
   (결정 ③). 점유가 바뀌어도 남은 탄은 무기에 남는다

**B단계 — 자동 터렛** ("사람 없이 쏜다")

6. **서버 구동 자동 사격** — A단계의 사격 파이프라인에서 **조작자만 AI로 바꾼다**.
   대상 선정은 순수 함수, 발사는 서버 권위(로컬 선반영 없음 — 입력이 없다)
7. **수동 장전** — 사람이 다가가 탄약을 채워 넣는다. 낮에 준비하고 밤에 소모하는 루프

**소규모**:

8. **HUD** — 점유 중 탄창 표시(`WeaponAmmoChangedLocalEvent` 재사용) + 조작 안내
9. **QA 키 1개** — `F4`: 겨눈 자리에 거치 무기 즉시 설치 + 소총탄 지급 (넘패드는 15키 전부 점유)

**비범위** (이번 차수에서 손대지 않는다):

- **지뢰·철조망** (기획 §6.2 설치형 3번째 줄) — 준비형 방어는 다른 축이다
- **화염방사기** (착수 준비 §1 — 북극 차수에서 재론했으나 미편입)
- **포수 전용 상위 장비** (기획 §7.2 역할 장비 특화) — 장비 축은 열지 않는다
- **거치 무기 전용 모델** — 형상은 임시(기존 구조물 에셋 조합). M8 아트 패스의 몫이다
- **5차 연동** — 가속 방어전의 "전 병력 추격"은 5차가 이 축을 소비하는 쪽이다

## 2. 설계

### 2.1 건축물 2종 등재 — 데이터 append (코드 최소)

`StructureKind`에 값 2개를 append한다. **한 번 배정한 값은 바꾸지 않는다**는 기존 규약을 지킨다.

```
MountedGun = 7,   // 거치 기관총 — 사람이 붙어서 쏜다
Turret     = 8,   // 자동 터렛 — 사람 없이 쏜다
```

카탈로그 엔트리 2개를 추가한다. **기존 필드만으로 대부분이 채워진다**:

| 필드 | 거치 기관총 | 자동 터렛 | 근거 |
|---|---|---|---|
| `MaxHealth` | 60 | 45 | 칸(120)보다 낮게 — 건축물부터 노출되는 기존 규칙 |
| `BuildCost` | 6 | 8 | 난방기 3 · 강화 난방로 7 사이. 터렛이 더 비싸다(무인 화력) |
| `FootprintWidth/Length` | 2 × 2 | 2 × 2 | 갑판 본체는 4열이라 2열을 먹으면 통행로가 2열 남는다 (§6 리스크 6) |
| `Placeable` | true | true | R 순환에 노출 |
| `ProvidesStorageBlock` | false | false | 탄창은 저장 블록이 아니다 (§2.5) |
| `RefundResource` | Scrap | Scrap | 목재가 아니라 고철 — 금속 구조물 |
| `ViewPrefab` | `Structure_MountedGun` | `Structure_Turret` | 신규 프리팹 2종 |

**신규 카탈로그 필드 1개** — 이 축에만 필요한 것:

```csharp
[Tooltip("거치 무기 설정 — 비어 있으면 거치 무기가 아니다. 이 필드 하나가 '무기 건축물' 판정의 데이터 축이다.")]
[SerializeField] private MountedWeaponSettings _mountedWeapon;
```

`ProvidesHeat`·`ProvidesStorageBlock`이 그랬듯 **플래그가 곧 판정**이다 — 종류 이름을 코드에서
하드코딩하지 않는다. 세 번째 거치 무기가 생기면 에셋만 추가하면 된다 (OCP).

### 2.2 점유 모델 — 호스트 확정 + 별도 리스트 (결정 ⑤)

**왜 `StructureEntry`에 넣지 않는가**: 그 리스트는 `TrainState`가 들고 **전 피어에 복제**된다.
조준각을 거기 실으면 사람이 포신을 돌리는 동안 매 프레임 리스트가 dirty가 되고, 건축물이 20개면
20개 항목이 함께 흐른다. 점유는 드물게 바뀌고 조준각은 매 프레임 바뀐다 — **주기가 다른 두 값을
한 리스트에 담지 않는다.**

**신설 `MountedWeaponHost : NetworkBehaviour`** (Train 루트에 1개):

```csharp
struct MountOccupancy : INetworkSerializable, IEquatable<MountOccupancy>
{
    public ushort StructureId;      // StructureEntry.Id — 안정 참조 키
    public ulong  OccupantClientId; // 점유자
}
// NetworkList<MountOccupancy> — 점유 중인 것만 항목이 있다 (없음 = 비점유)
```

| 경로 | 권위 | 내용 |
|---|---|---|
| `RequestMountServerRpc(structureId)` | 호스트 | 거치 무기인지 · 살아 있는지 · 좌석 반경 안인지 · **이미 점유 중이 아닌지**를 확인하고 항목 추가 |
| `RequestDismountServerRpc()` | 호스트 | 요청자의 항목 제거. 중복 호출 무해 |
| 강제 하차 | 호스트 | 건축물 파괴 · 칸 파괴 · 점유자 사망 · 점유자 접속 종료 → 항목 제거 + 소유자에게 통지 |

**순수 함수 `MountOccupancyLogic`** (EditMode 대상):

- `CanMount(occupied, isAlive, distanceSq, radiusSq)` → 승인/거부 사유
- `ResolveForcedDismount(structureAlive, occupantAlive, occupantConnected)` → 강제 하차 여부

**한 사람은 하나만** — 같은 클라이언트가 다른 거치 무기를 요청하면 **기존 점유를 먼저 해제**한다
(창고 동시 경합에서 배운 규칙: 경합은 서버 도착 순서로 결정론적으로 끝낸다).

### 2.3 플레이어 구속 — 사다리 선례의 재사용 (결정 ②)

`NetworkPlayerController`에 마운트 상태를 추가한다. 사다리와 **같은 구조**다 — 로컬 구동,
위치는 `OwnerNetworkTransform`이 복제, 판정만 서버.

| 축 | 처리 |
|---|---|
| 붙기 | 좌석 반경(2.5 m) + 시선 안에서 `E` → 서버 승인 후 좌석 앵커로 스냅 |
| 이동 | `_mounted` 동안 이동 입력·점프·컨베이어·중력 처리를 건너뛴다 (사다리 `_climbing`과 같은 게이트 자리) |
| 시야 | 카메라 yaw/pitch를 **사각 제한 안에서만** 움직인다 — `MountedAimMath.ClampAim` |
| 핫바 | `HotbarController`에 점유 게이트 추가 — 점유 중 무기·망치·집게 입력 전부 off (기존 `InputEnabled` 축 재사용) |
| 내리기 | `E` 또는 `Esc`. `Esc`는 세션 메뉴보다 **먼저** 소비한다 (제작 창 닫기와 같은 우선순위 규칙) |
| 강제 하차 | 서버 통지 수신 즉시 로컬 해제 + 좌석 옆 갑판으로 내려놓는다 |

**사각 제한**(`MountedWeaponSettings`): yaw ±110° · pitch −15°~+40°. 열차 안쪽으로는 돌아가지
않는다 — 아군 오사와 "포신이 칸을 뚫는" 그림을 **데이터로** 막는다.

### 2.4 조준·발사 — `GunController` 파이프라인의 이식 (결정 ⑥)

**재사용하는 것**(코드 복사 아님 — 기존 타입을 그대로 호출):

| 자산 | 쓰임 |
|---|---|
| `GunSettings` | 피해·사거리·연사·탄창·탄종·트레이서·탄착 — **거치 무기용 에셋 2개를 새로 만든다** |
| `WeaponSpreadMath.ApplySpreadSeeded` | 시드 결정적 산탄 — 전 피어가 같은 궤적을 재계산 |
| `WeaponRaycast.TryGetClosestHit` | 자기 root 제외 레이 — 거치 무기의 root는 Train이라 **열차를 쏘지 않는다** |
| `TracerView` · `ImpactEffectView` | 풀링 연출 그대로 |
| `GunMagazine` | 장탄·연사 간격·재장전 상태 기계 |
| `IDamageable` | 대상 계약 |

**새로 만드는 것**: `MountedWeaponView`(비네트워크, 건축물 프리팹 루트) — 요크 회전 표시·총구
앵커·발사 연출 재생·좌석 앵커 제공. `StructureView`(피해·수명) 옆에 **역할을 나눠** 붙는다.

**발사 파이프라인** (A단계 — 사람이 조작):

```
점유자 입력 → 로컬 레이 판정(지연 0) → 로컬 연출 재생
            → ReportMountedHitServerRpc(structureId, seat, hitPoint, pellets)  ← 판정
            → ReportMountedFireServerRpc(structureId, seed, origin, forward)   ← 연출 중계
호스트: 좌석 앵커 기준 거리 재검증 → ApplyDamage → 장탄 1 차감
```

`GunController`와 다른 점은 **기준점이 플레이어가 아니라 좌석 앵커**라는 것뿐이다. 서버는
점유자가 실제로 그 자리에 있는지 이미 알고 있으므로(점유 리스트), 사거리 검증이 더 강하다.

**조준각 중계**: 점유자 → 서버 → `NotOwner` 10 Hz Unreliable. 원격 피어는 받은 각도로 요크를
보간한다. **판정에 쓰지 않는다** — 유실돼도 그림만 잠깐 늦는다.

> **M6 잔여의 "지상 원격 떨림"과 같은 계열이다.** 로컬 구동 옆에 스냅샷 구동을 두면 상대 떨림이
> 보인다(M5 8차 교훈). 요크는 **열차 프레임에 고정**이라 관찰자 이동과 위상차가 생기지 않는다 —
> 이 축에서는 안전하다.

### 2.5 탄창·재장전 (결정 ③ · ⑦)

| 축 | 규칙 |
|---|---|
| 탄종 | **소총탄**(`RifleAmmo`) — 볼트액션과 공유. 밤에 거치 무기를 돌리면 저격 탄이 준다는 **경쟁 관계**가 그대로 압박이 된다 |
| 탄창 | 거치 기관총 40발 / 터렛 25발 (`GunSettings.MagazineCapacity`) |
| 재장전 | 점유 중 `R` → 개인 인벤에서 차감(서버 확정) → 무기 탄창 충전. `GunController.RequestReloadServerRpc`와 **같은 선반영 규약** |
| 권위 | **서버 내부 `Dictionary<ushort,int>`** — 발사 중계 수신마다 1 차감, 재장전 확정 시 충전. 리스트에 싣지 않는다 |
| 점유 교대 | 남은 탄은 **무기에 남는다.** 다음 사람이 붙으면 서버가 현재 장탄을 `OwnerRpc`로 알려 준다 |
| 파괴 | 남은 탄은 **소실**한다 — 보따리 배출 대상이 아니다 (`ProvidesStorageBlock` false) |

**HUD**: 기존 `WeaponAmmoChangedLocalEvent`를 그대로 발행한다(표시명 = "거치 기관총").
예비 탄약 칸에는 **개인 인벤의 소총탄 수**가 들어간다 — 지금 화면에 있는 것과 같은 의미다.

### 2.6 자동 터렛 — 조작자만 AI로 (B단계 · 결정 ⑧)

A단계가 끝나면 **판정·연출·탄창이 이미 서 있다.** B단계가 새로 만드는 것은 조작자뿐이다.

| 축 | 처리 |
|---|---|
| 구동 | **서버 전용.** 로컬 선반영이 없다 — 예측할 입력이 없다 |
| 대상 탐색 | `Physics.OverlapSphere`(탐색 반경 35 m, 몬스터 레이어) → `IDamageable` 생존 필터 → **가장 가까운 것** |
| 대상 필터 | **몬스터 계열만** (레이어 + `MonsterHealth`/`BossHealth` 계약). 플레이어·열차·자원은 후보에서 제외 |
| 사각 | 사람과 같은 제한을 받는다 — 뒤로는 못 쏜다 |
| 발사 | `GunSettings.FireInterval` 주기. 시야가 막히면(레이가 대상에 안 닿으면) 쏘지 않는다 |
| 연출 | 서버가 시드를 정해 전 피어에 브로드캐스트 — A단계의 중계 RPC를 그대로 쓴다 |
| 장전 | 사람이 다가가 `E` → 개인 인벤에서 탄창으로 이전 (점유가 아니라 **1회 상호작용**) |
| 상한 | 동시 활성 터렛 수 상한(에셋, 기본 4) — 밤 웨이브와 겹칠 때의 RPC·프레임 방어선 |

**순수 함수 `TurretTargetingMath`**(EditMode 대상): 후보 배열 → 사각·거리·생존 필터 → 선정.
물리 조회는 호출부가 하고, **선정 규칙은 순수 함수가 소유**한다 (레벨 검사기에서 세운 규약과 같다).

### 2.7 파괴·이탈·수명 주기 경계

| 상황 | 처리 |
|---|---|
| 건축물 파괴 | 기존 경로(체력 0 → 항목 제거 → 뷰 회수). **점유자 강제 하차**가 추가된다 |
| 칸 파괴 | 그 칸의 건축물 일괄 제거 — 기존 경로. 점유자 강제 하차 동반 |
| 칸 이탈 | 건축물은 칸 자식이라 **따라간다**. 점유자도 좌석에 붙어 함께 끌려간다 — 이탈 칸 위 전투가 성립한다 |
| 점유자 사망 | 강제 하차 → 부활은 기존 경로 |
| 점유자 끊김 | 강제 하차. **재접속 복원 대상이 아니다** — 점유는 세션 순간 상태다 |
| 호스트 이탈 | 세션 종료 경로 그대로 (M6 H9 관찰 범위 — 이 차수가 건드리지 않는다) |
| 철거 | `X` 홀드 → 기존 경로. **점유 중이면 기각**한다 |

**접속 회귀 위험 없음**: 건축물 뷰는 `NetworkObject`가 아니다 (`PoolManager` 로컬 스폰).
**네트워크 프리팹 목록이 늘지 않으므로 `GlobalObjectIdHash` 오염·`ClosedByRemote` 위험이
이 차수에는 없다.** M7 2·3차가 매번 "최우선 관문"으로 세웠던 D·H 구역이 여기서는 빠진다.

## 6. 리스크

| # | 리스크 | 처방 |
|---|---|---|
| 1 | **유령 점유** — 건축물이 사라졌는데 점유 항목이 남아 플레이어가 허공에 고정 | 파괴·철거·칸 파괴 경로에서 **서버가 먼저 점유를 지운다**. 클라는 통지 수신 즉시 해제하고, 통지가 없어도 매 프레임 "내 점유 대상이 아직 있는가"를 확인한다 (이중 방어) |
| 2 | **조준각 원격 떨림** — 10 Hz 중계가 끊기거나 튄다 | 표현 전용이므로 보간으로 흡수. 요크는 열차 프레임 고정이라 관찰자 이동과 위상차가 없다 (§2.4) |
| 3 | **아군 오사** — 특히 자동 터렛 | 대상 필터를 몬스터 계열로 한정(결정 ⑧) + 사각을 바깥쪽으로만 제한. 사람 조작 기관총도 같은 사각을 받는다 |
| 4 | **밤 웨이브 + 터렛 다수의 RPC 폭증** | 동시 활성 상한(기본 4) + 발사 주기 하한. B4에서 웨이브 최대 물량과 함께 실측한다 |
| 5 | **통행 차단** — 2×2 발자국이 좁은 갑판을 막는다 | 돔이 같은 이유로 설치 목록에서 빠진 전례가 있다(건축 개편 1차). 판자 미증축 칸에서 통행로가 남는지 A1에서 먼저 확인하고, 안 되면 발자국을 2×1로 줄인다 |
| 6 | **소총탄 경쟁이 과하다** | 의도된 압박이지만 밤 하나를 못 버티는 수준이면 실패다. 탄창 용량·피해는 전부 에셋이므로 검증 중 조정한다 (M4 규약) |
| 7 | **B단계가 A단계를 재작업시킨다** | 그래서 순서가 A→B다. A6의 발사 경로를 **조작자 주체와 무관한 형태**로 먼저 잡는다 (입력 계층과 발사 계층 분리) |
| 8 | **점유 중 `Esc` 우선순위 충돌** | 세션 메뉴·제작 창과 같은 문제를 이미 푼 전례가 있다(M7 3차 W3). 점유 해제가 세션 메뉴보다 먼저 소비한다 |

## 7. 완료 기준

1. 갑판에 **거치 기관총을 짓고, 붙어서, 밤 웨이브를 쏴서 막을 수 있다** — 호스트·클라 양쪽에서
2. 점유는 **1인 확정**이고, 파괴·사망·끊김 어느 쪽으로도 **유령이 남지 않는다**
3. **자동 터렛이 사람 없이 몬스터만 쏘고**, 탄이 떨어지면 멈추며, 사람이 채우면 다시 돈다
4. 기존 건축물 6종·접속·이탈 칸 추종에 **회귀가 없다**
5. **4인 세션에서 포수 역할이 갈린다** (M5 완료 기준 이월 — H 구역)
