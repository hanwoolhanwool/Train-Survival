## 0. 범위

**코어**:

1. **부활 대기 일원화** — 이탈 사망(열차 뒤처짐)의 고정 5 s를 전투 사망과 같은
   Day 비례 계산(`PlayerHealthSettings.GetRespawnDelaySeconds`)으로 흡수 (결정 ①)
2. **게임오버 판정** — 호스트 권위 전멸 감지: 접속 중 플레이어 전원이 죽어 있으면
   (부활 대기 포함) 게임오버 확정. 끊긴 플레이어는 판정 제외 (네트워크 §2.3)
3. **게임오버 UI·세션 마무리** — 전 피어 결과 오버레이(도달 Day·경과 시간) →
   사용자 확인 → 세션 종료 + Main 복귀 (기존 `SessionExitHud.LeaveToMain` 경로 재사용)
4. **메타 진행 저장** — 로컬 JSON(`persistentDataPath`): 런 기록(최고 도달 Day·게임오버
   횟수) + 업적 플래그 집합. 게임오버 시 각 피어가 자기 로컬에 기록 (§2.3 "각자 로컬")
5. **업적 최소 집합** — 파이프 검증용 소수 정의 + Steam 업적 미러 계약 (결정 ③)

**비범위** (후속):

- **승리/완주 판정** — 최종장 진입·클리어 연출은 본편 몬스터·지역 설계와 함께.
  M6 완료 기준의 "완주"는 검증 세션의 플레이 목표이지 시스템 판정이 아니다
- **수집품(도감)** — 기획에 목록 미정. 저장 스키마에 확장 여지만 남긴다
- **자체 AppID 실 업적 정의·스토어 등록** — 릴리스 전 별도 (AppID 480에는 자체 업적을
  정의할 수 없다 — Spacewar 테스트 업적으로 왕복 스모크만 가능)
- 호스트 마이그레이션 · 신규 drop-in 정책 변경 (1·2차 비범위 유지)

## 2. 설계 (코드 실측 기반 — 2026-08-13)

### 2.1 부활 대기 일원화 (결정 ①)

- 현황: 전투/환경 사망(`PlayerHealth.ServerConfirmDeath`)은 이미 `IDayCycleService.DayNumber`
  조회 → `PlayerHealthSettings.GetRespawnDelaySeconds(day)`를 쓴다. 이탈 사망
  (`NetworkPlayerController.ServerCheckFallBehind`)만 `TrainLayoutSettings.RespawnDelaySeconds`
  (5 s 고정)를 쓴다 — **대기 시간 출처가 두 갈래**.
- 처방: `PlayerHealth`에 서버 헬퍼 `ServerComputeRespawnDelaySeconds()`(Day 조회 +
  설정 계산)를 공개하고, 이탈 경로가 이를 쓰도록 교체. `TrainLayoutSettings`의
  `_respawnDelaySeconds` 필드·프로퍼티는 제거(참조가 이탈 경로 하나뿐), 에셋 정리.
- 재접속 잔여 대기(1차 결정 ⑦ — 사망 시각 + 대기 − 현재)는 스냅샷에 대기 시간이
  절대값으로 저장돼 있어 **무수정으로 정합** — Day가 바뀌어도 사망 당시 값이 유지된다.
- n값 확정: 에셋 현행 값(기본 5 / Day당 +1 / 상한 20)을 그대로 확정안으로 제안 —
  기획서 §9.1 "n값 TBD, Day 비례 증가 검토 권장"의 해소. 밸런스 조정은 에셋 값 변경만.

### 2.2 게임오버 판정 — `GameOverLogic` + `GameOverMonitor` (Gameplay/Session)

- **소속 = Gameplay/Session**: 판정이 `PlayerHealth`·`NetworkPlayerController` 등
  Gameplay 타입을 직접 읽어야 해서 `Systems`에 둘 수 없다(단방향 — 1차
  `PlayerSessionRegistry`와 같은 사유). 개발 가이드의 "게임 상태 머신 = Systems/" 배치
  지정과 어긋나지만, 이번 범위는 상태 머신이 아니라 **판정 1건 + 종단 플래그**라
  Gameplay 소속이 무마찰이다 — 로비→인게임 전체 상태 머신이 생기는 시점에 재논의한다.
- **순수 판정 `GameOverLogic`** (static, EditMode 대상): 입력 = 접속 중 플레이어별
  `(스폰 여부, 생존 여부)` 목록 → 전멸 여부. 규칙(결정 ②ⓐ):
  - 생존 판정 = `PlayerHealth.IsAlive`(전투 사망 `_serverDead` + 이탈 `IsRespawnPending`
    통합 — M5 4차 D5·D10 결과물을 그대로 사용).
  - **스폰 전 접속자(PlayerObject 아직 없음)는 생존으로 간주(판정 보류)** — 접속
    승인~스폰 사이·재접속 복원 1프레임 창에서의 전멸 오탐 방지. 스폰·복원 완료
    시점에 재평가가 걸리므로 놓치지 않는다.
- **`GameOverMonitor`** (NetworkBehaviour, 호스트 전용 판정): `DayCycleController`가 있는
  Game 씬 네트워크 오브젝트에 컴포넌트 추가(**씬 배선은 YAML 직접 편집** 규약).
  - 재평가 트리거 4곳: ⓐ `PlayerDiedEvent`·ⓑ `PlayerFellBehindEvent` 구독(서버 분기 —
    두 이벤트 모두 호스트에서도 발행됨) · ⓒ `NetworkManager.OnClientDisconnectCallback`
    (NGO 2.13 실측 순서상 콜백 시점엔 `ConnectedClientsList`에서 이미 제거돼 있어
    "끊긴 자 제외"가 자동) · ⓓ 재접속 부활 재개 적용 직후(`PlayerSessionAgent` 복원
    코루틴에서 1회 — 복원 1프레임 창 보정). 폴링 없음 — 죽음·끊김 순간에만 평가.
  - 확정 = `NetworkVariable`로 게임오버 상태 + 결과(도달 Day·경과 시간) 복제 →
    각 피어 `OnValueChanged`에서 `EventBus<GameOverEvent>` 발행. RPC가 아니라
    NetworkVariable인 이유: **게임오버 후 재접속한 피어도 후발 동기화로 같은 화면**을
    받는다.
  - 종단 가드: 게임오버 확정 후 `ReviveServerRpc`·`RespawnCompleteServerRpc`는 서버에서
    무시(진행 중이던 소유자 부활 코루틴이 게임오버를 뒤집지 못하게). 신규 사망 이벤트도
    재평가하지 않는다.
- 부활 완료 이벤트는 신설하지 않는다 — 전멸은 죽음·끊김 트리거 순간에만 참이 될 수
  있고, 부활은 상태를 생존 쪽으로만 움직이므로 판정에 불필요.

### 2.3 게임오버 UI·세션 마무리 — `GameOverHud` (UI)

- `SessionExitHud` 패턴 답습(OnGUI + ServiceLocator 조회): `EventBus<GameOverEvent>`
  수신 → 전면 오버레이 — "전멸했습니다" + 도달 Day·경과 시간 + "메인 화면으로" 버튼.
  버튼 동작은 기존 `LeaveToMain`과 동일(`session.Shutdown()` + Main 씬 로드).
- **결과 표시 동안 세션 유지** — `INetworkSessionService`에 중간 상태가 없으므로
  Shutdown은 각자 사용자 액션으로 미룬다(기존 코드와 마찰 최소). 호스트가 먼저 나가면
  클라이언트는 기존 `DrawSessionEndedOverlay` 경로로 자연 복귀.
- 오버레이 중복 정리: 게임오버 표시 중에는 `SessionExitHud`의 세션 종료 오버레이·Esc
  메뉴를 억제(게임오버 화면이 우선).

### 2.4 메타 진행 저장 — `Systems/Meta` 신설

- **`MetaProgress`**(직렬화 데이터, 스키마 버전 필드 포함) + **`MetaProgressOps`**(순수
  갱신 로직 — EditMode 대상) + **`MetaProgressStore`**(파일 I/O 분리):
  `persistentDataPath/Meta/progress-{해시}.json`, `JsonUtility` 직렬화.
  - **MPPM 함정 선례 적용**: 가상 플레이어가 `persistentDataPath`를 공유하므로
    `LocalGuidIdentityProvider`와 같은 dataPath FNV-1a 해시로 파일명 분리. 해시 함수는
    비어 있는 `Utilities`로 승격해 공유(`Systems`가 참조 가능 — 단방향 유지).
  - 쓰기 실패는 식별 토큰 선례대로 catch + 로그(저장 실패가 게임을 막지 않는다).
- 데이터 v1: `bestDayReached` · `totalGameOvers` · `unlockedAchievements`(string id 집합).
  수집품 등 확장은 스키마 버전으로 흡수.
- 기록 시점: **각 피어가 `GameOverEvent` 수신 시 자기 로컬 갱신** (도달 Day는 이벤트
  페이로드 — 호스트 권위 값). 게임오버 전에 끊긴 피어는 그 런의 기록이 없다 — 수용
  (메타는 "참여한 결말"의 기록). 업적 해금은 발생 즉시 저장.

### 2.5 업적 — `IAchievementService` (+ Steam 미러, 결정 ③)

- 계약(Core): `bool IsUnlocked(string id)` · `void Unlock(string id)` — 구현은
  `Systems/Meta`(로컬 플래그 확정 + 저장). Steam 모드면 `SteamUserStats.SetAchievement +
  StoreStats`로 미러하는 데코레이터를 `Systems/Networking/Steam`에 —
  2차 `SteamService.Initialize` 성공 시에만 활성, 콜백 펌프는 기존 `GameBootstrapper`
  배선 그대로.
- 최소 집합(파이프 검증용 — 명칭·추가는 기획 협의로 언제든 확장): `first_game_over`
  (첫 런 결말) · `reach_day_3`(Day 3 도달). 해금 지점은 게임오버 훅 한 곳.
- AppID 480 한계: 자체 업적 정의 불가 — Spacewar 테스트 업적(`ACH_WIN_ONE_GAME`)으로
  Set→Store 왕복 스모크만 수행하고, 실 매핑 테이블은 자체 AppID 발급 후 채운다.

## 3. 구현 순서

1. 부활 대기 일원화(§2.1 — 이탈 경로 교체 + `TrainLayoutSettings` 필드 제거) +
   `GetRespawnDelaySeconds` Day 경계 EditMode
2. `GameOverLogic` 순수 판정 + EditMode(전원 사망 / 1명 생존 / 부활 대기 포함 /
   스폰 전 접속자 보류 / 호스트 단독)
3. `GameOverMonitor` — 트리거 4곳 배선 + NetworkVariable 복제 + 종단 가드
   (부활 RPC 무시) + Game 씬 컴포넌트 추가(YAML)
4. `GameOverHud` + `SessionExitHud` 오버레이 우선순위 정리
5. `Systems/Meta`(해시 유틸 Utilities 승격 → Ops/Store) + 게임오버 기록 훅 +
   EditMode(런 결과 반영·스키마 버전)
6. `IAchievementService` + Steam 미러(결정 ③ⓑ 시) + 검증 문서 갱신(3차 항목 편입)

## 4. 테스트·검증 계획

- **EditMode**: `GetRespawnDelaySeconds` 경계(Day 1 = 기본 · 증가 · 상한 도달) ·
  `GameOverLogic` 케이스(§3-2 목록) · `MetaProgressOps`(최고 Day 갱신 규칙 · 업적 중복
  해금 무해 · 구버전 스키마 수용). 관례대로 순수 로직만 — 파일 I/O·NetworkBehaviour는
  플레이 검증으로.
- **PlayMode**: 기존 세션 스위트 회귀(신규 PlayMode 테스트 없음 — 관례 유지).
- **플레이 검증** (MPPM 호스트 1 + 클라 1, 통합 검증 문서에 H 구역으로 편입):
