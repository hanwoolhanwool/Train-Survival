# M6 1차 구현 계획 — 재접속 (같은 플레이어로 복귀) + 후발 지형 표시

확정 대기 (아래 §1. 확정되면 구현 착수)**
(차수 편성: [M6-착수-준비.md](M6-착수-준비.md) §4 확정 — 1차 = 재접속 기반)

> **1차 목표**: **중도 이탈한 클라이언트가 재접속하면 같은 플레이어로 복귀한다** —
> 인벤토리·장비·집게 등급·생존 스탯이 끊김 시점 그대로다. **Steam 의존 0** —
> UnityTransport·MPPM 가상 플레이어로 개발·검증하고, 식별자는 계약 뒤에 격리해
> 2차에서 Steam ID로 갈아 끼운다. M3 확정 이월("재접속 시 플레이어 상태 유지")과
> M5 1차 TBD ②(H3 인벤토리 복원)가 이 차수에서 해소된다.

## 0. 범위

**코어** (재접속 축):

1. **재접속 식별** — `IPlayerIdentityProvider` 계약 신설 (개발 구현 = 로컬 영속 토큰).
   접속 페이로드로 호스트에 전달, NGO ConnectionApproval로 수신
2. **끊김 감지·상태 보존** — 호스트 `PlayerSessionRegistry`: 끊김 순간 플레이어 상태
   스냅샷을 식별 토큰으로 보관 (유예 = 세션 끝까지)
3. **복원** — 재접속 스폰 시 스냅샷을 서버 API로 재주입. 순수 구조체
   `PlayerStateSnapshot`(캡처·적용)로 EditMode 검증

**소규모**:

4. **(M4 검증 ④) 후발 접속 지형 표시 불일치** — 지역 전환 경계를 복제해 후발 피어가
   과거 구간 타일을 이전 지역 프리팹으로 생성

**비범위** (후속 차수 — [M6-착수-준비.md](M6-착수-준비.md) §4):

- Steam 트랜스포트·로비·초대·Steam ID 식별 (2차) · 게임오버/부활 규칙 확정·메타 진행
  저장 (3차)
- **호스트 재접속 / 호스트 마이그레이션** — 호스트 종료 = 세션 종료 유지 (완료 기준이
  요구하는 것은 클라이언트 복귀)
- **신규 drop-in** — 세션 시작 후 처음 보는 식별자의 접속은 현행 그대로(새 플레이어).
  준비 문서 결정 ④ 권장(복귀만 특별 취급)

## 1. 착수 전 결정 (확정 대기 — 제안값 굵게)

| # | 결정 | 제안 |
|---|---|---|
| 1 | 재접속 위치 | **기관차 갑판 스폰 지점** — 끊김 위치 복원은 이탈 칸·지상·견인 중 등 엣지가 많아 1차에서는 단순안. 위치까지 복원할 가치가 생기면 후속 |
| 2 | 사망(부활 대기) 중 끊김 → 재접속 | **부활 대기부터 재개** — 죽은 채 나갔다 들어와도 이득이 없다 (부활 시 스탯 초기화는 기존 부활 경로 그대로) |
| 3 | 개발용 식별 토큰 | **로컬 영속 GUID** (최초 실행 시 생성·저장). MPPM 가상 플레이어가 별도 저장소를 갖는지 스파이크로 확인 — 안 갖으면 실행 인자/가상 플레이어 인덱스로 분리 |
| 4 | 보존 유예 | **세션 끝까지** (준비 문서 결정 ③ 권장 그대로 — 슬롯 상한 4인이라 부담 없음) |

## 2. 설계

### 2.1 재접속 식별 — `IPlayerIdentityProvider` (Systems/Networking)

- 계약: `string LocalPlayerToken { get; }` — 세션 간 영속, 기기(플레이어) 단위.
- 개발 구현 `LocalGuidIdentityProvider`: 최초 호출 시 GUID 생성·로컬 저장. **2차에서
  `SteamIdentityProvider`로 교체되는 유일 지점** — 트랜스포트 이원화와 같은 격리 규약.
- 전달 경로: `NetworkManager.NetworkConfig.ConnectionApproval = true` +
  `StartClient` 전에 `NetworkConfig.ConnectionData`에 토큰 탑재 → 호스트
  ApprovalCallback에서 수신. **Boot 씬 NetworkManager 설정 변경 1건** (씬 배선은
  YAML 직접 편집 규약 — UnityMCP 저장 diff 회피).
- 승인 정책: 현행과 동일하게 전부 승인 (거부 사유 없음 — 슬롯 초과 등은 현행 NGO 기본).
  ApprovalCallback은 **식별 토큰 ↔ clientId 매핑 기록**이 목적이다.

### 2.2 끊김 감지·상태 보존 — `PlayerSessionRegistry` (호스트 전용)

- `NetworkManager.OnClientDisconnectCallback`(호스트)에서 despawn 전에 스냅샷 캡처:
  `token → PlayerStateSnapshot`. 호스트 자신은 대상 아님(호스트 종료 = 세션 종료).
- `PlayerStateSnapshot` (순수 구조체 — Gameplay 소속, EditMode 대상):
  핫바 슬롯(`HotbarSlotView[]` — **보따리 아이템의 보관소 id 포함, `IBundleItemStore`는
  서버 세션 상태라 세션 내 재접속에서 그대로 유효**) · 장비 4부위 · 집게 티어 ·
  체력 · 허기 · 체온 · 부활 대기 여부.
- 캡처·적용은 각 컴포넌트의 **기존 서버 API 우선 재사용**: `ServerCopySlotViews`/
  `ServerApplySlotViews`(인벤) · `ServerSetTier`(집게). 장비·체력·허기·체온에 서버
  세터가 없으면 같은 규약으로 신설 (권위 검증은 호스트 내부 호출이라 최소).

### 2.3 복원 — 재접속 스폰 훅

- 새 클라이언트 접속 → 플레이어 오브젝트 스폰 완료 시점(호스트)에 토큰으로 레지스트리
  조회 → 있으면 스냅샷 적용 + 항목 제거, 없으면 현행 초기 지급 그대로.
- 적용 순서: 슬롯·장비·티어 → 스탯 → 부활 대기(결정 2) → 위치(결정 1 — 기관차 스폰).
- 월드·열차 상태는 **복원 대상이 아니다** — NGO 후발 동기화(NetworkList·NetworkVariable)가
  원천 (가이드 §6.3 — 열차 상태 모델이 이 목적으로 설계됨). 클라 표시 재시뮬(이탈 오프셋
  등)은 스냅 시작 규약이 이미 있다 (`EnsureDisplayCapacity` — 후발 접속 워프 방지).

### 2.4 후발 지형 표시 (M4 검증 ④)

- 원인: 타일은 로컬 구동(동기화 없음)이고 지역 전환이 "이후 생성분부터 교체"라, 후발
  피어는 전 구간을 현재 지역 프리팹으로 채운다.
- 처방: **지역 전환 경계 기록 복제** — 호스트가 전환 시점의 누적 주행 거리를 목록으로
  복제(지역 수만큼 — 소량)하고, `TileStreamingLogic`이 타일 인덱스의 월드 z → 경계
  목록 → 지역을 결정한다. 타일은 계속 로컬 구동 — **복제되는 것은 경계 데이터뿐**.
- 순수 로직(인덱스 → 지역 선택)은 EditMode로 경계 고정.

## 3. 구현 순서

1. `IPlayerIdentityProvider` + 개발 구현 + ConnectionApproval 배선 (Boot 씬 1건)
2. `PlayerStateSnapshot` 순수 구조체 + 캡처/적용 + 부족한 서버 세터 보강
3. `PlayerSessionRegistry` — 끊김 캡처·재접속 적용 훅
4. 지형 경계 복제 + `TileStreamingLogic` 확장
5. EditMode(스냅샷 왕복·경계 선택) + MPPM 재접속 스모크 → 검증 문서 작성

## 4. 테스트·검증 계획

- **EditMode**: 스냅샷 캡처→적용 왕복 동등성 · 빈/가득/보따리 포함 슬롯 경계 ·
  타일 인덱스 → 지역 선택 경계.
- **재현 수단**: MPPM 가상 플레이어 중지 → 재시작 = 끊김·재접속 (결정 3 스파이크에서
  토큰 분리 확인). 검증 구성은 원칙대로 호스트 1 + 클라이언트 1.
- **검증 문서**: 구현 완료 후 `M6-1차-플레이-검증-항목.md` — M5 1차 **H3(재접속
  인벤토리 복원) 항목을 되살려** 포함하고, M4 검증 ④(지형 표시)를 재확인 항목으로 편입.
  M5 잔여 검증 56건의 편입 여부는 준비 문서 결정 ⑦에 따른다.
