## 증상

클라이언트가 뒤로 밀려가는 이탈 칸에 탑승하면 지상 자원·지형이 미세하게 떨려 보인다.
호스트에서는 같은 상황에서 떨림이 없다.

## 구조 배경 (관련 코드 지도)

| 요소 | 파일 | 역할 |
|---|---|---|
| 이탈 시뮬 (호스트) | `TrainState.ServerSimulateEjection` | 매 프레임 관성 램프·손잡이 저항으로 오프셋 적분 → `NetworkList<float>` 복제 |
| 이동 수식 (순수) | `EjectMotionMath` | 램프·저항·적분 — EditMode 테스트 대상 |
| 칸 표시 | `CarView.Update` | `ITrainState.GetEjectOffset`대로 배치 (건축물은 자식으로 따라감) |
| 손잡이 표시 | `HandrailAnchor.Update` | 같은 오프셋으로 기준 위치에서 밀어 배치 |
| 월드 스크롤 | `WorldScrollController` | 클라는 표시 거리를 "속도 적분 + 오차 지수 감쇠"로 매 프레임 부드럽게 유지 |
| 탑승 | `NetworkPlayerController` | 밟은 칸의 transform 위치 델타만큼 플레이어를 실어 나름 (무빙 플랫폼) |

**떨림의 구도**: 이탈 오프셋은 네트워크 틱(30Hz) 계단으로 복제 → 칸·플레이어(카메라)가 계단식 이동.
반면 지형·지상 자원은 월드 스크롤 표시 거리로 매 프레임 연속 이동. 이 상대 변위 진동이 떨림으로 보인다.
호스트는 시뮬 원값을 매 프레임 직접 쓰므로 떨림이 없다.

## 시도 1 — 수신 간격 기반 속도 추정 + 지수 감쇠 (`ea37ea9`)

- **접근**: 복제 값 변화량 ÷ 관측 도착 간격으로 속도를 추정하고, 그 속도로 매 프레임 외삽 + 오차를
  지수 감쇠(8/s)로 수렴. `GetEjectOffset`이 클라에서만 보간 값을 반환해 칸·손잡이·건축물이 한 소스로 부드러워짐.
  `TrainState`에 실행 순서 −150을 줘 소비자(CarView −100)보다 먼저 갱신.
- **결과**: 떨림이 크게 줄었지만 **호스트 대비 잔여 떨림**이 남음 (2026-07-31 플레이 확인).
- **잔여 원인**: 틱 도착이 **프레임 경계로 양자화**된다. 60fps에서 30Hz 틱은 보통 2프레임 간격이지만
  타이밍에 따라 1~3프레임으로 관측되어, 실제 8 m/s가 16 / 8 / 5.3 m/s로 널뛰며 추정된다.
  이 진동 속도로 외삽하니 프레임당 전진량이 ±수십% 흔들림 → 잔여 떨림.
  (검증 테스트가 완벽한 2프레임 간격을 가정해 이 결함을 놓쳤다.)

## 시도 2 — 클라 결정적 재시뮬 + 저속 드리프트 보정 (`24b8cf8`) ← 현재

- **접근**: 속도를 추정하지 말고, 클라이언트도 호스트와 **같은 수식을 같은 입력으로 매 프레임 적분**한다
  (연료 소모율과 같은 "같은 입력으로 재계산" 패턴).
  - 입력 3가지 중 스크롤 속도(복제 NetworkVariable)·설정 SO(공유)는 이미 있고,
    빠져 있던 **손잡이 잡은 인원을 `NetworkList<int>`로 복제** 추가 (판정 진실은 여전히 호스트 배열).
  - 관성 램프(`StepPushSpeed`)는 클라가 분리 관측 시점부터 로컬로 다시 밟는다 — 시작 시차에 의한
    오차는 수 cm 수준.
  - 복제 오프셋은 **드리프트 보정 목표**로만 사용: 저속 지수 감쇠(기본 3/s, `TrainDurabilitySettings`
    튜닝 필드), 오차 10 m 이상(후발 접속)은 즉시 스냅.
- **왜 이러면 떨리지 않는가**: 표시 이동이 복제 도착 타이밍과 무관해진다. 프레임당 전진량 = 재시뮬
  순 속도 × dt (+ 미세한 보정항)로 항상 매끈하고, 호스트와 같은 경로를 그린다.
- **알려진 트레이드오프**:
  - 잡기/놓기 순간 저항 반영이 복제 지연(수십 ms)만큼 늦는다 → 수십 cm 드리프트가 생겼다가
    보정률로 ~1초에 걸쳐 흡수(떨림 아닌 완만한 수렴).
  - 후발 접속으로 이탈 중인 칸을 처음 본 경우 램프를 0부터 밟아 일시 드리프트(최대 ~3 m)가
    생기며 같은 방식으로 수렴한다.
- **검증(자동)**: EditMode 149개 전체 통과. 신규 테스트 — 30Hz 계단 복제 아래서 호스트 경로 추종
  (드리프트 ±0.3 m)과 프레임 전진량 매끈함(재시뮬 속도 대비 ±0.02 m), 2인 잡기(속도 반전) 구간 포함.

## 검증 결과 (2026-08-01 · 2인 정식 테스트) — 통과

이탈 칸 자체의 떨림·정렬·후발 접속 항목은 모두 통과. 다만 **별개 경로의 증상**이 새로 관찰됐다:

- 두 플레이어가 열차 위에 있을 때 **상대(원격) 플레이어가 떨려 보인다**.
- 열차 위 **원격 플레이어의 위치가 약간 밀려 보인다**.

이탈 칸(복제 오프셋 표시) 경로가 아니라 **플레이어 복제 경로**의 문제로 추정된다 —
원격 플레이어는 `OwnerNetworkTransform`(소유자 권위, 30Hz 틱) 보간으로 표시되는 반면, 로컬
플레이어·칸·월드는 매 프레임 연속 이동하므로 같은 구도의 상대 변위 진동이 남는다. "위치 밀림"은
보간 지연 + 컨베이어 밀림(소유자 로컬 적용)의 표시 시차로 추정. **후속 분석 과제** — 착수 시
이 문서에 시도 3으로 이어서 기록한다.
