# M8 2차 플레이 검증 항목 — 낮/밤 시각 연출 (A안 + B안)

작성일: 2026-08-18 · 대상: `feat/structure-grid` (신규 브랜치 미분리) · 상태: **검증 대기**
(구현: [M8-2차-구현-계획.md](M8-2차-구현-계획.md) — 결정 ⑧~⑫ 반영.
EditMode **620/620 통과** 상태에서 시작 — 이 차수 신규 24)

> **2차 목표** (계획 문서): **낮 → 밤 전환이 한 프레임 도약이 아니라 시간의 경과로 읽힌다.**
> 게임플레이는 한 줄도 바뀌지 않았다 — 새 네트워크 상태 0, `DayPhase`·이벤트·서비스 시그니처 무변경.
> **검증 구성**: 원칙대로 **호스트 1 + 클라이언트 1** (MPPM 가상 플레이어).
> **검증 씬**: **`Game_ArtTest`** — 본편 `Game.unity` 이식은 1차 잔여로 남아 있어 이 차수의 범위가
> 아니다(결정 ⑨). 여기서 잡은 색·강도는 **이식 후 A·E 구역을 재실행**해야 한다(리스크 9).

**재현 수단**

| 시나리오 | 조작 |
|---|---|
| **모드 전환** | **F8** — `Off → A → B → Off` 순환. 숫자패드는 15키가 전부 점유돼 있어 F키를 썼다 |
| **시간 배속** | **F3** — `×1 → ×4 → ×16` 순환 (**이번 차수 신설**). ×16이면 낮 240 s → **15 s**, 밤 150 s → **9 s** |
| 밤으로 즉시 | **숫자패드 2** (저녁 = 밤 시작 경계) — 크로스페이드가 여기서 시작된다 |
| 낮으로 즉시 | **숫자패드 1** (아침 = 낮 시작 경계) |
| 다음 Day | **숫자패드 3** |
| 몬스터 없이 관찰 | **숫자패드 −** (웨이브 토글) — 밤 가시성(E 구역)을 몬스터 간섭 없이 본다 |
| 날씨 간섭 관찰 | 모래폭풍이 뜬 상태에서 숫자패드 1·2를 오간다 (C 구역) |

> **F3과 숫자패드 1·2·3의 차이가 검증에서 중요하다.** 숫자패드는 국면을 **점프**시키므로
> "전환 순간"만 볼 수 있고, F3은 **가속**이라 "국면 내내 변하는가"(A4·A7)를 볼 수 있다.
> 빨라지는 것은 시간축뿐이며 이동·전투 속도는 그대로다. **밤이 자주 오므로 웨이브가 잦아진다** —
> 조명만 격리해 보려면 숫자패드 −로 웨이브를 끄고 쓴다.

**튜닝 지점** — 마음에 들지 않는 값은 전부 `DayVisualSettings.asset`에서 고친다. **코드 수정이 필요한
항목은 하나도 없다.** 자주 손댈 값:

| 증상 | 고칠 필드 |
|---|---|
| 전환이 너무 빠르다/느리다 | `_fadeSeconds` (기본 6) |
| 밤이 너무 어둡다/밝다 | `_nightAmbientIntensity` (0.45) · `_nightAmbientSky` · `_nightSunIntensity` (0.3) |
| 밤 색이 파랗지 않다 | `_nightAmbientSky` · `_nightSunColor` |
| 정오 그림자가 너무 짧다/길다 | `_noonElevation` (80) |
| 밤 그림자가 너무 길다 | `_nightElevation` (8) 을 올린다. **0 이하로는 내리지 말 것** — 빛이 아래에서 위로 향해 그림자가 통째로 사라진다(계획 §11.5) |

## 1. 구현이 이미 수치로 확인한 것 (검증에서 다시 볼 필요 없음)

플레이 검증의 초점을 좁히기 위해, **에디터에서 실측으로 끝난 것**을 먼저 적어 둔다.

| 확인 | 결과 | 방법 |
|---|---|---|
| 환경광이 실제 화면 값에 반영된다 | 낮 probe (0.284, 0.292, 0.298) → 밤 (0.004, 0.005, 0.009) — **약 71배** 차이 | `RenderSettings.ambientProbe` 실측 |
| 밤이 청색으로 기운다 | 밤 probe에서 **B > R** (0.0093 vs 0.0040) | 〃 |
| A안과 B안이 같은 색을 쓴다 | A안 전환 중간값 == B안 일몰값 (완전 일치) | 〃 |
| 태양이 하루를 돈다 | 정오 80°/1.00 → 일몰 10°/0.55 → 한밤 **8°/0.30** | 순수 함수 산출 |
| **그림자가 태양을 따라간다** | 방향광 `Soft`·`Strength 1`, URP 셰도우맵 2048·캐스케이드 4, 렌더러 `CastShadows` 7/7 — **전부 켜져 있다.** B안이 광원을 돌리므로 방향이 그대로 따라간다 | 씬·`PC_RPAsset` 실측 |
| 밤 고도가 양수여야 한다 | 초기값 −5°에서 `forward.y = +0.087`(빛이 아래→위) → **그림자 소멸·명암 반전** 확인, **8°로 상향** | 씬 뷰 렌더 비교 |
| 경계·연속성·하한 | EditMode 21개 통과 | `DayVisualMathTests` |

**따라서 플레이 검증이 답할 질문은 "값이 맞는가"가 아니라 "보기에 맞는가"다.**

## 2. 검증 항목

### A 구역 — 전환이 시간의 경과로 읽히는가 (**완료 기준 2 · 이 차수의 본질**)

| # | 항목 | 통과 기준 |
|---|---|---|
| A1 | 모드 `A`에서 **낮 → 밤** (숫자패드 2) | 색이 **한 프레임에 튀지 않고** 수 초에 걸쳐 넘어간다 |
| A2 | 모드 `A`에서 **밤 → 낮** (숫자패드 1) | 반대 방향도 같은 느낌으로 이어진다 |
| A3 | **전환 속도** | 6초가 길지도 짧지도 않은가 — 아니면 `_fadeSeconds` 조정 후 재확인 |
| A4 | 모드 `B`에서 **국면 내내 변화가 있는가** (**F3 ×16 권장**) | 낮 중반에 가만히 서 있어도 **그림자 방향·길이가 서서히 달라진다** |
| A5 | **A와 B의 차이가 눈에 보이는가** | F8로 오갔을 때 "B가 더 시간이 흐른다"고 말할 수 있는가 |
| A6 | **B의 일몰이 읽히는가** | 낮 끝 무렵 태양이 낮아지며 주황으로 기우는 것이 보이는가 |
| A7 | **자연 전환** (국면 점프 없이, **F3 ×16**) | 낮을 그대로 흘려보냈을 때도 A1과 같은 전환이 일어난다 |
| A8 | **배속이 시간축만 바꾸는가** (F3 신설분) | ×16에서 **이동·사격·몬스터 속도는 평소와 같다** — 낮/밤만 빨라진다 |
| A9 | **Day가 바뀔 때 태양이 튀지 않는가** (계획 §11.8 수정분) | F3 ×16으로 하루를 넘겨, 자정 → 다음 아침에 **그림자 방향이 순간이동하지 않는다** |
| A10 | **태양이 한 방향으로만 도는가** | 하루 내내 그림자가 한쪽으로만 돌고 되돌아가지 않는다 |

> **A5가 이 차수의 핵심 판정이다.** B가 A와 구별되지 않으면 4차(태양 이동)를 따로 둘 이유가 없고,
> 반대로 B가 확실히 낫다면 3차 실측 뒤 기본 모드 승격의 근거가 된다(계획 §2.8).

### B 구역 — 모드 토글과 원복

| # | 항목 | 통과 기준 |
|---|---|---|
| B1 | **F8 순환** | `Off → A → B → Off`가 콘솔 로그와 함께 즉시 바뀐다 |
| B2 | **`Off`가 기준선인가** (**완료 기준 5**) | Off로 돌렸을 때 화면이 **연출 도입 전과 같다** — 하늘·환경광·태양 각도·색 전부 |
| B3 | **B → A 원복** | B에서 A로 내리면 태양이 원래 각도·색으로 돌아가고 하늘도 기본 스카이박스가 된다 |
| B4 | **왕복 안정성** | F8을 여러 번 빠르게 돌려도 값이 누적되거나 어긋나지 않는다 |
| B5 | **호스트/클라 독립** | 한쪽만 B로 두어도 **게임플레이가 갈라지지 않는다** (순수 로컬 표현) |
| B6 | 플레이 종료 후 | 에디터 씬 뷰의 조명이 원래대로다 (`OnDisable` 원복) |

### C 구역 — 날씨와의 간섭 (계획 §2.5 소유 경계)

| # | 항목 | 통과 기준 |
|---|---|---|
| C1 | **모래폭풍 중 국면 전환** | fog가 **깜빡이거나 색이 튀지 않는다** — 두 컨트롤러가 서로를 덮어쓰지 않는가 |
| C2 | 모래폭풍 종료 후 | fog가 정상 복원된다 (기존 동작 회귀 없음) |
| C3 | **모래폭풍 중 밤** (**리스크 4 — 관측 항목**) | fog 색은 날씨가 잡고 환경광만 어두워진다. **위화감이 있는지 기록만 한다** — 이 차수에서 코드로 고치지 않는다 |
| C4 | 모드 `B` + 모래폭풍 | 하늘 교체와 fog가 동시에 걸려도 이상하지 않은가 |

> **C3에서 문제가 크면 결정 ②(fog 소유권 ㉮)의 재검토 안건으로 올린다.** 지금 고치는 것이 아니라
> **다음 결정의 입력으로 남기는 것**이 이 항목의 목적이다.

### D 구역 — 게임플레이 회귀 (**완료 기준 3**)

| # | 항목 | 통과 기준 |
|---|---|---|
| D1 | 밤 웨이브 | 밤 진입에 맞춰 평소대로 스폰된다 |
| D2 | HUD 국면 표시 | Day 번호·남은 시간이 이전과 같다 |
| D3 | **디버그 국면 점프 정합** | 숫자패드 1·2·3으로 뛰었을 때 **연출이 즉시 그 국면에 맞는다** (크로스페이드가 처음부터 다시 돌지 않는가) |
| D4 | **새벽 보류** (M7 2차) | 보스전으로 밤이 붙잡혀 있는 동안 **연출도 함께 멈춰 있다** |
| D5 | **후발 접속** | 세션 중간에 들어온 클라이언트가 **현재 국면의 색을 즉시** 본다 (전환을 놓쳐 낮 색으로 시작하지 않는가) |
| D6 | 지역 전환·날씨·스탬피드 | 이전과 동일하게 동작한다 |
| D7 | 체온 | 낮/밤 환경 온도가 이전과 같다 — **연출은 온도에 영향을 주지 않는다** |

> **D3·D4·D5는 "이벤트+타이머가 아니라 진행도 파생"을 택한 이유 그 자체다**(계획 §2.1).
> 이 셋이 통과하면 그 설계 판단이 실제로 값을 했다는 뜻이다.

### E 구역 — 밤 가시성 (**리스크 3**)

| # | 항목 | 통과 기준 |
|---|---|---|
| E1 | **몬스터가 보이는가** | 밤에 다가오는 몬스터의 실루엣이 식별된다 (숫자패드 −로 웨이브만 켜고 관찰) |
| E2 | **지상 자원이 보이는가** | 집게로 겨눌 수 있을 만큼은 보인다 |
| E3 | **아군이 보이는가** | 4인 색 구분이 밤에도 유지된다 |
| E4 | **열차 위 작업이 되는가** | 제작·건설·엔진 투입 등 밤 동선이 화면 어둡기 때문에 막히지 않는다 |
| E5 | 모드 `B` 한밤 그림자 | 고도 8°에서 **그림자가 살아 있는가** — 길이가 과하지 않은가(짧게 하려면 값을 올린다) |
