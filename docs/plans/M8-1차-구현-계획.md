> **이 절은 판정 *기준*이고, *결과*는 [M8-에셋-수용-판정.md](M8-에셋-수용-판정.md)에 있다.**
> 요약: **반려 0건** · 수용 2 · 조건부 수용 8 · 미채택 3 · 폐기 1 · 미보유 3 ·
> 애니메이션 6/26 채택. 반입 전 보완 13건 중 **Blender 측 완료**, 3건은 Unity 이관(§3 단계 3).

### 1.5.1 치수 기준 — 이 프로젝트의 실측 좌표계

모델이 맞춰야 할 값은 취향이 아니라 **이미 코드·데이터가 쓰고 있는 수치**다.

| 대상 | 기준 | 출처 |
|---|---|---|
| **캐릭터 키** | **1.8 m** (캡슐 기본 높이 2 × `localScale.y` 0.9) | `Player.prefab` — `Body` |
| **캐릭터 폭** | **0.7 m** (어깨 기준) | 〃 `localScale.x/z` 0.7 |
| **캐릭터 피벗** | **발밑 (0, 0, 0)** — 루트가 발밑이고 `Body`가 `y = 0.9`로 올라가 있다 | 〃 `localPosition` |
| **열차칸 길이** | **12 m 이하** | `TrainLayoutSettings.asset` `_carLength: 12` |
| **열차칸 폭** | **3 m** | 〃 `_carWidth: 3` |
| **갑판 상면 높이** | **3 m** | 〃 `_deckHeight: 3` |
| **칸 중심 간격** | 13.5 m (길이 12 + 연결 간격 1.5) | 〃 `_couplingGap: 1.5` |
| **차륜 즉사 존** | y ≤ 1.2 m — 칸 하부 조형이 이 높이를 침범해도 판정은 무변 | 〃 `_wheelKillHeight: 1.2` |

> 열차칸 모델이 12 m를 넘으면 **연결 간격을 먹어 칸끼리 겹쳐 보인다.** 폭 3 m는 갑판 판정
> 규약(`|x| ≤ 2`)과 값이 다른데, 이는 기존 설계 사안이므로 1차에서 건드리지 않는다 —
> **모델은 `_carWidth: 3`을 따른다.**

### 1.5.2 폴리곤 밀도 기준선

| 대상 | 권장 tris | 근거 |
|---|---|---|
| TP 전신 (LOD0) | 8,000 ~ 12,000 | 아트 예산 §2 |
| FP 팔 뷰모델 | 5,000 ~ 8,000 | 〃 |
| 무기·도구 (각) | 2,000 ~ 5,000 | 〃 |
| **기관차** | **8,000 ~ 15,000** | **신규 제안** — 랜드마크성이 있고 상시 화면에 있다 |
| **일반 열차칸 (각)** | **4,000 ~ 8,000** | **신규 제안** — 4량 반복이므로 절제한다. 합계 15k + 8k×4 ≈ **47k로 캐릭터 4명(48k)과 같은 규모** |

기관차·열차칸 예산은 아트 예산 문서에 없어 **이 계획서에서 처음 제안하는 값**이다.
1차 실측(§4 A8) 후 조정한다.

**밀도 일관성이 개별 통과보다 중요하다.** 아트 예산 §3.2가 지적한 그대로다 — *"31.7 k는
세미리얼 밀도. 이에 맞춰 몬스터·열차를 만들면 기획서 §9.3의 제작비 이점이 사라진다."*
1차는 캐릭터와 열차를 **동시에** 넣는 첫 차수이므로, 캐릭터 확정 tris가 나오면 그것을
기준선으로 삼아 나머지의 상대 밀도를 맞춘다. 한 모델만 정밀하고 나머지가 거칠면 정밀한
쪽이 튄다.

### 1.5.3 반입 전 체크리스트 (Blender에서 확인)

| 축 | 확인 항목 | 실패 시 |
|---|---|---|
| **폴리곤** | 통계 오버레이의 **`Tris` 값** (Faces가 아니다 — quad면 약 2배) | 조건부 수용 → 폴리곤 조정 |
| **스케일·단위** | 1 unit = 1 m, **Apply Scale 완료**. 캐릭터 1.8 m / 칸 12×3 m (§1.5.1) | 원본에서 수정 |
| **축 방향** | FBX export = **Y-up, −Z forward** | 원본에서 수정 |
| **피벗** | 캐릭터 = 발밑 / 무기 = 그립 / 열차칸 = 바닥 중심 | 원본에서 수정 |
| **머티리얼** | 캐릭터당 1~2개. 파츠별 분할은 tris보다 비싸다 | 조건부 수용 → 아틀라스 통합 |
| **텍스처** | 2048 아틀라스 1장 (팔레트면 256²도 가능). **PBR 맵 제거 대상 확인** | 조건부 수용 → §2.2에서 처리 |
| **지오메트리 위생** | N-gon · 겹친 버텍스 · 뒤집힌 노멀 · UV 겹침 | 다수면 **반려** |

### 1.5.4 판정 3단계

| 판정 | 조건 | 처리 |
|---|---|---|
| **수용** | 체크리스트 전 항목 충족 | 그대로 반입 |
| **조건부 수용** | tris 초과 · 머티리얼 분할 · PBR 잔존 — **원본 품질 자체는 정상** | §2.2 보완 후 반입. **검토된 캐릭터 모델이 이 경로다** (결정 ④) |

"미보유 무기는 프리미티브 유지"로 정한 것과 같은 원칙이다.

## 2. 설계

### 2.1 현재 배선 — 무엇을 어디서 갈아끼우는가

| 대상 | 현재 | 위치 |
|---|---|---|
| 캐릭터 몸체 | 내장 **Capsule** (`m_Mesh` fileID 10208) | `Prefabs/Player.prefab:589` — `Body` |
| 근접 무기 | 내장 **Cube** (10202) | 〃 `:921` — `MeleePivot/Blade` |
| 총구 기준점 | 빈 Transform (메시 없음) | 〃 `Muzzle` |
| 집게 로프 | LineRenderer (연출, 메시 아님) | 〃 `Rope` |
| 기관차·열차칸 | 프리미티브 조합, **씬 직접 배치** (프리팹 아님) | `Scenes/Game.unity` — `Car_Locomotive`, `Car_1`~`Car_4` |
| 씬 전체 | MeshFilter **40개** — Cube(10202) · Cylinder(10206) · Sphere(10207) | 〃 |

**교체는 메시·머티리얼 레벨에서 끝나지 않는다** (2026-08-15 갱신 — §1.6-3). 리깅이 들어오면서
`Body`는 `MeshFilter`/`MeshRenderer`가 아니라 **`SkinnedMeshRenderer` + `Animator`** 를 갖는다.

다만 **바뀌지 않는 것이 더 중요하다** — `Body`·`Blade`는 게임플레이 코드가 Transform으로만
참조하므로, **같은 이름·같은 로컬 위치를 유지하면 스크립트 배선은 그대로다.**
**콜라이더도 메시와 분리해 현재 형상을 유지한다** — 판정을 시각 모델에 맞추는 것은 체감
조정이므로 1차에서 건드리지 않는다(M7 잔여 ⑥과 같은 성격의 결정이다).

| 구분 | 1차에서 바뀌는가 |
|---|---|
| 렌더러 종류 (`MeshRenderer` → `SkinnedMeshRenderer`) | **바뀐다** |
| `Animator` 컴포넌트 | **추가된다** (§2.6) |
| Transform 계층·이름·로컬 위치 | 무변경 |
| `CharacterController`·콜라이더 | **무변경** |
| 스크립트 참조·이벤트·네트워크 계약 | **무변경** |

> 프리팹 구조가 바뀌므로 **`GlobalObjectIdHash` 정규화가 한층 중요해진다** — 누락 시

> **LOD0 품질·예산이 곧 체감 품질**이다. 이것이 감축을 기준 초과분에만 한정한 이유다
> (결정 G). **LOD 전환 거리(15 m/35 m)의 조정은 3차 실측 후로 미룬다.**

### 2.5 열차 — 모듈 3개 연결 + 씬 YAML 직접 편집

**1칸 = `Train_CarModule` 3개**다(§1.6-1 · 판정 결정 A). 원본 종횡비가 1.4:1이라
1모델 = 1칸이 성립하지 않으며, 폭을 기준으로 잡으면 길이가 4 m가 되어 3개로 12 m를 채운다.

| 항목 | 값 | 기준 대비 |
|---|---:|---|
| 모듈 Scale Factor | **4.008** | — |
| 모듈 길이 | 4.00 m | 칸 12 m = 3개 (**오차 0**) |
| 칸 폭 | 2.92 m | `_carWidth: 3` 대비 **−2.6 %** |
| 플랫폼 상면 | 0.94 m | `_deckHeight: 3` — **하부 2.08 m 공백** |
| 칸당 tris | 6,924 | 기준 4~8 k 충족 |

하부 공백은 `Train_Wheel`(Scale 2.004 = 지름 2 m)로 채우면 차륜 중심이 1.0 m에 놓여
`_wheelKillHeight: 1.2` 안쪽에 들어온다 — **즉사 존이 시각적으로 설명된다.**
**차륜을 실제로 붙일지는 반입 후 판단**한다(판정 §3.3) — 모듈당 4륜이면 60륜 89 k로
열차 본체보다 비싸진다. **칸당 4륜(20륜)이 상한**이다.

열차칸은 프리팹이 아니라 **씬에 직접 배치**돼 있다(§2.1). 에디터로 씬을 저장하면 수천 줄
재정렬 diff가 생기므로, `Game.unity`의 해당 블록만 직접 편집한다. **편집 대상이 칸당 1개가
아니라 모듈 3개 + 차륜 N개로 늘어난다** — 5칸이면 최소 15개 블록이다.
