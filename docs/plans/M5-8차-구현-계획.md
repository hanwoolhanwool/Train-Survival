> 육안 검증 불가 — C3·C4·C5·C7·D4·E2·E4·E6·G4)이 **일괄 재검증 가능**해진다 — 판정·권위
> 경로는 이미 실증됐고 관측 수단만 없던 항목들이다. 검증 이월(7차 R5~R9·D6·F2~F5 +
> 6차 26건)은 8차 검증 문서에 편입한다.

## 1. 코어 A ① — 보따리 오브젝트

**설계 확정분** (잔여 문서 6번, 2026-08-10 결정): 회수 UX = **E창(창고 창 재사용) + 집게 운반
전용**, 칸 파괴 시 = **느린 포물선 지상 낙하**.

| 축 | 설계 |
|---|---|
| 데이터 | 풀링 NetworkObject 프리팹 + `NetworkList<NetworkSlot>` 10칸 — 창고와 **같은 슬롯 표현**이라 무기·장비도 그대로 담긴다. 스폰 직전 서버가 창고 슬롯을 이관하고 창고를 비운다 |
| E창 | 창고 창(InventoryHud)의 컨테이너 연결 — 이동 판정은 `StorageLogic.TryTransfer`가 `HotbarSlotView[]` 복사본 위에서 돌므로, 보따리 전송 RPC(거리·생존 재검증 포함)만 신설하면 병합·스왑·무기 이동이 공짜로 성립한다 (`TrainStorage.RequestTransferServerRpc` 규약 복제) |
| 집게 운반 | `IGrabbable`(Reel, `GrabWeight` 1 제안) — `TryCompleteGrab`은 항상 **Rejected**(운반 전용). 도착·해제 낙하가 **7차 안착 파이프라인을 그대로 탄다**: 갑판 위 = 휴지(+이탈 추종·소실 회수), 지상 = 월드 재바인딩 + 하강 로컬 재생 |
| 안착 재사용 | `ResourceNode`의 휴지·하강·추종·회수 로직을 보따리가 함께 쓰도록 **공용화**(베이스 클래스 또는 조립 컴포넌트 — 구현 중 판단). 스포너의 소실 칸 회수(`IsDeckAlive`)도 같은 목록에 등록 |
| 소멸 | 슬롯이 전부 비면 서버가 자동 despawn. 후방 회수 = 자원 노드와 같은 규약 (월드 프레임에서 뒤로 밀리면 회수) |
| 프리팹 등록 | **8차 유일의 신규 네트워크 프리팹** — NetworkPrefabs 목록 중복 등록 금지 · `AutoObjectParentSync` 해제 · 편집 후 GlobalObjectIdHash 정규화 확인 (풀링 프리팹 규칙) |

## 2. 코어 A ② — 생성 2지점

| 지점 | 설계 |
|---|---|
| 건축물 파괴 (칸 생존, `TrainState.cs` 건축물 파괴 확정) | 그 칸 갑판 위 **휴지 상태로 스폰** — 위치 = 칸 중심 + 갑판 높이 |
| 칸 파괴 (`TrainState.cs` 칸 파괴 확정) | 그 자리 **지상으로 느린 포물선 투척** — ⚠ 7차 학습 적용: 서버가 매 프레임 위치를 밀지 않는다. **(시작 위치, 착지 위치)를 스폰 시 복제하고 각 피어가 같은 포물선을 로컬 재생** (하강 로컬 재생과 같은 규약 — 프레임 동기화 없음 = 떨림 없음). 착지 후 월드 재바인딩 |
| 슬롯 재건 (안전망 지점) | **소실 유지** — 파괴 시점에 이미 보따리가 나왔으므로 여기서 또 내면 이중 생성 |

- 훅은 `ServerClearStorageIfPresent`의 명시 호출 3지점을 `ServerDropStorageAsBundle`(가칭)로
  확장 — 이벤트 구독이 아닌 직접 호출 유지 (누락이 코드 리뷰에서 드러나는 구조 보존)
- 내용물이 전부 빈 창고는 보따리를 내지 않는다 (빈 보따리 스폰 방지)

## 3. 코어 B — 전투 연출 (판정 무변 — 표현 계층만)

**현황** (2026-08-11 코드 조사): 트레이서 = `LineRenderer` 1개, 최근접 1줄, 0.05초 on/off
(`GunController.cs:21·151~168·310`). 탄착 표현 0. `WeaponFiredLocalEvent`는 구독자 0 (죽은
이벤트). 근접(마체테)은 표현·원격 중계 모두 0. 변종은 색·크기 필드 자체가 없어 구분 0.
사망 = `NotifyDiedRpc` 직후 즉시 디스폰 — 연출 0. 즉사 존도 같은 경로.

| 항목 | 설계 |
|---|---|
| 탄착 이펙트 | 풀링 임팩트 이펙트(비네트워크 파티클)를 `hit.point`에 로컬 스폰 — 소유자는 판정 프레임에, 원격은 발사 중계에 실어 |
| 펠릿별 트레이서 | 트레이서를 총 공유 1줄에서 **풀링 트레이서 뷰(짧은 페이드)** 로 분리 — 펠릿별 끝점 N줄. **원격 중계는 좌표 배열 대신 발사 시드 1개**: 산탄 패턴(`WeaponSpreadMath`)이 시드 결정적이므로 각 피어가 같은 펠릿 궤적을 재계산한다 (대역폭 불변·판정 무변 — 표시 전용 재계산) |
| 근접 스윙 | 스윙 표현(무기 시각의 호 궤적 트윈 — Animator 없이 코드 구동) + 타격 이펙트. **원격 중계 RPC 신설** — 총기의 `ReportFire → PlayRemoteFire` 규약과 동일 형태 (현재 근접은 원격 화면에 아무것도 안 보인다) |
| 변종 시각 구분 | `MonsterSettings`에 **색 tint·스케일** 필드 추가 — 자원 노드 종류 색과 같은 규약 (`MaterialPropertyBlock` `_BaseColor`, 전 변종 공유 프리팹 유지). 기절 노란색과의 우선순위 = 기절이 덮고, 해제 시 변종 색 복원 |
| 사망·분쇄 연출 | 즉시 디스폰 앞에 **짧은 사망 연출**(파티클 버스트, 풀링 비네트워크) — `NotifyDiedRpc`에 사망 위치·**분쇄 여부**(바퀴 존 처치)를 실어 각 피어가 로컬 재생. 분쇄는 강조 변형(부피 큰 버스트). 판정·킬 카운트 경로 무변 |
| 죽은 이벤트 정리 | `WeaponFiredLocalEvent` — 이번에 트레이서·이펙트 소비자가 생기면서 살아난다. 끝까지 소비처가 없으면 제거 (죽은 축을 남기지 않는다) |

**완료 효과**: 2차 미검 9건(C3·C4·C5·C7·D4·E2·E4·E6·G4)이 재검증 가능 — 8차 검증 문서에 편입.

## 4. 소규모 ① 버리기 수량 지정

**현황**: 버리기 RPC가 `slotIndex`만 받고 `TryClearResourceSlot`이 전량을 비운다. 수량 지정
차감 API(`PlayerInventory.ServerTryRemoveAt(slotIndex, amount)`)는 **이미 존재하나 버리기
경로가 쓰지 않는다** — 확장 지점이 명확하다.

- **조작안 (제안 — 착수 전 결정)**: 패널 밖 드롭 시 **수정자 키**로 수량 결정 —
  기본 = 전량 (현행 유지) · **Shift = 절반** · **Ctrl = 1개**. 모달 입력창 없음 (IMGUI 조작감 유지,
  안내 문구 한 줄 추가)
- 경로: `RequestDrop(slotIndex)` → `RequestDrop(slotIndex, amount)` 확장 — 서버가 요청 수량을
  슬롯 보유량으로 클램프하고, 부분 차감 + `IResourceDropper` 산포 성공 시에만 반영 (원자 규약 유지)
- 무기·장비 버리기 불가 규약 유지 (창고 보관이 처분을 흡수 — 이제 보따리도 처분 경로가 된다)
- **드롭 위치 예측 표시는 비범위 제안** — 낙하가 선로변 랜덤 산포라 예측 표시의 정보 가치가 낮다

## 5. 소규모 ② 몬스터 갑판 장애물 회피

**현황**: `ComputeDeckVelocity`가 회피 인자를 `false`/`Vector3.zero`로 하드코딩해 갑판에서는
회피 자리가 닫혀 있고, `ProbeObstacle`(전방 레이 1회, `MonsterAgent.cs:290`)은 지상 분기만 호출한다.

- `MonsterSteering.ComputeDeckVelocity`에 `(hasObstacle, obstacleNormal)` 인자 추가 —
  `ComputeGroundVelocity`와 같은 법선 회피 합산, 컨베이어 항만 없음 (갑판 = 열차 프레임)
- `MonsterAgent` 갑판 분기에서 `ProbeObstacle` 호출 (지상과 같은 탐침 재사용 — 신규 물리 없음)
- EditMode: `MonsterSteeringTests`에 갑판 회피 케이스 (법선 합산·회피 없음 회귀)
- 웨이포인트 그래프는 여전히 과하다는 기존 판단(M2) 유지 — 최소안

## 6. 소규모 ③ 이탈칸 그랩 힘 게스트 표시 (조사 → 수정)

**분석 완료분** (7차 버그 5): 저항은 서버 단일 계산 — 갈리는 것은 관측 경로 (호스트 = 권위
원값 / 게스트 = `ClientSmoothEjectionDisplay` 재시뮬). 스크롤 속도는 복제 값이라 제외.
남은 후보: ① 저항 인원 복제 지연 동안 표시 속도가 역방향 적분 → 드리프트 ② 드리프트 보정
(저속 지수 감쇠)이 느려 고무줄 현상.

1. **관측 로그 선행** — QA 키 또는 이탈 중 주기 로그로 `서버 오프셋 vs 표시 오프셋` 차를
   수치화 (검증 R9의 "세기 비교"를 육안이 아닌 수치로)
2. 원인 확정 후 수정 — 후보 ①이면 저항 인원 변화 관측 프레임에 표시 속도 즉시 재적분,
   후보 ②면 보정 속도를 저항 변화 직후에만 한시 상향 (상시 상향은 틱 계단이 다시 보이므로 금지)
3. 규모 소~중 — 수정은 표시 계층만, 판정 무변

      규약만 — "회수 기회"라는 존재 이유 보존)
