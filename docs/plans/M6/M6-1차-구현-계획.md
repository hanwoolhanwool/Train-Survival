**비범위** (후속 차수 — [M6-착수-준비.md](M6-착수-준비.md) §4):

## 2. 설계

### 2.1 재접속 식별 — `IPlayerIdentityProvider` (Systems/Networking)

- 계약: `string LocalPlayerToken { get; }` — 세션 간 영속, 기기(플레이어) 단위.
- 개발 구현 `LocalGuidIdentityProvider`: 최초 호출 시 GUID 생성·로컬 저장. **2차에서
  `SteamIdentityProvider`로 교체되는 유일 지점** — 트랜스포트 이원화와 같은 격리 규약.
- 전달 경로: `NetworkManager.NetworkConfig.ConnectionApproval = true` +
  `StartClient` 전에 `NetworkConfig.ConnectionData`에 토큰 탑재 → 호스트
  ApprovalCallback에서 수신. **Boot 씬 NetworkManager 설정 변경 1건** (씬 배선은
  YAML 직접 편집 규약 — UnityMCP 저장 diff 회피).
  - ⚠️ 혼동 주의: 현행 `NgoNetworkSessionService.StartClient`의
    `UnityTransport.SetConnectionData(address, port)`는 **주소 설정**으로, 승인
    페이로드 `NetworkConfig.ConnectionData`(byte[])와 이름만 비슷한 완전 별개다.
- 승인 정책: 기본은 전부 승인. ApprovalCallback의 목적은 **식별 토큰 ↔ clientId 매핑
  기록**이며, 두 가지를 함께 처리한다:
  1. **필수 응답 필드 설정** — 승인을 켜면 자동 스폰이 콜백 응답에 위임되므로
     `response.Approved = true` · `response.CreatePlayerObject = true`를 직접 설정해야
     현행 자동 스폰이 유지된다.
  2. **중복 토큰 처리 (결정 ⑥)** — 같은 토큰의 살아있는 연결이 있으면 기존 연결을
     동기 킥한 뒤 승인 (킥이 despawn → 스냅샷 캡처를 동기로 완료시킨다).

### 2.2 끊김 감지·상태 보존 — `PlayerSessionRegistry` (호스트 전용, **Gameplay 소속**)

- **캡처 훅 = 플레이어 컴포넌트의 `OnNetworkDespawn`(서버 분기)** —
  ~~`OnClientDisconnectCallback`~~은 쓸 수 없다. **NGO 2.13.0 실측**:
  `OnClientDisconnectFromServer`는 ① 플레이어 오브젝트 despawn/destroy → ② 소유
  오브젝트 정리 → ③ `ConnectedClients` 제거 → ④ 콜백 발사 순서라, 콜백 시점에는
  컴포넌트를 이미 읽을 수 없다. `OnNetworkDespawn`은 ①에서 호출돼 상태가 온전하다.
  - 가드 2건: `NetworkManager.ShutdownInProgress`(세션 종료·씬 전환에도 불리므로
    캡처 제외) · 플레이어 프리팹 `DontDestroyWithOwner = false` 유지(켜면 despawn이
    일어나지 않아 훅 자체가 안 불린다 — 현행 false 확인).
- **소속 = Gameplay**: 레지스트리는 `PlayerInventory` 등 Gameplay 타입을 직접 캡처해야
  하는데 `Game.Systems`는 `Game.Gameplay`를 참조할 수 없다(단방향). 외부 노출이
  필요하면 Core 인터페이스 + `ServiceLocator` 역방향 등록(기존 `IBundleItemStore`
  방식)을 따른다. 호스트 자신은 대상 아님(호스트 종료 = 세션 종료).
- `PlayerStateSnapshot` (순수 구조체 — Gameplay 소속, EditMode 대상):
  핫바 슬롯(`HotbarSlotView[]` — **보따리 아이템의 보관소 id 포함, `IBundleItemStore`는
  서버 세션 상태라 세션 내 재접속에서 그대로 유효**) · 장비 4부위 · 집게 티어 ·
  체력 · 허기 · 체온 · 부활 대기 여부 · **사망 확정 시각**(잔여 대기 계산 — 결정 ⑦).
  버프는 제외(결정 ⑤).
- 캡처·적용 서버 API — **실측 결과, 재사용 가능한 것은 2건뿐이고 나머지는 신설**:
  - 재사용: `ServerCopySlotViews`/`ServerApplySlotViews`(인벤) · `ServerSetTier`(집게)
  - 신설 — 장비: private `CopyEquipment`/`ApplyEquipment`의 public 서버 래퍼
    (`RequestEquip` 계열은 IsOwner 게이트라 서버 호출 불가)
  - 신설 — 체력: 절대값 세터 (`ServerHeal`은 증가 전용 + `IsAlive` 게이트)
  - 신설 — 허기·체온: 절대값 세터. **`_serverHunger`/`_serverTemperature` private
    미러가 진짜 원본**이라 NetworkVariable만 쓰면 다음 프레임 `Update`가 되돌린다 —
    미러까지 함께 쓰는 API여야 한다
  - 신설 — 부활 대기: 서버 설정 API + **서버 → 소유자 부활 재개 지시 RPC**
    (`BeginOwnerRespawn`은 IsOwner 가드, 기존 재개 RPC는 전부 private). 호스트가
    사망 확정 시각을 기록하는 코드도 신설(현행 카운트다운은 소유자 코루틴에만 존재)

### 2.3 복원 — 재접속 스폰 훅

- 새 클라이언트 접속 → 플레이어 오브젝트 스폰 완료 시점(호스트)에 토큰으로 레지스트리
  조회 → 있으면 스냅샷 적용 + 항목 제거, 없으면 현행 초기 지급 그대로.
  - 순서 주의: `PlayerInventory.OnNetworkSpawn`이 서버에서 **무조건** 초기 지급
    (`_slots.Clear()` 후 재구성)을 실행한다 — 스냅샷 적용은 반드시 그 이후여야 한다.
- 적용 순서: 슬롯·장비·티어 → **부활 대기 분기** —
  - 부활 대기 중이었으면: **스탯 복원 생략** (사망 중에는 허기·체온이 매 프레임
    최대치/정상치로 강제 리셋되고 세터도 `IsAlive` 게이트에 막힌다 — 복원해도
    즉시 무효화되며, 부활 시 기존 경로가 스탯을 초기화하므로 결정 ②와 정합)
    → 잔여 대기 시간 계산(결정 ⑦) → 부활 재개 지시 RPC.
  - 생존 중이었으면: 스탯(체력·허기·체온) 복원.
- **위치는 서버 재주입이 아니다** — `OwnerNetworkTransform`이 소유자 권위라 서버 값은
  소유자가 덮어쓴다. 현행 소유자 배치 경로(Game 씬 도착 후
  `GetSpawnPosition` 셀프 텔레포트)가 이미 기관차 갑판이라 결정 ①은 자동 충족.
  단 스폰 인덱스 밀림은 수정한다(§0 소규모 5).
- 월드·열차 상태는 **복원 대상이 아니다** — NGO 후발 동기화(NetworkList·NetworkVariable)가
  원천 (가이드 §6.3 — 열차 상태 모델이 이 목적으로 설계됨). 클라 표시 재시뮬(이탈 오프셋
  등)은 스냅 시작 규약이 이미 있다 (`EnsureDisplayCapacity` — 후발 접속 워프 방지.
  단 이 규약은 열차 이탈 표시 전용이고, 지형 쪽 대응물은 `WorldScrollController`의
  `_displayDistance` 스냅뿐이다).

### 2.4 후발 지형 표시 (M4 검증 ④)

- 원인: 타일은 로컬 구동(동기화 없음)이고 지역 전환이 "이후 생성분부터 교체"라, 후발
  피어는 전 구간을 현재 지역 프리팹으로 채운다.
- 처방: **지역 전환 경계 기록 복제** — 호스트가 전환 경계를 복제하고,
  `TileStreamingLogic`이 타일 인덱스 → 경계 목록 → 지역을 결정한다. 타일은 계속
  로컬 구동 — **복제되는 것은 경계 데이터뿐**. 실측 반영 4건:
  1. **경계는 float 거리가 아니라 int 타일 인덱스로 기록** — 전환 순간 전방
     `TilesAhead`장(5 × 40 m = 200 m)이 이미 구 프리팹으로 생성돼 있어, 전환 시점
     거리를 그대로 쓰면 실제 경계보다 200 m 앞당겨진다. 새 프리팹이 처음 적용되는
     인덱스 = `floor(D/L) + TilesAhead + 1`을 기록한다.
  2. **복제 소유자 = `WorldScrollController`**(NetworkBehaviour + 주행 거리 소유)에
     `NetworkList` 배선 — 전환을 판정하는 `RegionController`는 MonoBehaviour라
     NetworkList를 가질 수 없다.
  3. **트림 규칙** — `_loopAfterLastRegion: 1`(순환)이라 경계가 "지역 수만큼"이 아니라
     세션 시간에 비례해 누적된다. 후방 가시 구간(`TilesBehind × TileLength`) 밖으로
     지나간 경계는 잘라낸다.
  4. **기존 타일 재판정 경로 신설** — `TerrainTileStreamer.ApplyRegion`은
     `_activeTilePrefab`만 바꿀 뿐 이미 깔린 타일은 손대지 않는다. 경계 목록 수신
     시점에 기존 타일을 인덱스별로 재판정해 어긋난 것을 교체(despawn → 재spawn)한다.
- 순수 로직(인덱스 → 지역 선택)은 EditMode로 경계 고정.

## 3. 구현 순서

1. `IPlayerIdentityProvider` + 개발 구현 + ConnectionApproval 배선 (Boot 씬 1건 +
   승인 응답 필드·중복 토큰 킥 — 결정 ⑥)
2. 서버 세터 신설 (§2.2 실측 목록: 장비 래퍼 · 체력/허기/체온 절대값 · 부활 재개 RPC ·
   사망 시각 기록) + `PlayerStateSnapshot` 순수 구조체 + 캡처/적용
3. `PlayerSessionRegistry` — `OnNetworkDespawn` 캡처·재접속 적용 훅 + 스폰 인덱스
   밀림 보정 (§0 소규모 5)
4. 지형 경계 복제 (타일 인덱스 기록·트림·`WorldScrollController` 배선) +
   `TerrainTileStreamer` 재판정 경로 + `TileStreamingLogic` 확장
5. EditMode(스냅샷 왕복·경계 선택) + MPPM 재접속 스모크 → 검증 문서 작성

## 4. 테스트·검증 계획

- **EditMode**: 스냅샷 캡처→적용 왕복 동등성 · 빈/가득/보따리 포함 슬롯 경계 ·
  타일 인덱스 → 지역 선택 경계(`+TilesAhead+1` 오프셋 포함) · 잔여 대기 시간 계산
  (잔여 ≤ 0 → 즉시 부활 — 결정 ⑦).
- **재현 수단**: MPPM 가상 플레이어 중지 → 재시작 = 끊김·재접속 (결정 ③ 스파이크에서
  토큰 분리 확인). 유령 연결 킥(결정 ⑥)은 타임아웃 전 빠른 재접속으로 재현. 검증
  구성은 원칙대로 호스트 1 + 클라이언트 1.
- **검증 문서**: 구현 완료 후 `M6-1차-플레이-검증-항목.md` — M5 1차 **H3(재접속
  인벤토리 복원) 항목을 되살려** 포함하고, M4 검증 ④(지형 표시)를 재확인 항목으로 편입.
  M5 잔여 검증 56건의 편입 여부는 준비 문서 결정 ⑦에 따른다.
