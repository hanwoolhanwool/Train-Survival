## A. 재접속 복귀 — 인벤토리·장비·집게·스탯 (M5 1차 H3 되살림)

- [0] **A3** **집게 등급**이 그대로다 (HUD 표기 + 상위 무게 그랩 가능)

- [0] **F4** 세션을 완전히 종료하고 **새 세션**을 시작하면 이전 세션의 스냅샷이 새어 들어오지
      않는다 — 새 세션 첫 접속은 초기 지급 (보존 유예 = 세션 끝까지, 결정 ④)
- [0] **F5** 재접속 후 이동·그랩·사격·제작·창고 등 기존 조작이 정상이다 (스모크)
- [0] **F6** Boot 씬 ConnectionApproval 활성화 후에도 기존 씬 전환(Main → Game)·클라 동기화가
      정상이다 (회귀)

## G. Steam 통합 (2차 — 로비·초대·릴레이·Steam ID 재접속)

**준비물** (준비 문서 §5): Steam 테스트 계정 2개(프렌드 관계), 두 번째 PC 또는 같은 PC의
두 번째 Steam 계정 실행 환경. 완료 기준 검증은 **외부 네트워크의 다른 회선 PC 1대** 필요.
에디터 Steam 모드 = 메뉴 `Game/Steam Transport (Editor)` 체크(플레이 전), 빌드 = `-steam`
인자. 스모크 중 Steam 프로필에 "Spacewar 플레이 중"으로 표시된다 (임시 AppID 480 — 정상).

- [ ] **G1** Steam 모드로 "호스트 시작" → 세션이 열리고 콘솔에 로비 생성 로그
      (`[SteamLobbyService] 친구 전용 로비 생성: …`)가 남는다 — *에디터 단독 스모크는 구현
      세션에서 통과 (2026-08-12), 여기서는 2인 구성으로 재확인*
- [ ] **G2** Esc 메뉴 "친구 초대 (Steam 오버레이)" → 오버레이 초대 창이 열리고 친구에게
      초대가 간다
- [ ] **G3** **게임 실행 중** 초대 수락 → 게스트가 로비 참가 → 자동으로 릴레이 접속 →
      Game 씬 동기화까지 이어진다
- [ ] **G4** **게임 미실행** 상태에서 초대 수락 → 게임이 `+connect_lobby`로 부팅되고 Steam
      모드로 자동 참가한다 (빌드 전용 — 에디터는 해당 없음)
- [ ] **G5** 릴레이 세션에서 기본 플레이 스모크 — 이동·그랩·사격·인벤토리가 UnityTransport와
      동일하게 동작한다
- [ ] **G6** **Steam ID 재접속** — 게스트 강제 종료 후 재초대/재참가 → A 구역과 동일하게
      같은 플레이어로 복귀한다 (토큰 = SteamID64, 1차 축 무수정 확인)
- [ ] **G7** 게스트 이탈 후에도 호스트 로비가 유지되고, 세션 종료(Esc — 세션 나가기) 시
      로비 이탈 로그가 남는다
- [ ] **G8** **완료 기준**: 외부 네트워크의 친구와 릴레이로 세션을 시작해 완주(낮·밤 사이클
      1회 이상)한다 + 중도 이탈 → 재접속 복귀 확인
- [ ] **G9** 회귀: Steam 토글/인자 없이 실행하면 기존 UnityTransport 흐름(메뉴·MPPM·직결
      접속)이 그대로다
* 한 컴퓨터로 테스트해볼 방법 추천해줘.
  → *답변 (2026-08-13): Steam은 한 PC에서 클라이언트를 1개만 띄울 수 있어 두 계정을 함께
  쓰려면 격리가 필요하다. 권장 순서:*
  1. ***가상 머신 1대** (권장 — VirtualBox/VMware + Windows 평가판): VM 안에 Steam을 설치해
     **두 번째 계정**(본 계정과 프렌드)으로 로그인하고, 게임 **빌드 폴더**(steam_appid.txt
     포함)를 VM에 복사해 실행. 본편(호스트, 에디터 Steam 토글 또는 빌드 `-steam`)에서 로비
     생성 → Esc 초대 → VM 쪽에서 수락 → G1·G2·G3·G5·G6·G7 전부 확인 가능. 릴레이(SDR)는
     NAT 안 VM에서도 붙는다.*
  2. ***G4(`+connect_lobby` 부팅)는 AppID 480의 한계**로 초대 수락 시 Steam이 우리 exe가
     아니라 **진짜 Spacewar를 실행**하려 든다 — 자체 AppID 전까지는 "게임 미실행 수락" 대신
     로비 id를 로그에서 읽어 `게임.exe +connect_lobby <로비id>`로 **수동 실행**해 대체 검증한다.*
  3. ***G8(완료 기준)만은 대체 불가** — 외부 네트워크(다른 회선)의 실제 PC 1대가 필요하다.
     노트북 + 휴대폰 테더링으로도 충분하다.*

## H. 수명 주기 규칙 (3차 — 게임오버·부활 Day 비례·메타 저장)

전멸을 만들 때는 체온·이탈(후미 40 m 낙오)로 죽거나 몬스터에게 맞는다. Day 비례 확인은
넘패드 3(다음 Day)으로 Day를 올린 뒤 사망 시점의 대기 시간을 잰다. 구성은 호스트 1 +
게스트 1 (MPPM).

- [ ] **H1** **전원 사망 → 게임오버**: 호스트·게스트가 모두 죽으면 양쪽에 "전멸 — 게임오버"
      오버레이가 뜨고, **도달 Day·생존 시간이 양쪽에서 같다** (호스트 권위 값). 각자
      "메인 화면으로"로 복귀하고, 호스트 콘솔에 전멸 확정 로그가 남는다
- [ ] **H2** **1명 생존 시 게임오버 없음**: 게스트만 사망 → 게임오버가 뜨지 않고 게스트는
      대기 후 부활한다 (기획서 §9.1 — 팀원 1명 이상 생존 시 부활)
- [ ] **H3** **부활 대기 Day 비례** (3차 결정 ① — M2 미결 해소): Day 1 사망 = 5초,
      넘패드 3으로 Day를 올린 뒤 사망 = Day당 +1초 (예: Day 4 = 8초). **이탈 사망**(후미
      40 m)도 같은 시간이다 — 5초 고정이 아님 (일원화 확인)
- [ ] **H4** **마지막 생존자 끊김** (3차 결정 ②): 게스트(유일 생존자)를 강제 종료 →
      남은 접속자(호스트)가 사망 상태면 **게임오버가 뜬다** (끊긴 자는 판정 제외 — §2.3)
- [ ] **H5** **종단 가드**: 부활 대기 중 게임오버가 확정되면 대기자는 **부활하지 않는다**
      (카운트다운이 끝나도 죽은 상태 유지 — 전멸이 뒤집히지 않음)
- [ ] **H6** **게임오버 후 재접속**: 게임오버 확정 뒤 게스트가 재접속 → **같은 게임오버
      화면**(같은 Day·시간)이 뜬다 (NetworkVariable 후발 동기화)
- [ ] **H7** **메타 진행 기록** (3차 결정 ③): 게임오버 후 호스트·게스트 **각자의** 메타
      파일(0. 기준 수치 표 경로)에 bestDayReached·totalGameOvers가 갱신되고
      `first_game_over`(+Day 3 이상이면 `reach_day_3`)가 unlockedAchievements에 있다.
      같은 파일로 다음 게임오버 시 **횟수 누적 + 최고 Day 유지**(더 낮은 Day로 죽어도)
- [ ] **H8** **Steam 업적 미러 스모크** (결정 ③ — 에디터 Steam 모드): 게임오버 시
      콘솔에 미러 로그(0. 사전 준비)가 남고 Steam 오버레이에 Spacewar 테스트 업적
      (`ACH_WIN_ONE_GAME`)이 해금된다 — **임시 매핑, 자체 AppID 발급 시 교체**
- [ ] **H9** 회귀: 게임오버 오버레이 중 Esc 세션 메뉴가 열리지 않고, 호스트가 먼저 나가도
      남은 피어의 화면이 "세션 종료" 오버레이로 바뀌지 않는다 (게임오버 화면 유지 →
      같은 버튼으로 복귀)
