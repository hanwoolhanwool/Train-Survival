사용자 결정: 제안대로) — 구현 착수**
(차수 편성: [M6-착수-준비.md](M6-착수-준비.md) §4 — 2차 = Steam 통합.
검증 방식: **1차와 통합해 한 번에** — 사용자 지시 2026-08-12)

> **2차 목표**: **Steam 릴레이로 세션을 열고, 친구를 초대해 접속하며, 재접속 식별이
> Steam ID로 갈아 끼워진다**. 1차의 재접속 축은 재작업하지 않는다 —
> `IPlayerIdentityProvider` 구현 교체 + 트랜스포트 스위칭만으로 그대로 탄다 (1차 격리 규약).
> 개발·CI·MPPM은 계속 UnityTransport 직결 (불변 지침).

## 0. 범위

**코어**:

1. **패키지 도입** — Steamworks.NET 2025.164.1 (UPM git) + `steam_appid.txt`(임시 AppID 480)
2. **트랜스포트 벤더링** — 커뮤니티 NGO Steam 트랜스포트 소스를 프로젝트 안
   (`Systems/Networking/Steam/`)에 벤더링, NGO 2.13에 맞게 수선·유지 (결정 ①)
3. **모드 결정·이원화** — 실행 인자 `-steam` + 에디터 토글(메뉴)로 Steam 모드 활성 (결정 ②).
   세션 서비스가 시작 직전 `NetworkConfig.NetworkTransport`를 스위칭 — 분기점은
   `NgoNetworkSessionService` 한 곳
4. **Steam 수명 주기** — Steam 모드에서만 `SteamAPI.Init`(AppID 480)·콜백 펌프·종료 처리
5. **로비/초대** — 친구 전용(FriendsOnly) 4인 로비 (결정 ③): 호스트 시작 = 세션 + 로비 생성,
   오버레이 초대, 초대 수락 → 로비 참가 → 로비 데이터의 호스트 SteamID로 릴레이 접속.
   게임 미실행 초대 수락(`+connect_lobby` 인자)도 처리
6. **Steam ID 식별** — `SteamIdentityProvider`(토큰 = SteamID64)로 1차 계약 교체 배선.
   Steam 모드일 때만 등록 — UnityTransport 모드는 기존 로컬 GUID 그대로
7. **UI 최소 배선** — Main 메뉴 Steam 분기(로비 호스트·초대 버튼), 세션 종료 시 로비 이탈

**비범위** (3차·후속):

- 게임오버/부활 규칙·메타 진행 저장 (3차) · 자체 AppID 발급 (릴리스 전 별도)
- 신규 drop-in 허용 정책 변경 (1차 비범위 유지 — 준비 문서 결정 ④ 1안)
- 승인 페이로드 SteamID의 암호학적 검증(Auth Ticket) — 친구 전용 로비 전제로 후속 검토 항목

## 2. 설계

### 2.1 모드 결정 — `NetworkTransportMode` (Systems/Networking)

- `enum NetworkTransportMode { UnityDirect, SteamRelay }` + 정적 리졸버:
  실행 인자에 `-steam` 포함 → SteamRelay (순수 파싱 함수 — EditMode 대상).
  에디터는 메뉴 토글(`Game/Steam Transport (Editor)`, EditorPrefs)로 강제 가능.
- 게임 미실행 초대 수락 시 Steam이 `+connect_lobby <id>`를 붙여 실행한다 —
  이 인자가 있으면 모드도 SteamRelay로 간주하고 부팅 후 자동 참가한다.

### 2.2 트랜스포트 이원화 — `NgoNetworkSessionService` 확장

- Boot 씬 NetworkManager에 **두 트랜스포트 컴포넌트 공존** (UnityTransport 기존 +
  벤더링 Steam 트랜스포트 추가 — 씬 YAML 직접 편집).
- `StartHost`/`StartClient` 직전에 모드에 따라 `NetworkConfig.NetworkTransport`를 지정.
  Steam 모드의 `StartClient(address, port)`는 **address = 호스트 SteamID64 문자열**로
  재해석한다 (포트 무시) — `INetworkSessionService` 계약 변경 없음.
- 1차 재접속 배선(ConnectionData 토큰·승인 콜백·중복 킥)은 트랜스포트 무관 — 그대로 동작.

### 2.3 Steam 수명 주기 — `SteamService` (Systems/Networking/Steam)

- Steam 모드에서만: `SteamAPI.Init()`(steam_appid.txt = 480 필요 — 저장소에 포함,
  에디터·빌드 옆) → 실패 시 명확한 로그 + UnityTransport 폴백은 하지 않는다(모드 명시가
  원칙 — 실패는 실패로 보이게). 콜백 펌프는 부트스트래퍼가 만드는 드라이버
  MonoBehaviour(DontDestroyOnLoad)의 Update에서 `SteamAPI.RunCallbacks()`.
- 종료: `OnApplicationQuit` → `SteamAPI.Shutdown()`.

### 2.4 로비/초대 — `SteamLobbyService` (Systems/Networking/Steam)

- 호스트: `StartHost` 성공 후 `CreateLobby(FriendsOnly, 4)` → `LobbyCreated_t`에서
  로비 데이터 `host_steam_id` 기록. 초대 = `ActivateGameOverlayInviteDialog(lobbyId)`.
- 참가: `GameLobbyJoinRequested_t`(실행 중 초대 수락/친구 목록 참가) → `JoinLobby` →
  `LobbyEnter_t` → `host_steam_id` 조회 → `session.StartClient(hostId, 0)`.
  게임 미실행 수락은 `+connect_lobby <id>` 인자로 부팅 직후 같은 흐름.
- 세션 종료(Shutdown)·호스트 이탈 시 `LeaveLobby`. 재접속(1차 축)은 같은 로비로 다시
  참가하면 된다 — 로비가 세션과 함께 살아 있다.

### 2.5 Steam ID 식별 — `SteamIdentityProvider`

- `LocalPlayerToken => SteamUser.GetSteamID().m_SteamID.ToString()` — 세션 간 영속·기기
  단위라는 1차 계약을 자동 충족 (Steam 계정 = 플레이어).
- 등록 분기: 부트스트래퍼가 Steam 모드면 `SteamIdentityProvider`, 아니면 기존
  `LocalGuidIdentityProvider`를 `IPlayerIdentityProvider`로 등록. **1차 코드 무수정** —
  계약 교체 지점이 설계대로 한 곳임을 이 배선이 증명한다.
- 알려진 한계(비범위): 승인 페이로드의 SteamID는 자기 신고 — 친구 전용 로비 전제로
  수용, Auth Ticket 검증은 후속 검토.

### 2.6 UI — Main 메뉴 Steam 분기 (`MainMenuController`)

- Steam 모드일 때: "호스트 시작" = 세션 + 로비 생성 · "친구 초대(오버레이)" 버튼(세션 중) ·
  직접 주소 접속 버튼 숨김(참가는 오버레이 경유). UnityTransport 모드 UI는 현행 유지.

## 3. 구현 순서

1. Steamworks.NET UPM 도입 + `steam_appid.txt`(480) + **에디터 스파이크**: Init·로비
   생성·데이터 왕복 확인 (Steam 클라이언트 실행 중 확인 완료 — 프로필에 Spacewar 표시됨)
2. 커뮤니티 트랜스포트 벤더링 + NGO 2.13 수선 + Boot 씬 컴포넌트 추가 (YAML)
3. `NetworkTransportMode` 리졸버 + 세션 서비스 트랜스포트 스위칭 + `SteamIdentityProvider`
   등록 분기
4. `SteamService`(Init·콜백 펌프·종료) + `SteamLobbyService`(생성·초대·참가→접속·이탈)
5. Main 메뉴 Steam 분기 + EditMode(인자 파싱·모드 결정) + **1차+2차 통합 검증 문서**
   (1차 문서를 대체하지 않고 2차 항목을 추가 편입한 통합본)

## 4. 테스트·검증 계획 — **1차와 통합, 한 번에** (사용자 지시)

- **자동**: EditMode(모드 결정·인자 파싱 + 1차 스위트 회귀) · PlayMode(기존 세션 스위트 —
  UnityTransport 경로 회귀).
- **에디터 Steam 스모크 (이 세션에서 수행)**: Init → 로비 생성 → 로비 데이터 확인 →
  로비 이탈 — 단일 인스턴스로 확인 가능한 범위.
- **사용자 통합 플레이 검증**: `M6-1차-플레이-검증-항목.md`의 A~F (UnityTransport·MPPM)
  + 2차 신규 G 구역(Steam: 로비·초대·릴레이 접속·Steam ID 재접속 — 2계정/2대 필요,
  준비물 체크리스트는 준비 문서 §5). 완료 기준 검증(외부 네트워크)도 이 세션에서 겸한다.
