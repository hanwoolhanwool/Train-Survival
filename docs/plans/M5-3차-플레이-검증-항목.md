## A. 건축물 종류화 (설치 UX·복제)

- [x] **A1** 망치로 칸을 겨누면 "우클릭 {종류명} 설치 (소모: …) [R] 종류 변경"이 뜬다
- [x] **A2** **R 키로 4종 순환** — 온실 돔 → 난방기 → 공유 창고 → 제작대 → 돔. 종류마다 비용 표시가 바뀐다 (창고만 4)
- [x] **A3** 4종을 서로 다른 칸에 설치 → **외형이 서로 다르다** (돔 구형 / 난방 실린더 / 창고 상자 / 제작대 납작)
- [x] **A4** 게스트 화면에서도 같은 칸에 같은 종류의 외형이 보인다 (Kind 복제)
- [x] **A5** 설치 배너가 종류명으로 뜬다 — "난방기 설치! (#n번 칸)"
- [x] **A6** 파괴된 자리(숫자패드 6 반복)에 **다른 종류**를 새로 지을 수 있다
- [x] **A7** 몬스터가 새 종류 건축물도 공격한다 (밤 웨이브 — 표적 등록 회귀)
- [x] **A8** 수리 망치 좌클릭 수리가 4종 모두에 동작한다

**Q. 몬스터가 새 건축물을 관통하는데 의도된 설계인가?** — 코드 확인 결과, **의도된 단순화가 맞다
(버그 아님)**. 몬스터 이동은 물리 충돌 해소 없는 transform 직이동이고, 갑판 위 조향
(`MonsterSteering.ComputeDeckVelocity`)은 장애물 회피 없이 목표 직선 추격이다 (장애물 레이캐스트
회피 `ProbeObstacle`은 **지상 이동에만** 적용). M2~M3에는 갑판에 장애물이 없어 문제가 없었으나,
M5에서 건축물이 갑판에 생기며 관통이 보이게 된 것 — 갑판 장애물 회피는 "개선 방향"에 등재.

## B. 난방·체온 (사막 밤 2℃ 복원)

- [ ] **B1** 사막(Day 6+) 밤 노숙 → 체온이 계속 내려가 **34 ℃ 밑에서 지속 피해** (2 ℃ 복원 확인) — **이월**: 밤 노숙이 몬스터 간섭으로 실플레이 검증 곤란

- [x] **B3** **난방기 칸 위**로 올라가면 체온이 회복으로 돌아선다 (실효 17.2 ℃)
- [x] **B4** 난방기 칸은 **사막 낮 더위를 막지 못한다** (그늘 아님 — 돔과 역할 분리)
- [x] **B5** 돔 칸은 여전히 낮 더위만 막고 밤 추위를 못 막는다 (기존 계약 유지)
- [ ] **B6** 난방기가 파괴되면 즉시 완화가 사라진다 (체온 다시 하락) — **이월** (B1과 동일 사유)
- [ ] **B7** 게스트도 B1~B3 동일 (체온은 호스트 권위 — 서버 계산 정합) — **이월** (B1과 동일 사유·B3 부분은 통과)

**Q (B4). 실효 온도는 사막 온도 + 난방기 온도인가?** — **아니다, 덧셈이 아니라 보간이다**.
`TemperatureMath.ResolveAmbient`는 환경 온도가 쾌적 하한(10 ℃) **밑일 때만** 쾌적대 중심(21 ℃)
쪽으로 heaterFactor(0.8)만큼 당긴다: 사막 밤 2 ℃ → Lerp(2, 21, 0.8) = **17.2 ℃**. 사막 낮 45 ℃는
하한 밑이 아니므로 난방기는 아무 효과가 없다 (B4가 성립하는 이유). 그늘(돔)은 반대로 쾌적 상한(32 ℃)
초과일 때만 같은 방식으로 당긴다.

*개선 제안 (검증 중 관찰)*: 사막이 아닌 다른 지형에서도 옷·난방의 온도 영향이 체감되면 좋겠다
(예: 온대 지형에서 보온복 착용 시 더위 역효과) → "개선 방향"에 등재.
