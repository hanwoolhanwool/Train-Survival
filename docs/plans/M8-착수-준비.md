> 밸런스·연출 수치는 전부 데이터(SO)로 뺀다.

## 0. 이 문서가 만들어진 경위

2026-08-15 세션에서 **"낮과 밤이 갑작스럽게 바뀐다 — 시간이 흘러간다는 표현이 없다"** 는
관찰이 출발점이었다. 조사 결과 시각 연출이 미구현이라는 것과, 그보다 먼저 **비출 대상 자체가
프리미티브**라는 것이 확인되어 **"에셋과 연출 중 무엇을 먼저 하는가"** 가 실제 결정 사항이
됐다. 이 문서는 그 판단과 실행 순서를 담는다.

### 1.1 이 스냅샷이 해소한 기존 미결

아트 예산 문서 §8의 **"타일 프리팹당 오브젝트 개수"** 가 미확정으로 남아 있었고, §6의

## 2. 순서 결정 — 에셋이 먼저다

**결론: 에셋 적용 → 연출 A안 → 렌더 실측·조정 → 연출 B안.**

| 근거 | 내용 |
|---|---|
| 산출물의 성격 | 조명 연출의 산출물은 **색·명암·그림자 튜닝값**이다. 캡슐 위에서 잡은 값은 실제 모델이 들어오는 순간 다시 잡아야 한다 — 재작업이 가능성이 아니라 확정이다 |
| 의존의 방향 | 에셋 적용은 조명의 미확정 변수(그림자 캐스터 수·머티리얼 수·LOD 단계)를 **확정시킨다.** 역방향 이득은 없다 |
| 결정 상태 | 에셋 적용은 아트 예산 문서 §3.3에서 처리 방침이 **이미 결정된** 작업이고, 조명은 아직 선택지 단계다 |

### 2.1 예외 — A안은 에셋과 병행해도 된다

A안(전환 크로스페이드)이 정하는 값은 색이 아니라 **전환 시간(몇 초에 걸쳐 바꿀 것인가)** 이다.
이 값은 프리미티브 위에서 정해도 실제 모델로 바뀐 뒤 그대로 유효하다.
B안(태양 각도·하늘 색 곡선·강도)은 재질과 노멀 위에서만 판단이 서므로 **반드시 에셋 후**다.

### 2.2 A안 · B안 정의

| | 내용 | 그림자맵 재생성 | 오브젝트 수 민감도 |
|---|---|---|---|
| **A안** | 국면 전환 시 ambient(·fog) 색을 수 초에 걸쳐 보간 | 없음 | **없음** — 오브젝트가 몇 개든 비용 동일 |
| **B안** | 국면 진행도로 태양 각도·색·강도를 상시 보간 | **매 프레임** | **있음** — 캐스터 수 × 캐스케이드 배수 |

B안이 A안을 거의 포함하므로 **파일 2개가 아니라 컨트롤러 1개 + 모드 필드**로 만든다(§4 2차).

## 3. 범위

**포함**

1. 캐릭터·무기·기관차·열차칸 모델 적용 (LOD 생성 + 머티리얼 통합 포함)
2. 낮/밤 시각 연출 A안 — 전환 크로스페이드 + 모드 토글
3. 렌더 설정 실측·조정 — 아트 예산 문서 §7 실행 항목 1·2·4
4. 낮/밤 시각 연출 B안 — 태양 이동·하늘 색

**비포함 (M8에서 다루지 않는다)**

- `DayPhase` 국면 세분화(황혼·새벽) — 웨이브·보스·날씨·스탬피드 구독자 전부가 영향권이다.
  게임플레이 계약을 건드리므로 연출 목적으로는 채택하지 않는다
- 열차 전조등·모닥불 등 **점광원 추가** — 밤 밝기 설계와 묶이는 별도 축(§8 리스크 2)
- 몬스터·보스·자원·건축물 모델 (결정 ⑤에서 편입 여부 판단)
- 애니메이션·리깅 — 모델 적용과 별개 축
- 사운드·UI 아트

## 4. 차수 분할 (제안)

### 1차 — 에셋 적용

| 항목 | 내용 |
|---|---|
| 대상 | 캐릭터(FP 팔 / TP 전신) · 무기 · 기관차 · 열차칸 4량 (결정 ⑤) |
| 예산 기준 | FP 팔 5~8 k / TP 전신 8~12 k / 무기 각 2~5 k tris (아트 예산 §2) |
| **임포트 전 보완** (결정 ④) | 상태 점검 → 폴리곤 조정 → PBR 제거. **반입 전에 실제 `Tris` 값을 확정**한다 — 31.7 k는 quad 해석에 근거한 추정이다(아트 예산 §3.1) |
| 필수 부수 작업 | LOD 3단(원본 / 50 % @15 m / 25 % @35 m) · 캐릭터당 머티리얼 1~2개로 통합 · 4인 색 구분은 `MaterialPropertyBlock` · **셰이딩 모델은 결정 ⑦을 따른다** |
| 주의 | 프리팹 편집 후 **GlobalObjectIdHash 정규화** — 누락 시 클라이언트 접속 거부 |
| 검증 | 호스트 1 + 클라 1로 4인 색 구분·LOD 전환·접속 정상 확인 |

> 열차칸은 `Game.unity`에 직접 배치돼 있어 프리팹이 아니다(§1). 모델 교체 시
> **씬 YAML 직접 편집** 경로를 쓴다 — 에디터 씬 저장은 수천 줄 재정렬 diff를 만든다.

### 2차 — 낮/밤 연출 A안

| 항목 | 내용 |
|---|---|
| 신규 | `DayCycleVisualController` 1개 + 곡선/색 데이터 SO 1개 |
| 입력 | `IDayCycleService.PhaseRemaining` / `PhaseDuration` → 진행도 `t = 1 − remaining ÷ duration`. **인터페이스 무수정** |
| 모드 | `Off / A / B` 필드 + 런타임 토글 키 — 선례는 `DayCycleController._enableDebugPhaseKeys`(숫자패드 1·2·3 국면 점프, `:107-119`). 같은 자리에 붙이면 **같은 장면에서 A↔B 비교**가 된다 |
| 네트워크 | 없음. 로컬 표현이므로 호스트·클라가 서로 다른 모드여도 게임플레이가 갈라지지 않는다 |
| 선행 결정 | **결정 ② (fog 소유권)** — 미결 상태로 착수하면 날씨와 충돌한다 |
| 테스트 | 색 보간 수식을 순수 함수로 분리해 EditMode 검증 (경계 0·1, 국면 전환 연속성) |

모든 수치는 스스로 "실측 전 추정치"로 명시하고 있다.

### 4차 — 낮/밤 연출 B안 (+ 배경 조형물)

3차 조치 완료가 **선행 조건**이다. 광원이 회전하면 매 프레임 그림자맵을 다시 그리므로,
캐스케이드 2와 배경 LOD 없이 착수하면 비용이 그대로 배수로 붙는다(아트 예산 §4.1 — 밤
시나리오 약 4배).

배경 조형물 채우기(타일당 3개 → N개)는 결정 ③에 따라 이 차수에 편입하거나 이월한다.

### 5.1 결정 ⑦ — 셰이딩 모델 (PBR 제거의 파급)

결정 ④의 **"PBR 제거"** 는 텍스처 작업 방침이 아니라 **조명이 표면에 닿는 방식의 변경**이다.
따라서 M8의 2차·4차(낮/밤 연출) 전제가 여기에 종속된다.

| 셰이딩 | 조명 반응 | A안(ambient 보간) | B안(태양 이동) | 비용 |
|---|---|---|---|---|
| **URP Simple Lit** | Blinn-Phong — metallic/smoothness 없이 **방향광·ambient는 그대로 받는다** | **성립** | **성립** | Lit보다 쌈 |
| **URP Lit 유지 (맵만 제거)** | 완전 PBR — 텍스처만 단색/팔레트로 | 성립 | 성립 | 가장 비쌈 |
| **URP Unlit** | **조명을 받지 않는다** | **불성립** | **불성립** | 가장 쌈 |

**Unlit을 고르면 낮/밤 연출이 원천적으로 성립하지 않는다** — ambient를 어둡게 해도 표면 색이
변하지 않고, 태양을 돌려도 명암이 생기지 않는다. 그림자도 받지 않으므로 §3(렌더 조정)의
캐스케이드·LOD 그림자 작업도 대상이 사라진다. 이 경로를 택한다면 M8의 연출 범위 자체를
재정의해야 한다(예: 하늘·포스트프로세스 색조만으로 시간 표현).

**권장: Simple Lit.** "PBR 제거 = 재질 물리 계산을 걷어낸다"는 의도를 만족하면서 방향광 반응은
유지되므로, 스타일라이즈드 톤(기획서 §9.3)과 낮/밤 연출이 양립한다.

---

## 6. 완료 기준

1. 캐릭터·무기·기관차·열차칸이 실제 모델로 보이고, 호스트 1 + 클라 1 세션에서 4인 색 구분과
   LOD 전환이 정상 동작한다
2. 낮 → 밤 전환이 **한 프레임 도약이 아니라 시간의 경과로 읽힌다** (A안 기준 — 사용자 확인)
3. 밤 웨이브 최대 물량(동시 12 + 플레이어 4 + 자원 12) 상태의 프레임 수치가 **조치 전후로
   기록되어 있다** — 개선 여부를 수치로 말할 수 있다
4. EditMode 전량 통과 유지 (현재 452개 + A안 색 보간 순수 함수 테스트)
5. 게임플레이 회귀 0 — `DayPhase`·이벤트·서비스 시그니처 무변경

---

## 7. 테스트·검증 방식

- **순수 함수 분리 유지** — 색·각도 보간은 `MonoBehaviour` 밖의 static 순수 함수로 빼고
  EditMode에서 경계값(진행도 0·1, 국면 전환 시점)을 검증한다. `DayTimelineMath` 전례와 동일
- **연출은 EditMode 대상 밖** — 실제 판단은 플레이 검증 항목 문서로 (M7 차수와 같은 형식)
- **모드 토글이 곧 검증 도구다** — 같은 장면에서 Off/A/B를 즉시 오가며 비교
- 호스트 1 + 클라 1 구성 유지 (가이드 §5 원칙)

## 8. 리스크

| # | 리스크 | 처방 |
|---|---|---|
| 1 | **에셋 적용이 예산을 소모한다** — 현재 여유는 배경·모델이 비어서 생긴 것이다 | 1차 완료 직후 3차 실측을 붙인다. 순서를 미루면 원인 분리가 어려워진다 |
| 2 | **밤을 정직하게 어둡게 하면 보이지 않는다** — 전조등·모닥불이 아직 없다 | 밝기 하한을 두고 **색조 위주**로 간다. 점광원은 M8 비범위이므로 밝기 설계를 그 전제로 잡는다 |
| 3 | **fog 이중 소유** — 두 컨트롤러가 매 프레임 서로를 덮어쓴다 | 결정 ②를 착수 전에 확정 |
| 4 | **프리팹 편집 후 해시 오염** — 클라이언트 접속 거부(ClosedByRemote) | 모델 교체 후 GlobalObjectIdHash 정규화 확인 |
| 5 | **씬 저장 diff 폭증** — 열차칸이 씬 직접 배치라 에디터 저장 시 수천 줄 재정렬 | 씬 배선은 YAML 직접 편집 |
| 6 | **B안을 3차 조치 없이 착수** | 4차 착수 조건에 3차 완료를 명시(§4) |
| 7 | **M7 미해결 건과의 증상 혼선** (결정 ① ⓒ의 부수 효과) | 세션 이탈·재접속 문제(P1~P5)가 미해결인 채로 M8 검증에 들어간다. **M8 검증 문서에 "기존 미해결" 구역을 따로 두고** 그쪽 증상을 M8 회귀로 오분류하지 않는다 |
| 8 | **셰이딩 모델이 연출을 무효화** (결정 ⑦ 미확정) | Unlit을 고르면 A·B안이 원천 불성립이다(§5.1). **2차 착수 전에 확정**하고, 확정 전에는 연출 코드에 손대지 않는다 |
