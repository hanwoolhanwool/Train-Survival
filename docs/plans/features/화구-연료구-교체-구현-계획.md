## 0. 이 계획이 만들어진 경위

기관차 연료 투입구(`EngineFuelPort`)는 지금 **흰 실린더 프리미티브**다. 씬에는 이렇게 서 있다.

| 씬 | 위치 | 자식 `Visual` | 부가 컴포넌트 |
|---|---|---|---|
| `Game_ArtTest.unity` (본 씬) | `(0, 3.566, 15.5)` | Cylinder · scale 0.8 · y +0.4 | `TrainElevationFollower` |
| `Game.unity` | `(0, 3, 15.5)` | 같은 `fileID 590166808` | 없음 |

머티리얼은 `Art/EngineFurnace.mat`(guid `e5dfde05…`)로, 정리된 `Art/Materials/M_*` 규약 바깥의
초기 임시물이다. 즉 **모델·머티리얼·연출이 전부 임시 상태로 남은 마지막 상호작용 지점**이다.

여기에 세 가지를 한 번에 넣는다 — 화구 모델 교체, 상시 화염, 투입 순간의 버스트.
셋은 별개 작업으로 보이지만 **같은 좌표계 위에 얹히므로 한 차수로 묶는다.**

## 1. 확인된 에셋 — `Meshy_Ironbound Hearth Vault`

`Train_Servival_M8_prep.blend`에 임포트되어 있다 (아직 `zz_src_` 규약 이전, 정규화 전).

```
Meshy_Ironbound Hearth Vault_mesh_node
  verts 13,997 / polys 28,050
  dimensions  1.517 × 1.898 × 1.502   (Blender 정규화 단위)
  머티리얼 material.043
    base_color.003          2048²  packed
    metallic_roughness.043  2048²  packed
    normal.043              2048²  packed
```

### 1.1 형태 — 벽돌 볼트 + 철제 문(활짝 열린 상태로 고정)

렌더 확인 결과: 아치형 벽돌 몸통에 리벳 박힌 철 문틀이 붙고, **경첩 달린 문이 왼쪽으로 활짝
열린 채 메시에 고정**되어 있다. 문 개폐 애니메이션은 없다.

### 1.2 내부는 이미 비어 있다 — 개조 불요

레이캐스트 실측(Blender 로컬):

```
개구부 평면   y ≈ +0.10           개구부는 Blender −Y 방향
뒷벽 안쪽     y = +0.870          → 캐비티 깊이 0.77
캐비티 좌우   x −0.278 ~ +0.368   폭 0.646 (중심이 +0.045로 살짝 오른쪽)
캐비티 바닥   z = −0.489
캐비티 천장   z = +0.445          높이 0.934
```

> **이것이 이 계획의 가장 중요한 확인 사항이다.** [vintage stove 선례](../../../CLAUDE.md)에서는
> 창 안이 잉걸불 벽으로 막혀 있어 Blender에서 내부를 파내야 했다. **이 화구는 그 작업이 필요 없다** —
> 개구부에서 뒷벽까지 실제로 뚫려 있어 파티클을 그 안에 그냥 넣으면 된다.

정면 렌더에서 보이는 벽돌 패턴은 막힌 면이 아니라 **캐비티 뒷벽의 벽돌**이다.

### 1.3 Unity 좌표로 옮긴 값 (globalScale 1.0 · 원점 = 몸통 바닥 중앙 기준)

Blender `(x, y, z)` → Unity `(x, z, −y)`, 원점을 바닥으로 올린 뒤:

```
개구부 정면 방향   Unity +Z
캐비티            x −0.32 ~ +0.37   y 0.26 ~ 1.20   z −0.87 ~ −0.10
불꽃 발생 면      중심 (0, 0.28, −0.45) · 크기 x 0.55 × z 0.60
몸통 외곽         약 1.52(W) × 1.50(H) × 0.85(D)
```

개구부 0.65 × 0.93 m — 사람이 자원을 던져 넣는 크기로 적정하다.

## 3. 설계

### 3.1 전체 구조

```
EngineFuelPort            (씬 루트 직속 · NetworkObject · 위치 유지)
├── Firebox               ← 신규. 실린더 Visual을 대체
│   └── Train_Firebox     FBX PrefabInstance (Unlit)
│       ※ 개구부 +Z를 플레이어 접근 방향으로 향하게 회전
├── FireboxFlame          ← 신규. ParticleSystem + FireboxFlameView
└── FireboxLight          ← 신규(결정 ④). Point Light
```

`Visual`(Cylinder)은 **GameObject 통째로 제거**한다 — `EngineFuelPort`의 판정은 `transform.position`
거리와 시선 내적만 쓰므로([`EngineFuelPort.cs:47`](../../../Assets/_Project/Scripts/Gameplay/Train/EngineFuelPort.cs))
렌더러가 사라져도 상호작용은 그대로다. 콜라이더는 원래 없다.

### 3.2 투입 순간을 어떻게 모든 피어에 알리나

지금 투입 경로는 **한 방향뿐이다.**

```
클라 Update → RequestDepositServerRpc(slot) → [호스트] 인벤토리 차감 + AddFuel
                                                        ↓
                                              FuelChangedEvent (잔량 복제 시)
```

호스트가 확정한 "투입이 성사됐다"는 사실이 **연출용으로 돌아오는 경로가 없다.** `FuelChangedEvent`로
때우면 안 되는 이유가 결정 ③에 있다 — 호스트는 매 프레임 연료를 깎으므로 한 프레임의 증가는
소모와 상쇄되고, 클라이언트가 그 증가를 보는 시점도 복제 지연에 흔들린다.

→ **투입 확정 직후 호스트가 연출 전용 RPC를 브로드캐스트한다.**

```csharp
// EngineFuelPort.RequestDepositServerRpc 끝, AddFuel 직후
if (ServiceLocator.TryGet(out IFuelService fuel))
{
    fuel.AddFuel(fuelValue);
    PlayDepositEffectRpc(fuelValue);   // 연출 전용 — 게임 상태를 바꾸지 않는다
}

/// <summary>투입 성사 연출 — 모든 피어의 화구가 같은 순간 타오른다. 상태는 담지 않는다.</summary>
[Rpc(SendTo.ClientsAndHost)]
private void PlayDepositEffectRpc(float fuelValue)
{
    EventBus<EngineFuelDepositedEvent>.Publish(new EngineFuelDepositedEvent(fuelValue));
}
```

`EngineFuelDepositedEvent`는 [`TrainEvents.cs`](../../../Assets/_Project/Scripts/Gameplay/Train/TrainEvents.cs)에
`EnginePromptLocalEvent` 옆에 넣는다. 발열량을 실어 보내 **통나무를 넣었을 때가 넝마를 넣었을 때보다
크게 타오르게** 한다.

> **`NetworkObject`는 늘지 않는다.** `EngineFuelPort`가 이미 `NetworkBehaviour`라 RPC 하나만 얹으면
> 되고, 화염·조명은 전부 비네트워크 자식이다. "NetworkObject 0개 추가" 유지.

### 3.3 판정은 순수 함수가 소유한다

[SOLID 규칙](../../conventions/solid-principles.md) — 세기 계산은 `MonoBehaviour` 밖에 둔다.

`Assets/_Project/Scripts/Gameplay/World/FireboxFlameMath.cs` (신규, static):

```csharp
/// <summary>잔량 비례 기본 세기 — 0이면 잉걸불(minIntensity), 가득이면 1.</summary>
public static float ComputeBaseIntensity(float fuel, float capacity, float minIntensity)

/// <summary>투입 버스트 감쇠 — elapsed 0에서 peak, duration에서 0. 그 뒤로는 0 고정.</summary>
public static float ComputeBurstFactor(float elapsed, float duration, float peak)

/// <summary>발열량이 클수록 큰 버스트 — 상한을 둬 통나무 연타로 화면이 하얘지지 않게 한다.</summary>
public static float ComputeBurstPeak(float fuelValue, float referenceValue, float maxPeak)

/// <summary>최종 세기 = 기본 + 버스트, [0,1] 클램프.</summary>
public static float ComposeIntensity(float baseIntensity, float burstFactor)
```

`World` 어셈블리에 두는 이유: 연료 개념(`FuelMath`·`FuelSettings`)이 이미 거기 있고,
`Gameplay.Train`에서 단방향으로 참조된다.

### 3.4 `FireboxFlameView` — 뷰는 반영만 한다

`Assets/_Project/Scripts/Gameplay/Train/FireboxFlameView.cs` (신규)

```
Awake        ParticleSystem 모듈을 코드로 구성 (ImpactEffectView 선례)
             ├ main.simulationSpace = Local        ★ 3.5 참조
             ├ main.loop = true / playOnAwake = false
             ├ shape = Box (0.55 × 0.05 × 0.60) — 캐비티 바닥 면
             └ emission.rateOverTime = 곡선 없이 코드로 매 프레임 대입

OnEnable     EventBus<FuelChangedEvent>       구독 → _baseIntensity 갱신
             EventBus<EngineFuelDepositedEvent> 구독 → 버스트 시작 + Emit 버스트

Update       intensity = FireboxFlameMath.ComposeIntensity(base, burst)
             ├ emission.rateOverTime  = Lerp(_minRate, _maxRate, intensity)
             ├ main.startSize         = Lerp(_minSize, _maxSize, intensity)
             ├ main.startColor        = Lerp(_emberColor, _flameColor, intensity)
             └ _light.intensity       = Lerp(_minLight, _maxLight, intensity)  (결정 ④)
```

**풀링하지 않는다.** `ImpactEffectView`는 탄착마다 생겼다 사라지므로 `PoolManager`를 쓰지만,
화구 불은 씬에 하나뿐이고 상시 살아 있다. [아키텍처 규칙](../../conventions/architecture-rules.md)의
풀링 원칙은 "스폰/소멸하는 것"을 대상으로 한다.

### 3.5 파티클 시뮬레이션 공간 — `Local` 이어야 한다

열차는 원점 고정이고 월드가 −Z로 흐르지만, `EngineFuelPort`에는 `Game_ArtTest`에서
**`TrainElevationFollower`가 붙어 y를 계속 흔든다.** `World` 시뮬레이션이면 화구가 오르내릴 때
불꽃 기둥이 제자리에 남아 **화구 밖으로 새어 나온다.**

> 증상이 "파티클이 벽을 뚫는다"로 보이지만 원인은 콜라이더가 아니라 시뮬레이션 공간이다.
> 사다리 계획서 §3.1과 같은 종류의 함정이다 — **열차 위의 것은 좌표계를 먼저 의심한다.**

### 3.6 렌더 순서와 가림

화염 머티리얼은 `Universal Render Pipeline/Particles Unlit`(guid `0406db5a14f94604a8c57ccfbc9f3b46`)
+ Additive. 투명 큐는 불투명 이후에 그려지고 **깊이 테스트는 유지되므로**, 캐비티 벽돌 뒤로 넘어간
파티클은 정상적으로 가려진다. 별도 스텐실·정렬 작업이 필요 없다.

1차는 Unity 내장 `Default-Particle` 텍스처를 쓴다. 전용 불꽃 시트는 2차 이후.

## 5. 씬 배선

**두 씬 모두** 고친다 — `Game_ArtTest.unity`(본 씬)와 `Game.unity`. `Visual`은 같은
`fileID 590166808`을 공유하지만 씬 파일은 별개다.

- [씬 저장 diff 폭발](../../../CLAUDE.md) 회피 — `manage_scene save`를 쓰지 않고 **YAML 직접 편집**
- 신규 fileID는 **913000000 대역** 사용 (기존 910/912 대역과 충돌 회피)
- `EngineFuelPort`의 `GlobalObjectIdHash: 3368617182` **보존** — 건드리면 클라 접속이 거부된다
- 편집 전 씬을 내려놓는다 — 열린 씬 YAML을 고치면 "modified externally" 모달이 MCP 전체를 막는다

개구부 방향(모델 로컬 +Z)을 플레이어 접근 방향에 맞추는 회전은 **씬에서 실측 후 확정**한다.
현재 투입구는 캐빈 앞쪽(z 15.5)이고 `_lookDotThreshold 0.8`이 시선 정면을 요구하므로,
**개구부는 플레이어가 서는 쪽을 향해야 한다** — 등 돌린 화구에 대고 E를 누르는 그림이 되면 안 된다.

### 5.1 실측 결과 — 배치 확정 (2026-08-23)

기관차에 임시 `MeshCollider`를 달아 6방향 레이캐스트로 캐빈을 쟀다(모델 바운즈로는 내부 공간을 못 잡는다).

```
캐빈 바닥  y 3.913      천장 y 7.239
좌우 벽    x ±2.356     앞벽 z 13.723     (뒤쪽은 열려 있다)
```

> **원래 자리(z 15.5)는 캐빈이 아니라 보일러 속이었다.** 흰 실린더는 지름 0.8 m라 파묻힌 채
> 안 보였고, 플레이어는 앞벽 **너머의 보이지 않는 점**에 대고 E를 눌러 온 셈이다.
> 화구는 1.5 m라 그 자리에 두면 보일러에 박힌다 — **캐빈 앞벽 안쪽으로 옮긴다.**
> 실제 증기기관차의 화구 위치이기도 하고, 상호작용 거리도 오히려 가까워진다.

| 씬 | `EngineFuelPort` 위치 | 근거 |
|---|---|---|
| `Game_ArtTest` | `(0, 3.913, 13.30)` ← 기존 `(0, 3.566, 15.5)` | 캐빈 바닥 + 몸통 뒷면(원점 +0.4235)이 앞벽 13.723에 닿는 자리 |
| `Game` | `(0, 3, 15.5)` **유지** | **이 씬에는 기관차 아트 모델이 없다** — 칸이 프리미티브 박스(3×3×12)뿐이라 캐빈도 앞벽도 없다. 현재 위치가 이미 갑판 상면(y 3.0) 위라 화구가 바닥에 정확히 선다 |

개구부 회전은 **프리팹 루트가 yaw 180**을 갖는다 — 모델·불꽃·조명이 한 좌표계로 같이 돌아
씬 인스턴스는 오버라이드가 필요 없다. 두 씬 모두 개구부가 −Z(플레이어가 오는 쪽)를 향한다.

### 7.1 구현 중 확인된 것

**① 프리팹에 직렬화된 값이 스크립트 기본값을 이긴다.** 화력을 올리려고 `_maxEmissionRate` 등의
**필드 초기값**을 고쳤는데 화면이 그대로였다 — 프리팹이 이미 옛 값을 직렬화해 들고 있었기 때문이다.
Unity의 필드 기본값은 **새로 추가된 필드에만** 적용된다. 튜닝은 프리팹 값을 고쳐야 한다
(`PrefabUtility.LoadPrefabContents` → `SerializedObject` → `SaveAsPrefabAsset`).

**② 원형 빌보드로는 잉걸불에서 멈춘다.** 처음 결과는 불이 아니라 바닥에 깔린 숯이었다.
`ParticleSystemRenderMode.Stretch`(lengthScale 2.6)로 바꿔 **솟는 방향으로 늘여야** 불꽃 혀가 된다.
여기에 수명·속도·회전·크기를 범위로 흩뜨리고(같은 값이면 떠오르는 구슬로 보인다),
`colorOverLifetime`에 색을 넣어 **위로 갈수록 식게** 했다.

**③ 플레이 모드 없이 불꽃을 볼 수 있다.** `Awake`를 리플렉션으로 부른 뒤
`ParticleSystem.Simulate`로 정지 화면을 잡으면 된다 — 도메인 리로드로 NGO 소켓을 고아로 만드는
위험 없이 반복 튜닝이 가능하다. 최종 확정 값:

```
방출량   8 → 85 /s        크기  0.09 → 0.30 (한 벌 안에서 ×0.5~1 랜덤)
속도     0.44 ~ 0.8 m/s   수명  0.75 ~ 1.15 s   → 최고점 로컬 y 0.745 (캐비티 천장 0.92 안)
조명     Point · range 9 · 4.6 (잉걸불) ~ 14 (최대) · Perlin 흔들림 ±18%
```
