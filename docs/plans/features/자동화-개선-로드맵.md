작성일: 2026-09-03 · 대상: `.github/workflows/ci.yml` · `tools/` · `Assets/_Project/Scripts/Editor/` ·
상태: **조사 완료 · 1차 계획 분리** ·
1차: [`자동화-1차-구현-계획.md`](자동화-1차-구현-계획.md) ·
관련: [`성능 프로파일링 자동화 계획`](성능-프로파일링-자동화-계획.md) · [`CI 복구 계획`](CI-복구-계획.md) ·
[`아키텍처 규칙`](../../conventions/architecture-rules.md)

> **이 문서가 하는 일**: 현업에서 쓰는 자동화 16종을 이 프로젝트와 대조해 **무엇이 서 있고 무엇이
> 비어 있는지** 확정하고, 비어 있는 것 중 **지금 값이 있는 것만** 골라 차수로 편성한다.
>
> **이 문서가 하지 않는 일**: 빈칸을 전부 채우자고 하지 않는다. 조사해 보니 **비어 있는 것의
> 절반은 이 프로젝트에 해당이 없거나, 만들어도 잡을 것이 0건이다.** 그 판정 근거를 수치로 남기는 것이
> 이 문서의 절반이다.

## 0. 왜 지금인가 — 게이트가 5회 연속 꺼져 있다

자동화 목록을 훑기 시작한 이유는 "무엇을 더 지을까"였는데, 조사 첫머리에서 **이미 지어 둔 것이
작동을 멈춘 상태**가 나왔다.

```
33625361117  failure  2026-09-02T11:35Z   docs: 야간 실측으로 4차의 열린 질문을 닫는다
33611436684  failure  2026-09-02T08:56Z   docs(design): 예산 스펙을 실측으로 개정한다
33603689930  failure  2026-09-02T07:27Z   docs(plans): 성능 계획에 2차 완료와 사용법을 적는다
33592873382  failure  2026-09-02T04:59Z   docs(plans): 성능 계획에 1차 결과와 실행이 뒤집은 사실을 적는다
33413967930  failure  2026-08-31T16:25Z   fix(vfx): 파티클 속도 축 모드를 맞춘다
33342467102  success  2026-08-30T23:41Z   docs(plans): 에셋랩 계획과 아트 예산 v0.2 정정을 기록한다   ← 마지막 성공
```

그리고 실패의 대가는 테스트 결과 하나가 아니다. `build` 잡이 `needs: test`라서 **함께 건너뛰어진다.**

```
Test  (EditMode + PlayMode)   failure   11:35:11 → 11:42:24
Build (StandaloneWindows64)   skipped   11:42:25 → 11:42:25
```

즉 **2026-08-30 이후 빌드가 CI에서 한 번도 성공하지 않았다.** 새 자동화를 짓기 전에, 이미 지은
자동화가 다시 켜져야 한다. 그래서 1차는 신규 기능이 아니라 복구다
([`자동화-1차-구현-계획.md`](자동화-1차-구현-계획.md)).

## 2. 실측 — 우선순위를 뒤집은 넷

빈칸을 그냥 채우려 했다면 13번(협업 게이트)이 상위였을 것이다. 실제로 재 보니 순서가 바뀌었다.

### 2.1 에셋 위생은 이미 무결하다 — 검사기를 지어도 0건을 잡는다

`Assets/` 전수 검사 (2026-09-03 · 파일 2,685 · 폴더 77 · `.meta` 1,379):

| 검사 항목 | 결과 |
|---|---:|
| `.meta` 누락 | **0건** |
| 고아 `.meta` (짝 없는 메타) | **0건** |
| GUID 중복 | **0건** |
| missing script (`m_Script: {fileID: 0}`) | 1파일 5건 — 전부 `Assets/Settings/DefaultVolumeProfile.asset`(URP 기본 제공물) |

"`.meta` 누락 검사·GUID 충돌 검사"는 현업 체크리스트의 단골이지만, **이 저장소에서는 지금 잡을 것이
없다.** LFS·`.gitattributes`·머지 드라이버가 이미 깔려 있고 에디터를 통해서만 자산을 만들어 온 결과다.
지어도 되지만 **1순위는 아니다.**

### 2.2 반대로 CI는 실제로 꺼져 있다

§0. 5회 연속 실패 · 빌드 잡은 4일째 미실행. **13번이 "있다"고 표시된 것은 파일이 있다는 뜻이지
지키고 있다는 뜻이 아니었다.**

### 2.3 성능 게이트의 CI 연결은 이미 "불가"로 닫혀 있다

착수 전 이것을 1차 후보로 올렸으나, [`성능 프로파일링 자동화 계획`](성능-프로파일링-자동화-계획.md)이
이미 두 곳에서 닫아 두었다.

- §2 결정 ③ — **"C. CI 게이트 없음" 확정.** `ubuntu-latest`에 GPU가 없어 씬 벤치가 돌지 않고,
  self-hosted(이 PC)는 "측정 머신은 조용해야 한다"는 전제를 못 지킨다(에디터·Blender가 같이 돈다).
- §6 3차 완료 기준 — `~~CI에 스모크 잡~~ → **불가 판정**. 플랫폼 불일치라 로컬 게이트로 남긴다`

여기에 더해, 빌드 산출물이 `StandaloneWindows64`의 `.exe`인데 test 잡은 우분투 컨테이너다.
**스모크조차 같은 잡에서는 실행할 수 없다.** 이 판정을 다시 열려면 Windows 러너가 전제이고,
그 대가는 §5 2차의 열린 항목으로 남긴다.

### 2.4 기획자 툴은 "부분"이 아니라 완전한 공백이다

| 항목 | 수 |
|---|---:|
| `ScriptableObject` 파생 클래스 | 43종 |
| `CreateAssetMenu` 부착 | 43개 |
| `Assets/_Project/Data/`의 `.asset` | **96개** |
| `CustomEditor` · `CustomPropertyDrawer` | **0개** |

밸런스 수치 96개를 **전부 기본 인스펙터로** 편집하고 있다. 대신 검증은 EditMode 테스트가 맡는다
(`GrasslandSegmentPaletteAssetTests` 등) — 즉 **틀린 값을 넣으면 잡히지만, 넣기 편하게 해 주는 것은
아무것도 없다.** 이 공백은 게임 동작에 지장이 없어 급하지 않지만, 6번이 현업 도구 프로그래머의
핵심 산출물이라 [`포트폴리오 구성 계획`](../포트폴리오-구성-계획.md)과 맞물린다.

## 3. 해당 없음 — 빈칸이지만 채우지 않는 것

16종 중 다섯은 **이 프로젝트의 형태 때문에** 성립하지 않는다. 로드맵에서 영구 제외한다.

| # | 항목 | 왜 해당 없는가 |
|---|---|---|
| 14 | Android keystore · iOS provisioning | PC(StandaloneWindows64) 단독 타깃 |
| 2 | 오디오 압축 자동화 | 오디오 에셋 **0개** (`.wav`/`.mp3`/`.ogg` 없음) |
| 10 | 라이브옵스 (Remote Config·A/B) | 전용 서버가 없다 — P2P + Steam 릴레이 구조 |
| 3 | CDN 업로드 · 콘텐츠 업데이트 빌드 | 배포처가 Steam 단일이고 런타임 콘텐츠 갱신 계획이 없다 |
| 12 | localization key 생성 | 로컬라이제이션 시스템 자체가 없다(한국어 단일) |

**주의**: "지금 없으니 영원히 없다"가 아니라 **"지금 지으면 쓰는 곳이 없다"**는 뜻이다.
오디오가 들어오거나 다국어를 시작하면 2번·12번은 그때 다시 연다.

3번 Addressables는 다르다. 해당 없음이 아니라 **아직 필요가 증명되지 않았다** — 빌드 크기·로딩
시간을 잰 적이 없어 도입 근거가 수치로 없다. §5 3차의 조사 항목으로 둔다.

## 4. 우선순위 원칙 — 이 로드맵이 따르는 세 줄

조사에서 나온 판단을 규칙으로 굳힌다. 다음 차수를 고를 때 이 셋으로 재판정한다.

1. **꺼진 게이트가 새 게이트보다 앞선다.** 작동하지 않는 자동화는 없는 것보다 나쁘다 —
   있다고 착각하게 만들기 때문이다.
2. **지금 잡을 것이 0건인 검사기는 짓지 않는다.** 짓기 전에 먼저 세어 본다(§2.1이 그 예다).
   0건이면 그 검사는 "이미 지켜지고 있다"는 뜻이고, 사람이 아니라 **문서에 규약으로** 남기면 된다.
3. **화면에 보이지 않는 자동화는 그 자동화가 막는 사고를 실제로 겪었을 때만 짓는다.**
   ("보여주는 화면 우선"이라는 개발 방향과 충돌하지 않게 하는 조건이다.)

## 5. 차수 편성

| 차수 | 주제 | 상태 | 근거 |
|---|---|---|---|
| **1차** | **게이트를 다시 켠다** — CI 세그폴트 복구 · 잡 구조 정리 | **계획 수립 완료** | §0 · §2.2 |
| 2차 | 검증기를 실제 사고 쪽으로 확장 | 미착수 | §5.2 |
| 3차 | 기획자 툴 · 데이터 편집 보조 | 미착수 | §2.4 |

### 5.1 1차 — 게이트를 다시 켠다

별도 문서: [`자동화-1차-구현-계획.md`](자동화-1차-구현-계획.md)

한 줄 요약 — PlayMode 진입에서 나는 세그폴트를 잡고, 한 잡이 죽어도 나머지가 도는 구조로 바꾼다.
크래시 지점이 `MenuController::GetChecked`이고 `Menu.SetChecked` 사용처가 프로젝트에 **하나뿐**이라
원인 후보가 이미 좁혀져 있다.

### 5.2 2차 — 검증기를 "실제로 겪은 사고" 쪽으로 확장 (미착수)

§2.1 때문에 `.meta`/GUID 검사는 넣지 않는다. 대신 **이 프로젝트에서 실제로 터졌던 것**만 넣는다.

| 후보 | 왜 이것인가 | 착수 전에 셀 것 |
|---|---|---|
| `GlobalObjectIdHash` 오염 검사 | 스크립트로 프리팹을 고친 뒤 정규화를 빠뜨리면 **클라이언트 접속이 거부**된다(`ClosedByRemote`) — 실제로 겪었다 | NetworkObject 보유 프리팹 **10개**의 현재 해시 |
| `NetworkPrefabs` 중복 등록 · `AutoObjectParentSync` | 풀링 NGO 프리팹 규칙 위반이 런타임에만 드러난다 | `DefaultNetworkPrefabs.asset` 항목 수 |
| 클리어 존 검사기의 사각 메우기 | 현 검사기는 **콜라이더만** 본다. 지형 소품에는 콜라이더가 없어 **통과해도 스탬피드가 갇힌다** — 대초원 계획이 이미 이 사각을 발견해 렌더러 기준 테스트를 따로 만들었다 | 프리팹 **91개** 중 타일 프리팹 수 |
| Missing Reference 전역 스캔 | 씬 8 · 프리팹 91 대상 | 먼저 1회 수동 스캔으로 **건수를 센다**. 0건이면 원칙 2에 따라 보류 |

**2차를 여는 조건**: 위 "착수 전에 셀 것"을 재서 **0건이 아닌 항목이 하나라도 나올 때.**

### 5.3 3차 — 기획자 툴 · 데이터 편집 (미착수)

| 후보 | 대상 규모 | 비고 |
|---|---|---|
| 밸런스 SO 일괄 편집 창 | `.asset` 96개 · SO 43종 | 지역·몬스터·무기 값을 한 표에서 비교 편집 |
| `CustomPropertyDrawer` 몇 종 | 0개 → 반복 구조체부터 | 곡선·범위·가중치처럼 숫자만으로는 안 읽히는 필드 |
| 데이터 파이프라인 (CSV → SO) | 원본 0개 | **먼저 "밸런스를 시트에서 관리할 것인가"를 결정해야 한다.** 결정 없이 변환기부터 지으면 쓰이지 않는다 |
| Addressables 도입 검토 | — | 빌드 크기·로딩 시간을 먼저 잰다(§3) |

3차는 게임 동작이 아니라 **작업 속도와 증빙**을 위한 차수다. 착수 시점은 게임 쪽 마일스톤과
경쟁하므로, [`포트폴리오 구성 계획`](../포트폴리오-구성-계획.md)과 함께 판단한다.

## 6. 이 로드맵이 명시적으로 하지 않는 것

| 항목 | 왜 |
|---|---|
| 성능 게이트를 CI에 올린다 | §2.3 — 이미 불가 판정. 다시 열려면 Windows 러너가 전제이고, 그건 별도 결정이다 |
| `.meta`·GUID 검사기 | §2.1 — 잡을 것이 0건 |
| Slack/Discord 알림 | 1인 개발이라 알림 대상이 자신뿐이다. GitHub 알림으로 충분 |
| 패치노트 자동 생성 | 릴리스가 아직 없다. 첫 배포가 정해지면 그때 연다 |
| 커밋 훅(pre-commit) | CI가 같은 일을 하고, 훅은 로컬에만 걸려 협업 보장이 안 된다. **CI를 고치는 것이 먼저다** |

| **세그폴트 원인이 후보일 뿐** | 정황(시각·스택·유일한 사용처)은 맞아떨어지나 **재현으로 확정하지 않았다** | 1차 1단계를 "원인 확정"으로 두고, 가드 커밋 1개 + CI 1회로 판정한다 |

## 부록. 조사 방법

§2.1의 수치는 일회성 스크립트로 `Assets/` 전체를 순회해 얻었다(파일 2,685 · 폴더 77).
검사한 것은 넷이다 — `.meta` 짝 맞춤 양방향, `guid:` 중복, `m_Script: {fileID: 0}`,
프로젝트 밖 GUID 참조. **스크립트는 저장소에 넣지 않았다** — 결과가 전부 0건이라
원칙 2에 따라 상설 검사기로 만들지 않았기 때문이다. 2차에서 필요해지면 그때
`ClearZoneAuditWindow`와 같은 방식(순수 판정 함수 + EditMode 테스트)으로 다시 짓는다.
