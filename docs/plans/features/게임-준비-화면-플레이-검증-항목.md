# 게임 준비 화면 플레이 검증 항목 — 1~5차 통합

작성일: 2026-08-22 · 대상: `Main.unity` 안의 `Canvas_Ready` · 상태: **검증 대기**
(구현: [게임 준비 화면 구현 계획](게임-준비-화면-구현-계획.md) §8의 **1~5차 전부**.
EditMode **743/743 통과** 상태에서 시작 — 1차 이전 707 + 신규 36)

> **무엇을 보는가**: 이 화면의 목표는 `게임 준비.png`를 **동작하는 대기실로 만드는 것**이었다.
> 검증 축은 셋이다 — **그림이 시안으로 읽히는가**(A), **혼자서 끝까지 가는가**(B~D),
> **여럿이서 어긋나지 않는가**(E). 마지막 F·G는 손과 화면의 문제다.
>
> **검증 구성**: A~D·F·G는 **단독 실행**으로 충분하다. **E 구역만 호스트 1 + 클라이언트 1**
> (MPPM 가상 플레이어 또는 빌드 두 벌)이 필요하고, **이번 계획에서 한 번도 실기로 확인하지
> 못한 유일한 구역**이다(§14 ⑤ ㉤ · ⑥ ㉦ — 에디터 한 벌로는 붙일 수 없어 콜백을 직접 태워 갈랐다).

## 0. 검증자가 먼저 읽을 것 — "결함 아님" 여섯 가지

아래는 전부 **의도된 상태**이거나 **이미 알고 있는 계획 밖 결함**이다. 새로 올리지 않는다.

1. **호스트 이름이 `NightRail_01`이 아니라 `플레이어 1`이다** (§7.3 결정).
   Steam 퍼소나 이름 연결은 차후 작업이고, 이번에는 호스트가 칸 번호로 이름을 짓는다.
   시안과 문구가 다른 것은 **이 한 곳뿐**이다.

2. **난이도를 바꿔도 게임이 쉬워지거나 어려워지지 않는다** (§12 미결 1번 결정).
   값 전달까지가 이번 범위다. 화면에 "적용 예정" 같은 표기를 **일부러 넣지 않았다** —
   미완성을 광고하는 문구는 시안을 해치고, 배율이 붙는 순간 지워야 할 부채다.
   대신 **값이 인게임까지 도달하는지**를 D3에서 확인한다.

3. **한 번 나가면 그 방을 다시 열 수 없다** (§10 리스크 9번).
   NGO의 메시지 시스템이 `Shutdown()` 뒤 다시 초기화되지 못한다 — 순정
   `NetworkManager.StartHost()`도 같고, `SessionExitHud.LeaveToMain()`이라는 **기존 경로에도
   이미 있던 결함**이다. 나가기를 확인한 뒤에는 **플레이 모드를 다시 시작**하고 이어서 본다.

4. **직결 모드의 "초대 하기"가 복사하는 주소는 `127.0.0.1:7777`이다** (§14 ⑥ ㉢).
   LAN 주소가 아니라 실제 바인드 값이다 — Boot 씬 `UnityTransport`의 `ServerListenAddress`가
   `127.0.0.1`이라 **호스트가 루프백에만 귀를 연다.** LAN IPv4를 보여 주면 붙지 않는 주소를
   건네는 셈이라, 귀를 여는 일이 선행이다. **같은 PC 두 벌 테스트에서는 이 값이 맞다.**

5. **확인 창이 시안에 없다** (§12 미결 3번 결정). 회색 판에 문구와 버튼 둘뿐이다.
   나가기가 되돌릴 수 없는 조작이라(위 3번) 넣기로 한 것이고, 정식 스타일링은
   [UI 구현 계획](UI-구현-계획.md)의 몫이다.

6. **`Panel_Host`가 사라졌다** (§6.4 · §14 ⑦). "새 여정 / 초대 / 개발용 씬 선택"은 전부
   대기실로 옮겨 갔고, 명판 **방 만들기를 누르면 곧바로 대기실**이 뜬다. 중간 패널이 없는 것이 정상이다.

## A. 그림 — 시안으로 읽히는가

`Downloads/게임 준비.png`를 옆에 띄우고 대조한다.

- [ ] **A1** 두 패널의 자리·크기가 시안과 겹쳐 보인다 (왼쪽은 화면 좌변, 오른쪽은 우변)
- [ ] **A2** 왼쪽 패널 가장자리에 **회색·갈색 얼룩이 없다** — 밤하늘 위에서 확대해 본다
- [ ] **A3** 오른쪽 패널 경계에 **흰 자국이 남지 않았다** — 어두운 하늘 위에서 확대해 본다.
      **이 항목이 이 계획의 최대 아트 리스크였다**(§10 리스크 2 — 평면 열차에서 실제로 났다)
- [ ] **A4** 금색 "게임 시작" 버튼의 하이라이트가 **키잉으로 파먹히지 않았다**
- [ ] **A5** 두 패널이 **세로로 눌리지 않았다** — NPOT 임포트 스케일(§10 리스크 2-b)
- [ ] **A6** 패널 위 문구가 **전부 TMP**다 — 그림에 구워진 한국어가 한 글자도 없다(§11).
      타이틀 "게임 준비"와 "난이도"는 각인을 **지우고** TMP만 올렸다(§14 ③ ㉣)
- [ ] **A7** 공고대가 **보이지 않는다** — 대기실에서는 숨긴다(§5.3)
- [ ] **A8** 빈 칸 셋에 "플레이어 대기 중"과 사람+ 아이콘이 있고, 첫 칸에는 왕관과 "HOST"가 있다

## B. 혼자서 끝까지 — 방 열기부터 출발까지

- [ ] **B1** 명판 **방 만들기**를 누르면 **중간 패널 없이** 곧바로 대기실이 뜬다
- [ ] **B2** 배너와 공고대가 함께 사라진다 (배경·열차는 그대로 이어진다)
- [ ] **B3** 첫 칸에 **플레이어 1 · HOST · 접속 중(녹색 점)**이 앉아 있다
- [ ] **B4** **게임 시작**을 누르면 인게임 씬으로 넘어간다
- [ ] **B5** 대기실이 떠 있는 동안 **인게임 하늘이 비치거나 커서가 잠기지 않는다**
      (§14 ④ ㉢ — 플레이어가 메뉴 위에 스폰되는 문제를 막아 둔 자리다)

## C. 나가기 — 묻고 나간다

- [ ] **C1** **나가기**를 누르면 확인 창이 뜬다. 호스트 문구는
      "방을 닫고 나가시겠습니까? / 함께 있는 사람들의 연결이 끊깁니다."
- [ ] **C2** 창이 열린 순간 포커스가 **"취소"에 있다** — 확인에 손가락을 얹어 두면
      확인 창이 오조작을 막는 장치가 아니라 한 번 더 눌러 통과시키는 장치가 된다
- [ ] **C3** **취소**를 누르면 창만 닫히고 **방은 그대로 살아 있다**
- [ ] **C4** **Esc**(게임패드 B)도 취소와 같다 — 창만 닫힌다
- [ ] **C5** 대기실에서 Esc를 누르면 **나가기와 같은 뜻**이라 확인 창이 뜬다(§6.5)
- [ ] **C6** **확인**을 누르면 배너로 돌아간다
- [ ] **C7** 창 뒤가 어둡게 덮이고, **뒤쪽 버튼이 클릭으로 눌리지 않는다**

> **여기서 플레이 모드를 다시 시작한다** — 위 "결함 아님" 3번(세션 재시작 불가) 때문이다.

## D. 난이도

- [ ] **D1** 처음 열었을 때 값이 **"보통"** 이다 (시안과 같다)
- [ ] **D2** ▶ ▶ ▶ 를 누르면 **어려움 → 쉬움 → 보통**으로 **순환**한다. ◀도 반대로 순환한다
- [ ] **D3** **고른 난이도가 인게임 씬까지 도달한다.** "어려움"으로 두고 출발한 뒤,
      인게임에서 `ServiceLocator.Get<ILobbyRoomService>().Difficulty`가 `Hard`인지 본다
      (배율 적용은 비범위 — 위 "결함 아님" 2번)
- [ ] **D4** 난이도를 바꿔도 **왼쪽 칸 넉 장이 깜빡이지 않는다**
      (멤버와 난이도가 같은 신호로 오므로 거르지 않으면 로스터가 함께 다시 그려진다)

## E. 여럿이서 — **두 벌이 필요하다 · 이번 계획에서 실기 확인 못 한 구역**

- [ ] **E1** 게스트가 접속하면 **두 사람 모두의 화면**에 두 칸이 찬다
- [ ] **E2** 게스트 화면에서 **호스트가 첫 칸**이고 자기는 둘째 칸이다
- [ ] **E3** 게스트 화면에서 **게임 시작이 눌리지 않고** 라벨이 **"호스트를 기다리는 중"** 이다
- [ ] **E4** 게스트 화면에서 **난이도 화살표가 보이지 않고**, **값은 보인다**
- [ ] **E5** 호스트가 난이도를 바꾸면 **게스트 화면의 값도 바뀐다**
- [ ] **E6** 게스트가 나가면 호스트 화면의 칸이 **비워진다**
- [ ] **E7** **가운데 사람이 나가면 뒤가 앞으로 당겨진다** — 칸 사이에 구멍이 남지 않는다
      (§10 리스크 6의 "유령 칸")
- [ ] **E8** 호스트가 나가면 게스트가 **메뉴로 복귀**하고 **"방이 닫혔습니다"** 가 뜬다
- [ ] **E9** 호스트가 출발하면 게스트도 **함께 인게임 씬으로 끌려간다**
- [ ] **E10** **5번째 접속이 거부되거나, 대기 없이 튕기지 않는다** (§11 완료 기준)
- [ ] **E11** 게스트 화면에서 **초대 하기가 눌리지 않는다** (직결 모드 — 게스트는 호스트 주소의
      출처가 아니다). Steam 모드에서는 **눌린다**

## F. 손맛 — 호버 · 포커스 · 연출

- [ ] **F1** 마우스를 버튼에 올리면 **밝아진다** (원화가 한 상태뿐이라 밝기 변조다 — §5.2-3)
- [ ] **F2** 선택된 버튼에 **황동 테두리가 둘린다.** 마우스로 옮기든 방향키로 옮기든 따라온다
- [ ] **F3** **테두리는 언제나 한 곳에만** 있다 — 마우스와 키보드가 각각 다른 버튼을 켜지 않는다
- [ ] **F4** **색을 흑백으로 놓고 봐도** 어느 버튼이 선택됐는지 구분된다 (색각 대응 — §9.2).
      테두리의 있고 없음이 그 답이다
- [ ] **F5** 마우스를 한 번도 쓰지 않고 **방향키·확인·취소만으로** 모든 버튼에 도달·실행된다
- [ ] **F6** 위아래로 계속 누르면 **순환**한다 (맨 아래에서 맨 위로)
- [ ] **F7** 난이도 줄에서 **좌우**로 ◀ ▶ 사이를 오간다
- [ ] **F8** 게스트 화면에서 위아래로 움직이면 **잠긴 줄을 건너뛴다** — 눌러도 반응 없는
      자리에 화살표가 멈추지 않는다
- [ ] **F9** 사람이 들어오거나 나가면 그 칸이 **짧게 커졌다 가라앉는다**(0.18초)
- [ ] **F10** 그 연출 중에 **칸 테두리가 이중으로 보이지 않는다** — 배율이 1보다 작아지면
      밑에 깔린 프레임 그림이 삐져나온다(로비 계획 §4.2-3에서 데인 자리)
- [ ] **F11** 화면을 처음 열 때는 **넉 장이 한꺼번에 깜빡이지 않는다**
