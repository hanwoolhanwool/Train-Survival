## 0. 범위

1. **FP/TP 표현 분리** — 기존 AimPivot 아래 무기 피벗 5종은 **FP 뷰모델**(소유자
   전용)로 남기고, **TP 월드모델** 1벌을 신설해 오른손 본 소켓에 부착한다
2. **`HeldWeaponSocket` 신설** — `ActiveAnimator`에서 오른손 본을 해석해 소켓 생성,
   Girl↔Man 전환 시 재해석, `HeldItem` 기준 가시성·소켓 오프셋 적용 (표현 전용)
3. **`WeaponHoldIk` 신설** — Humanoid 내장 `OnAnimatorIK`로 양손을 홀드 타깃에 부착.
   총기(리볼버·샷건·집게)는 조준 자세가 기본, 망치·근접은 소켓 부착만
4. **`WeaponHoldSettings` SO 신설** — 무기별 소켓 오프셋·홀드 타깃·양손 여부·IK
   가중치를 데이터화 (`HotbarItemType` 키)
5. **순수 로직 분리** — `WeaponHoldMath` (피치→홀드 타깃 산출·가중치 블렌드 스텝,
   EditMode 대상)

**비범위** (의도적 제외):

- **TP 근접 휘두르기·망치 타격 모션** — `MeleeSwingView`는 FP 피벗 절차 회전이라
  TP에 그대로 안 옮겨진다. 1차는 "손에 쥐고 있음"까지만, 휘두르기는 후속 차수
  - **수용된 회귀 (2026-08-17 보완)**: 근접 칼날 호 궤적은 현재
    `PlayRemoteSwingRpc`로 원격에도 재생되는데, FP 전용화하면 이번 차수 동안
    **원격 화면에서 스윙 모션이 사라진다** (남기면 TP 손의 마체테와 눈높이의 칼날이
    이중 표시되므로 전용화가 옳다). 타격 이펙트(`ImpactEffectView`)는 월드 좌표
    스폰이라 원격에도 계속 보이고, RPC 채널은 후속 TP 스윙 표현을 위해 유지한다.
    망치는 원래 타격 모션이 없어(수리 즉발 판정) 회귀 없음.
  - 근접은 현재 스윙 중에만 보이므로, TP 월드모델의 "상시 손에 쥔 마체테"는 원격·
    그림자에 **새로 생기는** 시각이다. FP는 현행 유지(비스윙 시 비표시 — 결정 ②).
- **FP 팔 뷰모델** — M8 결정 ① ⓐ 이월 유지 (FP는 무기만 보이는 현행 그대로)
- **파지·조준 애니메이션 에셋 반입** — 에셋 확보 시 상체 레이어로 얹고 IK 가중치를
  내리는 업그레이드 경로만 열어둔다 (§2.5) — 상세 계획은
  [무기-파지-품질-업그레이드-계획.md](무기-파지-품질-업그레이드-계획.md) **C축**
- **Animation Rigging 패키지** — 내장 IK로 충분한지 먼저 검증. 팔꿈치 힌트 등
  품질 한계가 확인되면 그때 도입 — 상세 계획은
  [무기-파지-품질-업그레이드-계획.md](무기-파지-품질-업그레이드-계획.md) **B축**

## 2. 설계

### 2.1 현재 구조와 문제

- `Player.prefab`: 루트 → **AimPivot**(y 1.6) → Melee/Hammer/Revolver/Shotgun/Harpoon
  피벗 5종. `PlayerAimView.LateUpdate`가 AimPivot을 피치로 회전 — 소유자 화면에서는
  무기가 화면에 고정되지만, **원격 화면에서는 같은 무기가 눈높이에 떠서** 시선만
  따라다닌다. 손 본과 무관하므로 "파지"가 아니다.
- Girl/Man 휴머노이드 모델은 `PlayerCharacterView`가 교대(`ActiveAnimator` 노출),
  가슴·머리는 `PlayerAimView.ApplyBodyPitch`가 절차 회전 중.
- `AC_Player.controller`는 Base Layer 단일(Locomotion 블렌드·Jump·Dead·Grabbed),
  파지·조준 클립 없음.

### 2.2 표현 분리 구조

| 구성요소 | 역할 | 계층 |
|---|---|---|
| FP 뷰모델 (기존 피벗 5종) | 소유자 화면 전용 — 현행 배치 무수정. 원격 분기 제거 대상은 **4곳**(`GunView` 인스턴스 2·`HarpoonView`·`RepairHammerView`) — `MeleeSwingView`는 HeldItem 가시성이 없는 스윙 한정 표시라 **원격 RPC 재생을 소유자 전용화**로 처리 (§0 수용된 회귀 참조) | 기존 |
| TP 월드모델 (신설 1벌) | 무기 모델 복제를 오른손 소켓에 부착 — 원격 화면·자기 그림자 담당 | 프리팹 |
| `HeldWeaponSocket` | 오른손 본 해석 → 소켓 생성·오프셋 적용·가시성 토글. 판정 무관 표현 전용 | MonoBehaviour (`Gameplay/Player`) |
| `WeaponHoldIk` | `OnAnimatorIK`에서 양손 IK 목표·가중치 설정 | MonoBehaviour (`Gameplay/Player`) — **Animator와 같은 GameObject** (Girl·Man 모델 루트 각각) |
| `WeaponHoldSettings` | 무기별 소켓 오프셋·홀드 타깃 로컬 pos/rot·양손 여부·IK 가중치·블렌드 반감기 | ScriptableObject |
| `WeaponHoldMath` | 피치→홀드 타깃 산출, 가중치 블렌드 스텝 | 순수 static |

### 2.3 조준 자세 — Humanoid 내장 IK

- `AC_Player.controller` Base Layer **IK Pass 활성화**.
- 신설 **TP 조준 피벗**(가슴 높이, 루트 자식)이 복제 피치로 회전하고, 그 아래
  무기별 **홀드 타깃**(오른손·왼손)이 배치된다. `WeaponHoldIk`가
  `AvatarIKGoal.RightHand/LeftHand`의 position·rotation을 홀드 타깃으로 설정.
- **가중치 규칙** (결정 ③ — 상태 머신 없음):
  - `HeldItem` ∈ {Revolver, Shotgun, Harpoon} → 오른손 1 (+양손 무기는 왼손 1)
  - `HeldItem` ∈ {Hammer, Melee} → 0 (소켓 부착만 — 내린 손에 쥔 자세)
  - `HeldItem == None`(UI 열림·사망 포함 — 이미 None으로 복제됨) → 0
  - 전환은 짧은 블렌드(반감기 ~0.1 s)로 팔이 튀지 않게 한다 (`WeaponHoldMath.Step`)
- TP 무기는 오른손 본 자식이므로 IK로 팔이 들리면 **총도 자연히 조준 위치로
  올라간다** — 무기 위치를 따로 구동하지 않는다.

### 2.4 실행 순서·기존 절차 회전과의 관계

- `OnAnimatorIK`(Animator 내부) → Animator 본 확정 → `PlayerAimView.LateUpdate`
  (가슴·머리 절차 회전) 순서다. 가슴 회전이 IK 이후 손 위치를 다시 움직이지만,
  무기는 손 본의 자식이라 **파지 자체는 깨지지 않는다** — 홀드 타깃과 실제 손의
  잔차만 남는다.
- 잔차가 크면: 총기 파지 중에는 `ChestPitchWeight`를 낮추고(팔 IK가 시선 추종을
  대신한다) 홀드 타깃 배치로 흡수한다 — 튜닝 항목이지 구조 문제가 아니다.
  - 주의: `ChestPitchOffsetDegrees`는 리타게팅 편향 보정 **상수**라 피치 0에서도
    잔차가 상시 존재한다. §5 2단계 리볼버 검증은 **피치 0의 잔차 실측**부터
    시작한다 — 이 상수 편향을 홀드 타깃 로컬 배치로 먼저 흡수해야 피치 가변
    잔차(`ChestPitchWeight` 몫)의 튜닝이 분리된다.
- 원격 Animator는 `CullUpdateTransforms` — 화면 밖이면 본이 안 움직이지만 무기도
  안 보이므로 무해 (기존 규약 유지).

### 2.5 업그레이드 경로 (후속 — 이 차수 비범위, 상세는
[무기-파지-품질-업그레이드-계획.md](무기-파지-품질-업그레이드-계획.md))

- 파지·조준 애니 에셋 확보 시(**C축**): 상체 AvatarMask 레이어에 클립을 얹고 IK
  가중치를 데이터로 내린다 — `WeaponHoldSettings` 필드 조정만으로 전환 가능한
  구조를 지킨다.
- TP 휘두르기(**C축 C4**): 망치·근접 사용 시 상체 스윙 — 유지해 둔
  `PlayRemoteSwingRpc` 채널에 표현만 얹으면 된다. §0의 수용된 회귀도 이때 복구된다.
- 내장 IK 품질 미달 시(**B축**): TwoBoneIK 제약으로 백엔드 교체 — 홀드 타깃·설정·
  `WeaponHoldMath`는 무수정 재사용이 계약이다.

## 4. 아키텍처 마감 기준 (SOLID · 판정-표현 분리)

구현 중 하드코딩은 허용하되(§5 단계별 허용 지점), **계획서를 닫으려면 아래를 전부
통과해야 한다.** 어느 하나라도 미달이면 완료가 아니다 — 하드코딩 허용은 착수 순서의
자유이지, 마감 품질의 면제가 아니다.

| 원칙 | 적용 | 검사 방법 |
|---|---|---|
| **SRP** | 소켓 부착(`HeldWeaponSocket`) / IK 자세(`WeaponHoldIk`) / 수치(`WeaponHoldSettings`)가 각각 한 파일. `PlayerAimView`에는 피치 공개 프로퍼티 노출만 추가 — 기존 컴포넌트에 "그리고"가 늘지 않는다 | 리뷰 체크리스트 |

**실측 마감** (2026-08-17 — 계획 수립 시 몰랐던 두 가지가 파지를 깨고 있었다):

- **손 본 스케일 100배**: FBX 임포트 스케일 0.01의 역수를 본 계층이 물고 있어
  `RightHand.lossyScale`이 Girl·Man 모두 100이다. 소켓을 `localScale = 1`로 붙이면
  오프셋 단위가 1 = 100 m가 되고 근접 무기가 100배로 커진다 →
  `HeldWeaponSocket.NormalizeToRootScale`이 소켓을 루트 배율로 되돌려 **오프셋을 미터
  단위로 고정**한다. 무기 모델의 임포트 스케일은 프리팹 배치가 갖고 있으므로
  설정의 `SocketLocalScale`은 그 위에 얹는 **배율**로 쓴다(하푼만 0.75).
- **무기 로컬 축**: 총구는 **+Y**, 총의 위쪽은 **+Z**다(FP 피벗의 Y 180° 회전에서
  −Z로 추정했던 것이 틀렸다 — 무기 단독 정사영 렌더로 확정). 소켓 회전은
  "무기 +Y → 손끝(전완→손) · +Z → 캐릭터 위쪽"으로 산출한 Girl↔Man 중간값
  (335.35, 261.24, 31.99)이다. 두 모델의 손 본 축 차이는 9.2°로 단일 값으로 흡수한다(LSP).
- **조준 피벗 높이**: 어깨 실측 y ≈ 1.08 (치비 비율 — 머리가 1.15다). 초기 계획의
  1.25는 머리 위였다. 홀드 타깃은 팔 길이 0.475 m의 60~85% 범위에 둔다.
- 소켓 오프셋은 각 무기 메시 바운즈에서 그립 위치를 잡아 산출했다(리볼버는 조준
  자세 렌더로 검증 완료, 나머지는 같은 비율 규칙 적용 — 플레이 검증에서 미세 조정).
