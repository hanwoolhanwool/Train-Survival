(2026-08-18 갱신, `feat/weapon-hold`).
- **C1~C3 완료**: Mixamo 클립 3종 반입 · Hold 레이어 가동 · IK 합성 비율 확정

- **남은 품질 미달**(손목 각도)은 [뷰랩-파지-포즈-편집-계획.md](뷰랩-파지-포즈-편집-계획.md)가 잇는다

구조를 그대로 재사용하며, 서로 독립적으로 착수·마감할 수 있다)

>   손목 회전 부정확)가 확인되면 TwoBoneIK 제약으로 교체해 **정밀 손 배치**

> - 신규 동기화 채널 0 유지 — 전부 기존 복제 값(`HeldItem`·피치)의 표현 확장이다.

## 0. 범위

**C축 — 파지 애니메이션 에셋** (아트 반입 + Animator 레이어):

1. **파지 포즈 클립 반입** — 무기 카테고리 3종: 한손 조준(리볼버) · 양손 조준
   (샷건·집게) · 한손 하단 파지(망치·근접). 정지 포즈 1클립씩이면 시작 가능
2. **`AC_Player.controller`에 Hold 레이어 신설** — 상체 AvatarMask(가슴·양팔·머리),
   레이어 가중치와 카테고리 전환은 로컬 파라미터로 구동 (동기화 채널 0)
3. **IK 가중치 인하** — 포즈 클립이 기본 자세를 담당하고, A안 IK는 피치 추종
   보정만 남긴다 — `WeaponHoldSettings` 데이터 조정으로만 전환 (A안 §2.5 계약)
4. **TP 휘두르기·타격 모션** (A안 이월분) — 근접 스윙을 기존 연출 RPC 채널
   (`PlayRemoteSwingRpc` — A안 §0이 후속 TP 스윙용으로 유지하기로 한 채널)에 얹어
   **A안이 수용한 원격 스윙 회귀를 여기서 복구**한다. 망치 타격 모션도 같은 방식

**B축 — Animation Rigging** (품질 한계 확인 시에만):

5. **`com.unity.animation.rigging` 패키지 도입** + Girl/Man 모델 2벌에 리그 셋업
   (RigBuilder + TwoBoneIK 제약 양팔 + 팔꿈치 힌트)
6. **`WeaponHoldIk`의 IK 백엔드 교체** — `OnAnimatorIK` 호출을 리그 제약 가중치
   구동으로 대체. `WeaponHoldSettings`·홀드 타깃·`WeaponHoldMath`는 **무수정 재사용**
7. **(선택) 가슴 절차 회전의 리그 이관** — `PlayerAimView.ApplyBodyPitch`의
   LateUpdate 본 덮어쓰기를 MultiAim 제약으로 옮겨 실행 순서 잔차(A안 §2.4)를
   구조적으로 해소

**비범위** (의도적 제외):

- **FP 팔 뷰모델** — M8 결정 ① ⓐ 이월 유지 (별건)
- **하체·전신 무기 애니메이션** (조준 보행 전신 클립 등) — 상체 레이어로 충분한지
  먼저 본다. 전신 블렌드는 로코모션 구조 개편이라 별건
- **몬스터·보스 리깅** — 이 계획은 플레이어 한정

## 2. 설계

### 2.1 C축 — Hold 레이어 (Animator)

| 구성요소 | 역할 | 계층 |
|---|---|---|
| Hold 레이어 (`AC_Player.controller`) | 상체 AvatarMask · 카테고리별 파지 포즈 스테이트 + 스윙 스테이트 | 에셋 |
| `WeaponHoldPoseDriver` (신설) | `HeldItem` → `HoldPose` 파라미터·레이어 가중치 구동. 판정 무관 표현 전용 | MonoBehaviour (`Gameplay/Player`) |
| `WeaponHoldSettings` (A안, 확장) | 카테고리 매핑 · 레이어 블렌드 반감기 · 카테고리별 IK 잔여 가중치 | ScriptableObject |

- **레이어 구성**: Base Layer(로코모션)는 무수정. Hold 레이어가 AvatarMask로 가슴
  위만 덮어쓴다 — 하체는 걷기·달리기가 그대로 돌고 상체만 파지 자세.
- **A안 IK와의 합성**: 포즈 클립이 "자세"를, IK가 "피치 추종·그립 밀착"을 담당한다.
  IK는 Animator 평가 후 적용되므로 클립 위에 자연히 얹힌다 — 카테고리별 IK 잔여
  가중치(예: 조준 0.4·하단 파지 0)는 데이터로 튜닝.
- **TP 스윙**: 근접·망치의 기존 연출 RPC 수신 지점에서 Hold 레이어의 스윙 트리거를
  1발 재생 — 신규 RPC 없음.

### 2.2 B축 — 리그 구성 (Animation Rigging)

- Girl/Man 모델 루트에 `RigBuilder` + `Rig`(WeaponHoldRig) — TwoBoneIK 제약
  (오른팔·왼팔, 팔꿈치 힌트 트랜스폼 포함).
- **⚠ 주 논거 철회 (2026-08-18)**: 초안은 "팔꿈치 힌트가 내장 IK 대비 핵심 이득"을
  B축의 근거로 삼았으나 **사실이 아니다.** 내장 Humanoid IK에도
  `Animator.SetIKHintPosition(AvatarIKHint.RightElbow, …)` + `SetIKHintPositionWeight`가
  있다(리플렉션 실재 확인). **따라서 팔꿈치 통제만을 이유로 B축을 도입할 근거는 없다.**
  B축이 여전히 이득인 지점은 ① 제약을 Animator 평가 파이프라인 **안**에서 돌려
  `LateUpdate` 덮어쓰기 잔차를 없애는 것(§0-7 가슴 MultiAim 이관)과 ② 다중 제약의
  선언적 구성이며, 이는 §2.3의 착수 순서(C축 먼저) 판단을 바꾸지 않는다.
- IK 목표는 **A안의 홀드 타깃을 그대로 참조** — 제약의 target에 연결만 바꾼다.
  `WeaponHoldIk`는 `OnAnimatorIK` 대신 제약 weight를 `WeaponHoldMath.Step`으로
  구동하는 형태로 개정 — 공개 계약(설정 조회·가중치 규칙)은 무수정.
- **평가 순서**: 리그 제약은 Animator 평가 파이프라인 안(레이어 뒤)에서 돌므로
  C축 포즈 클립 위에 정확히 얹힌다. §0-7(가슴 MultiAim 이관)까지 하면
  `LateUpdate` 본 덮어쓰기가 사라져 A안 §2.4의 잔차 문제가 구조적으로 소멸.
- **모델 전환**: Girl↔Man 전환 시 비활성 모델의 리그는 Animator와 함께 잠들므로
  추가 처리 불요 — 단 리그 셋업 자체는 2벌 중복이라 프리팹 배선 검증 항목이다.

### 2.3 축 간 독립성·순서

- **C축 단독**: 포즈 클립 + 내장 IK 잔여 보정만으로 마감 가능 (B축 불요 판정 시).
- **B축 단독**: 클립 없이도 내장 IK → 리그 교체만으로 그립 밀착 개선 가능.
- **둘 다**: C축 먼저 권장 — 포즈가 좋아지면 B축 필요 범위(결정 ③)가 줄어든다.

## 4. 아키텍처 마감 기준 (SOLID · 판정-표현 분리)

구현 중 하드코딩은 허용하되(§5 단계별 허용 지점), **계획서를 닫으려면 아래를 전부
통과해야 한다.** 어느 하나라도 미달이면 완료가 아니다 — 하드코딩 허용은 착수 순서의
자유이지, 마감 품질의 면제가 아니다.

| 원칙 | 적용 | 검사 방법 |
|---|---|---|
| **SRP** | 포즈 구동(`WeaponHoldPoseDriver`) / IK·리그 가중치(`WeaponHoldIk`) / 데이터(`WeaponHoldSettings`)가 각각 한 파일 — A안 분담 유지, "그리고"가 늘지 않는다 | 리뷰 체크리스트 |
| **OCP** | 무기·카테고리 추가는 `WeaponHoldSettings` 엔트리 + 클립 에셋만 — 컴포넌트 무수정. B축 교체도 `WeaponHoldIk` 내부 한정 | 6번째 무기 사고 실험 + 교체 diff 범위 확인 |
| **LSP** | Girl/Man 어느 모델·어느 IK 백엔드(내장/리그)든 같은 가중치 계약으로 동작 — 백엔드별 호출측 분기 금지 | 호출측(설정·타깃) diff 0건 |
| **ISP** | `WeaponHoldPoseDriver`와 `WeaponHoldIk`는 상호 참조 없음 — 각자 `HeldItem`·설정만 조회 | 상호 참조 grep 0건 |
| **DIP** | 무기 컨트롤러 구체 타입 무의존 유지 — `HotbarItemType`·설정 데이터만. Animator 파라미터명은 해시 상수로 한 곳 | 컨트롤러 타입 참조 grep 0건 |
| **판정-표현 분리 (MVP)** | 전 구성요소 표현 전용 — 사격·수리 판정 경로 diff 0. 클립·리그는 상태를 소유하지 않는다 | 판정 코드 diff 0건 |
| **순수 로직 분리** | 가중치 블렌드·카테고리 매핑은 `WeaponHoldMath`(A안) 확장으로 — Unity API 무의존 유지 | EditMode 테스트 존재 |

**C1 반입 결과** (2026-08-17):

- **리타게팅 편향은 실재했다 — 기술 확정 ⑥이 맞았다** (2026-08-18 정정). 최초에
  "머리 *위치*"만 보고 편향 없음으로 판단했으나, **회전**을 재니 정반대였다:
  기존 Base Layer 클립은 고개를 **17.4° 숙이고** 있어 `HeadPitchOffsetDegrees = −22°`가
  그에 맞춰 튜닝돼 있는데, Torch Idle은 고개를 오히려 **11° 들어** 보정이 그대로 얹혀
  **시선이 33° 위(하늘)** 로 향했다. 가슴도 −8.8° → −19.3°로 어긋났다.
- **해결: 마스크를 팔·손으로 좁혔다** (`UpperBodyMask` → **`ArmsOnlyMask`**).
  머리만 빼는 것으로는 안 된다 — 머리는 가슴의 자식이라 `Body`가 켜져 있으면 함께
  젖혀진다. 팔만 남기니 머리·가슴이 Hold on/off와 무관하게 −4.6°/−8.8°로 동일해졌다
  (상체 기울기·시선은 원래 설계대로 `ApplyBodyPitch`의 절차 회전이 담당한다).
  대가로 Rifle Aiming Idle의 상체 비틀기는 버린다 — 파지 자세의 본질은 팔이다.
- **왼손 IK 비율 분리** — 오른손은 무기가 소켓으로 이미 붙어 있어 클립에 맡겨도 되지만
  왼손은 총열까지 가야 그립이 성립한다. `Entry.LeftIkResidualWeight`를 신설해
  왼손 0.9 / 오른손 0.4로 둔다.
- **미러 처리** — Torch Idle은 **왼손**으로 물체를 든다. 무기 소켓이 오른손이므로
  `OneHandAim` 스테이트에 **`AnimatorState.mirror = true`** 를 걸어 좌우를 뒤집었다.
  `ModelImporterClipAnimation.mirror`(임포트 단계 미러)는 `SampleAnimation` 검증에
  반영되지 않아 스테이트 미러 쪽이 확실하다. `OneHandLow`는 미러 없이 같은 클립을 써
  오른손을 내린 자세가 된다 — 클립 하나로 두 카테고리를 덮는다.
- **IK 타깃 = 클립 실측값** — 각 스테이트를 `Animator.Update`로 구동해 손 위치·회전을
  조준 피벗 로컬로 재고(Girl↔Man 중간값) 그 값을 홀드 타깃에 넣었다. 그래야 IK가
  켜져도 클립 자세가 무너지지 않는다. **IK 잔여 가중치는 0.4** — 클립이 자세를,
  IK가 피치 추종을 맡는 §2.1 합성 비율.
- **샷건은 0.8배로 축소** — 팔 길이가 0.475 m인데 원본 1 m 샷건의 총열까지는 0.52 m라
  왼손이 닿지 않았다. 0.8배로 줄여 왼손 도달 거리를 0.40 m로 맞췄다(치비 비율의 한계 —
  무기 크기로 흡수). 하푼은 한손이라 왼손 타깃이 필요 없다.

**C2 구현 메모** (2026-08-17):

- `HoldPose`(int)·`Swing`(트리거) 파라미터와 상체 마스크(`UpperBodyMask` — Body·Head·
  양팔·손가락·손 IK만) 기반 **Hold 레이어**를 `AC_Player`에 신설했다. 스테이트는
  `NoHold`/`OneHandAim`/`TwoHandAim`/`OneHandLow` 4종이며 **모션은 비어 있다**.
- **레이어 가중치 기본 0** (`WeaponHoldSettings.HoldLayerWeight`) — 모션 없는 스테이트가
  가중치를 얻으면 상체가 바인드 포즈로 굳는다. 클립을 꽂은 뒤 1로 올리고 엔트리의
  `IkResidualWeight`를 내리는 순서다. 그 전까지는 A안의 IK 단독 경로와 동일하게 돈다.
- **스윙 스테이트는 일부러 넣지 않았다**: 포즈 AnyState 전이가 매 프레임 참이라
  스윙 스테이트에 들어가는 즉시 밀려난다. 클립 반입 시 별도 레이어(또는 포즈별
  직접 전이)로 배선해야 한다 — 파라미터·`WeaponHoldPoseDriver.PlaySwing`·
  `MeleeWeaponController` 호출부는 이미 준비돼 있어 스테이트만 꽂으면 된다.
