# 레벨 디자인 구현 계획 — 선로변 월드

작성일: 2026-08-21 · 상태: **1차 진행 중 — 코드 축 완료 · 검증 통과 · 잔여 2건** (2026-08-22) ·
규격 문서: [`레벨 디자인 가이드`](../../design/Train-Survival-레벨디자인-가이드.md)

> **진행 요약 (2026-08-22)**
> - **1차 코드 축 완료** — 앵커 스폰 전환·세그먼트 팔레트 추첨·클리어 존 검사기까지. EditMode **803/803** 통과
> - **미결 ①·③ 해소** — 추첨은 인덱스 시드(전 피어 동일), 프리팹 결정은 팔레트 → 단일 → 씬 3단
> - **에셋 27종 반입** — 자원 12 · 지형/식생 15 (§10)
> - **첫 세그먼트 `TerrainTile_Forest_A` 제작 + `Game_ArtTest` 배선**, 앵커 스폰 실측 확인
> - **클리어 존 검사기 도입** — 첫 판정에서 `Forest_A` 통과, 궤도 도상 오탐 1건을 규격으로 잡았다 (§10.5)
> - **잔여**: `LandmarkSlot`/`ScatterSlot` · 숲 팔레트 나머지 4종

> **이 계획이 하는 일**: 가이드가 정한 저작 규격을 **언제·어떤 순서로** 실행하는가.
> 규칙·수치·지역 콘텐츠 자체는 가이드가 소유하며, 이 문서는 차수·완료 기준·리스크만 담는다.
> 차수가 끝나면 이 문서는 동결되고 결과는 [개발 가이드 §5](../../guide/Train-Survival-개발-가이드.md)와
> [as-built 명세](../../specs/README.md)에 반영된다.
>
> **불변 지침**: 배경은 **전부 로컬 표현** — `NetworkObject`를 늘리지 않는다 ·
> 게임플레이 계약(`IWorldScrollService`·`RegionChangedEvent`·`ResourceNode` 복제 규약)을 건드리지 않는다 ·
> 팔레트가 비어 있으면 **현행 동작 그대로** 굴러간다 (전 차수 공통 회귀 방어선).

## 0. 이 계획이 만들어진 경위

문서 20여 편과 씬·프리팹 실측 결과, **레벨이라 부를 것이 아직 없다**는 것이 확인됐다.

| 실측 (2026-08-21) | 값 |
|---|---|
| 지형 타일 구성 | GameObject **3개** — `Ground` 큐브(60×0.2×40) · `TrackBed` 판때기 · 루트 |
| 지역 4종 타일 | 구조 동일, **머티리얼(색)만** 교체 |
| 자원 배치 | 12 m마다 · 좌우 **균일 랜덤** ±4~16 m — 지형과 무관 |
| 중경 배치물 · 원경 랜드마크 | **각 0개** (세계관 §4.2는 비적대 생물을 "반드시 배치"라 규정) |
| 하늘 | Unity 기본 스카이박스, fog off |

동시에 **문서 계열에도 빈자리**가 있었다 — 세계관 §4는 원칙(거리대별 임무)만 주고,
`specs/world/scroll-and-streaming`은 기계(풀링·좌표 유도)만 기록해, 그 사이의
**"무엇을 어떤 규칙으로 놓는가"** 가 통째로 비어 있었다. 그 자리를 가이드가 채우고,
이 문서가 실행을 맡는다.

## 1. 범위

**포함**

1. 세그먼트 팔레트 저작·추첨 기반 (마커 3종 · 팔레트 SO · 스트리머 확장 · 이음매 규칙)
2. 자원 스폰의 **앵커 경로 전환** (`GroundResourceSpawner`) + 폴백 유지
3. 지역 4종 팔레트 제작 (지역당 10종 = 총 40장)
4. 중경·원경 층 (랜드마크 패럴랙스 · 지역 스카이박스 · 비적대 생물)
5. 검수 도구 (클리어 존 검사기 · 정적 프리뷰 · 이음매 검사)

**비포함**

- **열차 위 공간** — 칸 레이아웃·건축 셀·방어 동선은 [건축 시스템 개편](건축-시스템-개편-계획.md)이 소유
- **트랙 커브·경사** — 미결 유지, 직선 전제 (가이드 결정 ②)
- **몬스터·보스 모델** — M8 결정 ⑤에서 이월된 축
- **날씨 표현 확장** — `WeatherVisualController`가 fog를 단독 소유하는 경계는 그대로
- 지형 기반 신규 게임플레이(엄폐·고저차 전투 등) — 레벨은 기존 규약을 **깨지 않는 것**까지가 임무

## 2. 선행 조건 3건 ⚠

이 계획은 **혼자 착수할 수 없다.** 아래가 정리되지 않으면 기준선 자체가 없다.

| # | 조건 | 현 상태 | 이 계획과의 관계 |
|---|---|---|---|
| **A** | **본편 `Game.unity` 이식** — 궤도 타일 배선(`TerrainTile_Rail`) + 열차 계열 y **+0.916** | M8 1차 **잔여** — 검증 씬 `Game_ArtTest`에만 있다 | **레벨의 물리적 기준선(레일 상면 0.976)이 본편에 없다.** 이식 전에 만든 세그먼트는 전부 높이를 다시 잡아야 한다 → **0차로 편입** |
| **B** | **M8 3차 렌더 실측** (Frame Debugger: SetPass·Batches·tris) + GPU Resident Drawer 활성화 | **미착수** | 가이드 §8이 "타일당 30개"를 목표로 잡았으나, **조치 전 수치가 없으면 효과를 주장할 수 없다.** GPU RD는 팔레트 방식(같은 프리팹 수백 개)의 전제 |
| **C** | **M8 결정 ③** — *"배경 조형물 채우기는 3차 실측 후 4차 편입 여부 판단"* | **보류 중** | 이 계획의 2차가 정확히 그 작업이다. **B가 끝나야 2차가 열린다** |

> **A는 이 계획이 흡수하고(0차), B·C는 M8에 남긴다.** A를 M8에 남겨두면 이 계획 전체가
> 남의 마일스톤 잔여에 묶이고, 반대로 B까지 흡수하면 M8 3차가 껍데기만 남는다.

## 3. 차수 편성

### 0차 — 본편 이식 (선행 조건 A)

| 항목 | 내용 |
|---|---|
| 대상 | `Game.unity` — 궤도 타일 배선 + 열차 계열 y +0.916 |
| 작업 | ① `TerrainTileStreamer._tilePrefab` → `TerrainTile_Rail`(`8f25cf9c…`) ② `Train`·`Train_Handrails` y 0 → 0.916 ③ `EngineFuelPort`·`CraftingStation` 2.65 → 3.566 ④ `Main Camera` 8 → 8.916 ⑤ 승차 램프 앵커 방식 확인 |
| 방식 | **씬 YAML 직접 편집** — 에디터 저장은 수천 줄 재정렬 diff를 만든다. 편집 전 다른 씬(`Boot`) 로드 |
| 함정 | **한쪽만 옮기면 안 된다** — 타일만 옮기면 열차가 궤도에 파묻히고, 높이만 옮기면 공중에 뜬다 |
| 완료 기준 | 본편에서 열차가 궤도 위에 얹혀 있고, 호스트 1 + 클라 1 접속·주행 정상 |
| 근거 | [train-art-layout §7.2·7.3](../../specs/world/train-art-layout.md) |

### 1차 — 저작 기반 (코드 축)

**핵심 원칙: 이 차수가 끝나도 화면은 그대로여야 한다.** 팔레트가 비어 있으면 현행 경로로 굴러간다.

| 항목 | 내용 |
|---|---|
| 신규 마커 | `ResourceAnchor`(+`AnchorKind` 열거) · `LandmarkSlot` · `ScatterSlot` — 전부 빈 `MonoBehaviour` |
| 신규 데이터 | `TerrainSegmentPalette`(SO) — 세그먼트 배열 + 가중치 + `NoRepeatAdjacent` 플래그 |
| 신규 순수 로직 | `SegmentPickLogic` — 인덱스·가중치·최근 K장 제외에서 세그먼트를 고르는 결정론 함수 |
| 스트리머 확장 | `TerrainTileStreamer.ResolveTilePrefab`이 지역 팔레트를 경유 — **팔레트가 null이면 기존 경로** |
| 스포너 전환 | `GroundResourceSpawner.SpawnAhead`가 전방 타일의 **미사용 앵커**에서 위치를 고르고, 없으면 **현행 랜덤으로 폴백** |
| 풀 정합 | 타일 `IPoolable.OnSpawned`에서 앵커 사용 플래그 리셋 — **누락 시 재사용 타일에 자원이 안 심긴다** |
| 검수 도구 | 클리어 존 검사기(에디터) — 가이드 §4.2 대역 침범 콜라이더를 찾아 로그 |
| 테스트 | `SegmentPickLogicTests`(가중 추첨 결정론·최근 K 제외·빈 팔레트 방어) · `AnchorPickTests`(Kind 우선·앵커 고갈 폴백) |
| 완료 기준 | **회귀 0** — 팔레트 미설정 상태에서 자원 스폰·타일 스트리밍이 현행과 동일. EditMode 전량 통과 |

#### 1차 진행 상태 (2026-08-22)

| 항목 | 상태 |
|---|---|
| `ResourceAnchor` + `ResourceAnchorKind` 4종 | **완료** — 정적 레지스트리(`OnEnable`/`OnDisable`), `PreferredKindFor` 순수 매핑 |
| 스포너 앵커 전환 + 폴백 | **완료** — 종류를 위치보다 먼저 추첨하도록 순서를 바꿨다(종류가 앵커 Kind의 입력이므로) |
| 풀 정합 | **완료** — 앵커 `OnEnable`에서 사용 플래그 리셋 |
| `SegmentPickLogic` | **완료** — 해시 결정론 + 가중 추첨 + 인접 반복 방지 |
| `TerrainSegmentPalette`(SO) | **완료** — 가중치·플래그 배열 캐시(`OnValidate`로 무효화) |
| `RegionDefinition._segmentPalette` | **완료** — 지역 데이터에 팔레트 축 신설 |
| 스트리머 연결 | **완료** — `TryPickFromPalette` (팔레트 → 단일 프리팹 → 씬 fallback 3단) |
| 테스트 | **완료** — `ResourceAnchorTests` 8 + `SegmentPickLogicTests` 7 + `ClearZoneRulesTests` 28, EditMode **803/803** |
| 클리어 존 검사기 | **완료** — `ClearZoneRules`(순수 판정) + `ClearZoneAuditWindow`(계층 훑기·창·콘솔 일괄). §10.5 |
| `LandmarkSlot` / `ScatterSlot` | **미착수** ← 다음 |

**추가로 발견해 넣은 것 — 앵커 워밍업.** 세션 첫 프레임에는 지형 타일이 아직 안 깔려 앵커가 0개라,
전방 60 m 초기 구간이 통째로 폴백 랜덤이 됐다. `AnchorWarmupSeconds`(0.5 s) 동안 스폰을 미루고,
그 시간이 지나면 앵커가 없어도 폴백으로 진행한다 — 팔레트 없는 지역에서 자원이 끊기지 않게 하는 상한이다.

**실측 검증 (`Game_ArtTest`, 호스트 1)**

```
[GroundResourceSpawner] 앵커 스폰 #1 kind=Rock   pos=(15.0, 0.4, -0.1) targetZ=-0.1
[GroundResourceSpawner] 앵커 스폰 #2 kind=Ground pos=(6.0, 0.4, 9.9)   targetZ=11.9
```

워밍업 적용 후 **초기 구간부터 전부 앵커 경로**로 심긴다(적용 전에는 #1이 폴백이었다).
`Kind` 우선 선택도 동작 — 자원 종류에 맞는 지형 성격이 먼저 잡힌다.

## 4. 완료 기준 (계획 전체)

1. 본편 `Game.unity`에서 열차가 궤도 위를 달리고, 지형이 **평면 판때기가 아니다**
2. 자원이 **지형의 결과로 놓여 있다** — 바위 아래, 물가, 잔해 속. 공중·매몰 0건
3. 낮 1회 주행에서 **반복 인지 3회 이하**
4. 지역 4종이 **색이 아닌 지형·하늘·생물**로 구분된다
5. 밤 웨이브 최대 물량(동시 12 + 플레이어 4 + 자원 12) 프레임이 **조치 전후로 기록**되어 있다
6. **회귀 0** — `IWorldScrollService`·`RegionChangedEvent`·`ResourceNode` 복제 규약 무변경, EditMode 전량 통과
7. 대역폭 증가 0 — 배경·장식에 `NetworkObject` 0개

## 10. 진행 기록

### 10.1 에셋 반입 (2026-08-22) — 27종

경로는 [이미지생성 브리프 §G9·§J·§K](../../design/Train-Survival-이미지생성-브리프.md)의
ChatGPT 이미지 → Meshy(image-to-3D) → Blender 정규화 → Unity 반입.

| 묶음 | 종수 | 위치 | 크기 기준 |
|---|---:|---|---|
| **자원 노드** | 12 | `Art/Models/ResourceNodes/Res_*.fbx` | 0.8 m · 원목 1.6 · 광맥 1.2 |
| **식생** | 7 | `Art/Models/Environment/Forest/`(6) · `Desert/`(1) | 침엽수 12 m · 활엽수 10 · 관목 1.5 · 그루터기 0.8 · 통나무 6 |
| **지형·기타** | 8 | `Art/Models/Environment/Forest/` | 절벽 11 m · 경사/강둑 8 · 교량기둥 4 · 울타리 3 · 침엽수 변형 10·8 |

**자원 12종은 `ResourceNode.prefab` 하나에 메시 토글로 들어갔다** (가이드 §5.5 결정 ④) —
`NetworkPrefabs` 등록 1개 유지, `GlobalObjectIdHash` **1939677764 보존**. 전용 메시가 없는 종류는
폴백 프리미티브 + 색 틴트로 남아, **12종을 한꺼번에 만들 필요가 없다.**

### 10.2 반입에서 확정된 규격 ⚠

두 건 모두 **처음에 틀렸다가 실측으로 잡았다.** 다음 에셋도 같은 함정을 밟는다.

| 항목 | 규격 | 틀렸을 때 |
|---|---|---|
| **임포트 스케일** | `useFileScale = true` + `globalScale` = 목표 미터 | 끄면 Blender FBX의 cm 단위 때문에 **100배**(폭 80 m)로 들어온다 |
| **씬·프리팹 배치** | FBX 루트의 기본 회전·스케일에 **합성**한다<br>`localRotation = Euler(0,yaw,0) * fbx.transform.localRotation`<br>`localScale = fbx.transform.localScale * scale` | 덮어쓰면 루트의 `scale 100`·`−90°X`가 사라져 **1/100 크기로 줄거나 눕는다** |

### 10.3 첫 세그먼트 — `TerrainTile_Forest_A`

`TerrainTile_Rail`의 배리언트(궤도 포함). `Game_ArtTest`의 `TerrainTileStreamer._tilePrefab`에 배선했다.

- **Decor 23개** — 절벽 5(양옆 \|x\| 27) · 나무 8(\|x\| 17~22) · 낮은 것 8(\|x\| 5~15) · 둔덕 2(y −1.0~−1.2로 묻음)
- **`Anchors` 6개** — Ground 4 · Rock 1 · Water 1, 전부 \|x\| 4~16 (집게 1단계 사거리 20 m 안), y 0.4
- 클리어 존(가이드 §4.2) 준수 — 궤도 통로 \|x\| ≤ 3.3 비움, 큰 나무를 16 m 밖으로 빼 **10~24 m 시야 확보**

**본편 `Game.unity`에는 배선하지 않았다** — 이 세그먼트는 궤도를 포함하는데 본편 열차는 아직
y +0.916이 적용되지 않아 궤도에 파묻힌다(0차 이식 미완).

### 10.5 클리어 존 검사기 (2026-08-22)

세그먼트가 40장으로 늘기 **전에** 자동 판정을 세웠다 — 리스크 6·7의 처방이다.

| 축 | 산출 | 자리 |
|---|---|---|
| 판정 | `ClearZoneRules` — 대역 겹침·연속 장벽·밟을 수 있는 표면·AABB 변환. 전부 순수 함수 | `Scripts/Gameplay/World/` |
| 훑기 | `ClearZoneAuditWindow` — 프리팹 폴더/선택 항목을 계층까지 펼쳐 콜라이더·렌더러·앵커·컴포넌트를 검사 | `Scripts/Editor/` |
| 테스트 | `ClearZoneRulesTests` **28**개 — 규격의 경계값을 코드로 고정 | `Tests/EditMode/` |

메뉴는 둘이다 — `Game/QA/Clear Zone Audit`(창: 폴더·선택 검사, 결과 클릭 시 핑)와
`Game/QA/Clear Zone Audit (Log)`(창 없이 전량을 콘솔에). 판정 목록은 [가이드 §9.3](../../design/Train-Survival-레벨디자인-가이드.md).

**설계 — 판정과 훑기를 갈랐다.** 에디터 어셈블리는 `Game.Tests.EditMode`가 참조하지 않으므로,
판정을 창 안에 두면 **한 줄도 테스트할 수 없다.** 콜라이더를 `ColliderProbe`(로컬 AABB + 플래그 4개)로
요약해 넘기면, 규격 판정 전체가 `UnityEditor` 없이 검증된다.

**첫 판정 결과 (타일 6장)**

| 타일 | 결과 |
|---|---|
| `TerrainTile_Forest_A` | **오류 0 · 경고 0** — 첫 세그먼트가 규격을 지키고 있음이 자동으로 확인됐다 |
| 나머지 5장 (옛 더미·궤도 타일) | 앵커 0개 경고만 — 팔레트 세그먼트가 아니므로 정상 |

**오탐 1건을 규격으로 잡았다.** 궤도 도상 `TrackBed`(상면 y 0.06)가 6장 전부에서 통로 침범으로 잡혔다.
허용 두께를 0.05 → 0.1로 올리는 대안은 *"낮은 것은 통과"* 라는 우회로를 열어 물리쳤고,
예외를 **이름으로 고정**했다(`RailTrack`·`TrackBed`) — [가이드 결정 ⑧](../../design/Train-Survival-레벨디자인-가이드.md).

**부수 발견 — 장식에 콜라이더가 없다.** `Forest_A`의 콜라이더는 지면·도상·궤도 5개뿐이고
**Decor 23개는 전부 무콜라이더**라 절벽·나무를 몸이 통과한다. 규격에 없던 항목이라 미결 ⑥으로 올렸다 —
검사기는 판단이 설 때까지 이 항목을 보지 않는다.
