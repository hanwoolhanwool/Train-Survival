대상: **M8 머지 후 별도 브랜치** (아트 패스 후속 도구) ·
상태: **✅ 구현 완료 (2026-08-17)** — 커밋 4건(`47703db` 컨트롤러 일가 · `4760ecc` 씬·머티리얼 반입 ·

`Scenes/ViewLab.unity` + `Gameplay/Debugging/ViewLab*`(6파일 1,345줄).
*(상태 줄은 2026-08-20 사후 갱신 — 구현 후 문서가 "착수 대기"로 남아 있었다)* ·

> **키보드 핫키는 만들지 않는다** — 조작은 씬 뷰 핸들 + 마우스(패널 버튼·수치 필드)만.

## 1. 목적과 범위 — 왜 필요한가

### 1.1 현재 구조 진단

| 항목 | 현재 상태 | 문제 |
|---|---|---|
| 뷰모델 위치 | `Player.prefab`의 `AimPivot` 자식 피벗 5종(`MeleePivot`·`HammerPivot`·`RevolverPivot`·`ShotgunPivot`·`HarpoonPivot`)에 로컬 TRS 하드코딩. 별도 데이터 없음 | 조정하려면 프리팹 YAML 수기 편집 또는 프리팹 모드 — **애니메이션도 피치도 안 걸린 정지 상태**에서 눈대중 |
| 조정 확인 | `Game_ArtTest` 씬 — NGO 인게임 씬의 대체 편성 (`GameplaySceneRoute.ArtTest`) | Play + 네트워크 세션 + 런타임 스폰 필요. 값 수정→확인 왕복이 통째로 재시작 |
| 뷰모델 표시 | `GunView`/`HarpoonView`/`RepairHammerView`가 `IsSpawned`/`IsOwner` 게이트로 `Renderer.enabled` 토글 | 비네트워크 씬에 Player를 놓으면 **전 뷰모델이 안 보임** (Awake에서 `SetVisible(false)` 후 유지) |
| 애니메이션 확인 | `AC_Player` 파라미터 4종(`Speed`/`Jump`/`Dead`/`Grabbed`)을 `PlayerAnimationDriver`(NetworkBehaviour)가 구동 | 세션 없이는 미구동. `Grabbed`는 파라미터만 선배치 — 확인 수단 자체가 없음 |

### 1.2 시급성 — 조정 반복이 예정돼 있다

- M8 1차에서 뷰모델 4종이 방금 배선됐고(파지·정합은 눈으로 맞춘 초기치), 라이플·마체테
  모델 도입 시(현재 미보유 → 프리미티브) **같은 조정을 다시** 해야 한다.
- `AimPivot`은 캐릭터 본이 아니라 **루트 직속 + 피치 회전만** 받으므로, TP 캐릭터 손과의
  정합은 애니메이션·피치가 실제로 걸린 상태에서만 판단할 수 있다 — 지금 그 상태를 만드는
  유일한 방법이 풀 세션 Play다.
- **B축 그랩**(M8 머지 후 착수, `플레이어-확장-계획.md`)의 `Grabbed` 상태 확인 수단도 겸한다.

### 1.3 범위

**포함**: 뷰랩 씬 1개 + 랩 컨트롤러(패널·기즈모·저장) + 궤도 카메라. 조정 대상은
`AimPivot` 자식 피벗 5종 (+새 피벗 추가 시 자동 수용 — 이름 하드코딩 금지, 자식 열거).

**제외**: `Muzzle`(CameraPivot 자식 — 판정·트레이서 시작점, 카메라 기준이라 뷰모델과 무관) ·
새 모델 제작 · 뷰모델 오프셋의 SO화(§8 선택지로만 기록) · 키보드 핫키(사용자 결정).

Mecha Survivor RigLab(Docs/06)의 채택·미채택 판정. **워크플로(조정·저장 방식)만 가져오고
데이터 구조는 가져오지 않는다.**

| RigLab 요소 | 판정 | 근거 |
|---|---|---|
| **Play 중 씬 뷰 핸들 조정 + `Selection.activeGameObject` 동기** | ✅ 채택 — **이 계획의 핵심** | 패널에서 피벗을 고르면 씬 뷰에서 바로 끌 수 있다. 사람이 씬에서 수정하는 방식 그대로 |
| **조정 결과의 에셋 저장 (Play 중 저장해도 유지)** | ✅ 채택 — 단 대상이 SO가 아니라 **프리팹** | 씬 뷰 핸들 값은 Stop 시 소실 — 저장 버튼이 에셋에 기록해야 워크플로가 성립. Train은 피벗 TRS의 단일 출처가 `Player.prefab`이므로 프리팹에 쓴다 (§4-⑤) |
| OnGUI 우측 패널 (버튼·수치 필드·넛지·미세 스텝·리셋·dirty 표시) | ✅ 채택 | 키보드 없이 전 기능을 마우스로 조작하는 유일한 통로. RigLab은 핫키+패널 병행이었지만 여기선 **패널이 유일 조작부** |
| 궤도 카메라 (우클릭 회전·휠 줌·휠클릭 팬) | ✅ 채택 | 마우스 전용이라 키보드 금지 제약과 충돌 없음 |

| 키보드 핫키 전체 (Tab/W/E/[ ]/화살표 넛지/S…) | ❌ 미채택 | **사용자 결정 — 키보드 기능은 만들지 않는다** |

## 3. 씬 구성

씬: `Assets/_Project/Scenes/ViewLab.unity` — **에디터 전용, 빌드 미포함** (Build Profiles
목록에 안 넣는다).

| 루트 오브젝트 | 내용 |
|---|---|
| `Ground` | 평면 + 접지 콜라이더 (원점) |
| `Directional Light` | 본편과 유사한 각도 1개 |
| `ViewLab` | `ViewLabController` + `ViewLabGrid`(GL 격자) + `ViewLabGizmo`(선택 축 표시) |
| `Main Camera` | `ViewLabOrbitCamera` (마우스 전용) — FP 모드 시 CameraPivot 위치로 스냅 (§4-④) |
| `Player` | **본편 `Player.prefab` 인스턴스 그대로** (사본 금지 — 계층·수치가 본편과 동일해야 "랩에서 보는 것 = 본편에서 나오는 것") |

스크립트 배치: `Assets/_Project/Scripts/Gameplay/Debugging/` (신설, `Game.Gameplay` 소속 —
씬 컴포넌트라 `Game.Editor`(Editor 전용 어셈블리)에 둘 수 없다). 에디터 API(프리팹 저장)는
`#if UNITY_EDITOR` 가드. 순수 계산(넛지 스텝·순환 인덱스·표시 판정)은 `ViewLabMath.cs`로
분리해 EditMode 테스트 대상으로.

## 4. 기능 블록

### ① 네트워크 게이트 무력화 (Start 1회)

Player 프리팹의 컴포넌트는 전부 NetworkBehaviour라 세션 없이는 침묵하지만, 셋은 능동적으로
방해한다. 랩 컨트롤러가 Start에서 정리한다:

1. `GunView`/`HarpoonView`/`RepairHammerView`/`MeleeSwingView` — **비활성화** (Awake의
   `SetVisible(false)`가 이미 실행된 뒤이므로) 후 표시 제어를 랩이 인수 (§4-②).
2. `PlayerCharacterView` — 비활성화 (소유자 `ShadowsOnly` 경로 차단). 캐릭터 택1은 랩이
   `Character_Girl`/`Character_Man` GameObject를 직접 켜고 끈다.
3. `PlayerAimView`/`PlayerAnimationDriver` — 미스폰이라 침묵하지만 명시적으로 꺼서
   랩의 피치·파라미터 주입과 경합할 여지를 없앤다.
4. 활성 캐릭터의 Animator에 `AlwaysAnimate` + `Application.runInBackground = true`.

### ② 무기 선택 + 피벗 조정 — **씬 뷰 핸들이 1차 수단**

- 패널 "무기" 절: `AimPivot` 자식 피벗을 열거해 버튼 목록으로 (Melee/Hammer/Revolver/
  Shotgun/Harpoon — 이름 하드코딩 없이 자식 순회, 새 피벗 자동 수용).
- 무기 버튼 클릭 시:
  - 그 피벗 아래 렌더러만 켜고 나머지는 끈다 (겹침 방지 — 본편 HeldItem 규칙의 랩 재현).
  - `Selection.activeGameObject = 피벗` (`#if UNITY_EDITOR`) — **씬 뷰에서 바로 이동/회전/
    스케일 핸들로 끈다. 이것이 "사람이 씬에서 수정하는 방식"의 본체다.**
  - 게임 뷰에는 `ViewLabGizmo`가 피벗 축을 GL로 그린다 (씬 뷰 없이도 축 확인).
- 패널 보조 조작 (전부 마우스):
  - 로컬 pos/rot/scale 수치 필드 + "입력 값 적용" 버튼 (필드 타이핑 중 갱신으로 덮지 않음 —
    RigLab의 필드 버퍼 방식 이식).
  - 축별 넛지 버튼 (X±/Y±/Z± · P±/Y±/R±) + "미세 스텝" 토글 (0.05 / 0.005m · 5° / 0.5°).
  - **R 리셋 버튼**: 프리팹 에셋의 현재 값으로 복원 (`PrefabUtility.GetCorrespondingObjectFromSource`).
  - **dirty 표시**: 씬 피벗 로컬 값 ↔ 프리팹 값 차이를 주기 검사 (매 프레임 문자열 할당 금지 —
    0.25초 주기), "● 미저장 변경" 경고.

### ③ 애니메이션 확인 — 파라미터 직접 주입

`PlayerAnimationDriver`를 흉내 내지 않고 활성 Animator에 파라미터를 직접 준다:

- 캐릭터 택: `Girl` / `Man` 토글 버튼 (조정 결과는 피벗 공유라 양쪽에서 확인 필수 —
  A축의 "파지 공유" 전제 그대로).
- 이동: `Idle` / `Walk` / `Run` 버튼 → `Speed` 값을 블렌드 트리 임계값에 맞춰 세팅.
- 단발·상태: `Jump`(Trigger) / `Dead`(Bool 토글) / `Grabbed`(Bool 토글 — **B축 그랩 착수 전
  포즈 확인 수단**).
- **피치 슬라이더**: `AimPivot.localRotation = Euler(pitch,0,0)` 직접 세팅 —
  `PlayerAimView`와 동일 공식·동일 클램프 범위. 뷰모델은 피치 전 구간에서 화면을 가리지
  않아야 하므로 **슬라이더로 훑으며 조정하는 것이 이 랩의 두 번째 존재 이유다.**
  (가슴·머리 본 절차 회전도 `PlayerAimView`의 공식을 재사용해 적용 — 본 회전이 빠지면
  TP 정합 판단이 틀어진다.)
- 재생 속도 슬라이더 (0.1×~2×, `Animator.speed`).

### ④ 카메라 — FP/궤도 토글

- **궤도 모드** (기본): 우클릭 드래그 회전 · 휠 줌 · 휠클릭 팬 (RigLab OrbitCamera 이식,
  Input System `Mouse.current`만 사용). TP 정합(캐릭터 손↔무기) 확인용.
- **FP 모드** (버튼 토글): 카메라를 `CameraPivot` 위치·회전에 고정 — **소유자 화면에서
  뷰모델이 실제로 어떻게 보이는지**가 최종 판정 기준이다. 피치 슬라이더에 따라 함께 회전.

### ⑤ 저장 — Play 중 프리팹 에셋 기록

패널 "저장" 버튼 (`#if UNITY_EDITOR`):

```
PrefabUtility.LoadPrefabContents("Assets/_Project/Prefabs/Player.prefab")
  → AimPivot 자식 피벗을 이름으로 매칭해 씬 인스턴스의 로컬 TRS 복사
  → SavePrefabAsset → UnloadPrefabContents
```

- **에셋 기록은 Play 종료와 무관하게 유지된다** — RigLab의 SO 저장과 같은 원리, 대상만
  프리팹. 씬 인스턴스에 오버라이드를 남기는 방식(Apply 의존)은 Play 중엔 불가능하므로
  쓰지 않는다.
- 저장 로그에 무기별 변경 전→후 값을 남긴다 (커밋 메시지 재료).

## 6. 테스트

- **EditMode**: `ViewLabMath` — 넛지 스텝 적용, 순환 인덱스, Speed↔이동 상태 매핑,
  피벗 이름 매칭(저장 대상 열거). 기존 466개에 추가.
- 조정 UI·기즈모·저장은 수동 QA — P3의 왕복 검증이 커버.

## 7. 알려진 함정 (선반영)

- **Play 중 씬 뷰 핸들 값은 Stop 시 소실** — 저장 버튼이 에셋에 기록해야 한다. dirty 표시로
  Stop 전 저장을 상기 (RigLab §7 동일).
- **프리팹 저장 후 `GlobalObjectIdHash` 확인** — Player.prefab은 NetworkObject다. Unity API
  (`SavePrefabAsset`) 경유라 YAML 수기 편집과 달리 안전할 것으로 보지만, P3 왕복 검증에
  **클라 접속 1회**를 포함해 ClosedByRemote 재발 여부를 확인한다 (프로젝트 기록:
  프리팹 편집 후 해시 오염 → 접속 거부 사례).
- **열린 씬의 YAML 외부 편집 금지** — ViewLab.unity 배선은 Unity를 통해서만. 외부 편집 시
  "modified externally" 모달이 MCP 전체를 막는다 (프로젝트 기록).
- **Animator 컬링·비포커스 정지** — `AlwaysAnimate` + `runInBackground` (§4-①-4).
- **View 컴포넌트의 Awake 선실행** — 랩 Start보다 먼저 `SetVisible(false)`가 돈다.
  비활성화만으로는 렌더러가 꺼진 채 남으므로 **비활성화 후 렌더러를 다시 켜는 순서**여야 한다.
- `HarpoonPivot`은 scale 0.75 — 저장·리셋이 스케일까지 왕복해야 한다 (위치·회전만 다루면
  리셋 시 스케일이 유실된다).
